# M1 验收记录

范围以已批准的 M1-01 至 M1-08 开发计划与 C01 判负口径为准。实测使用 Intel Core i5-1038NG7、16 GB 内存的 MacBook Pro，Chrome 158.0.8127.88（无头模式），视口 1440 × 900，内容版本 `m1-1`。

| 任务 | 验证 |
| --- | --- |
| M1-01 原创内容与状态契约 | 配置和版本检查，预算覆盖两种抽卡结果，首波收益可完成五类操作。 |
| M1-02 统一逻辑帧、指令与时钟 | 固定输入和种子在 1×、4×、改速、暂停和分块恢复下得到相同状态。C01 覆盖等于上限、超过上限先判负、同波后续批次、帧内升级先于攻击和冷却校验。 |
| M1-03 五类局内操作 | 覆盖各操作成功、拒绝、重复提交及从待执行快照继续。并行购买争最后一件库存、合成争共享材料时仅成功提交一次。 |
| M1-04 主线、无尽和结算 | 两种抽卡阵容用正式配置完成十波主线和至少五波无尽，再推进至失败。测例逐帧比较无尽波中恢复后的结果与连续运行。 |
| M1-05 自动存档与恢复 | Chrome 实测事务中止、同步写入异常、连续保存合并、未完成事务的页面关闭、恢复原记录及格式不兼容提示。 |
| M1-06 桌面 3D | 浮标灯、折光台、潮沫和盐壳使用项目内原创模型与纹理，无需手选素材。Chrome 实测阵位、塔和重叠敌人拾取、攻击动画、死亡模型移除和刷新后重建。场景只接收状态与命中事件，尝试指定攻击仍须通过对局校验。 |
| M1-07 桌面整局 | Chrome 用正常界面打完 1× 主线，刷新胜利存档，转无尽、暂停并关闭浏览器。重新打开后恢复同一快照，继续到失守，刷新失败存档并重开。 |
| M1-08 性能与交付 | 4× 运行连续现实时间 10 分钟，开启与关闭存档均通过阈值。冻结 5 分钟后补算到预计的失败帧。生产构建通过 Chrome 启动和恢复检查。 |

## 验证命令

- `npm run check` 检查类型、运行测试及生成生产构建。
- `node checks/replay.mjs <轨迹.json>` 按固定种子和输入重放；[运行说明](../README.md#重放对局)包含示例。
- `unzip -tq 图鉴.xlsx` 检查图鉴文件完整性。

## 浏览器专项

- 隐藏文档停止动画帧但允许定时器时，触发即时保存并继续周期保存，后台已入账的待处理帧一并写入 IndexedDB。
- 生产构建可在 Chrome 加载 3D 战场、建塔和保存，刷新后恢复原塔。
- IndexedDB 写入/恢复覆盖无尽波中敌人、塔与装备、攻击冷却、定时效果、待执行命令和时钟余量。真实读回的快照与连续运行逐帧一致。

- 从新局通过桌面界面完成五类经济操作，首波结算后成功装备聚光环。1× 主线在游戏时间 608.0 秒清场，浏览器经过约 608.8 秒。刷新后仍处于主线胜利等待。进入无尽后切换 4×，第 2 波暂停并关闭 Chrome。重新启动 Chrome 时恢复同一局、同样的阵容和保存状态，继续至第 13 波，以 26 容怪点失守，连续完成 11 波。退出结算前刷新仍显示失败，重开获得新对局 ID 和 100 起始金币。

## V1 性能

使用固定种子 1337 和持续负载场景。23 个在场容怪点接近上限 24，四个阵位均有满级塔和聚光环。测试为维持连续压力延长敌人寿命，运行 600 秒现实时间，速度 4×。开启和关闭保存的页面分别按相同目标序列提交 600 次指定攻击，记录每次收到命令到 DOM 确认的耗时，并独立记录到逻辑帧返回结果的耗时。结束快照约 58.8 KB。

| 指标（毫秒） | 保存开启 P95 / P99 | 保存关闭 P95 / P99 |
| --- | ---: | ---: |
| 收到命令至界面确认 | 0.3 / 0.5 | 0.3 / 0.5 |
| 收到命令至逻辑结果 | 22.2 / 37.9 | 23.1 / 37.4 |
| 单逻辑帧处理 | 0.1 / 0.2 | 0.1 / 0.2 |
| 捕获快照并交给保存队列 | 1.5 / 1.9 | — |
| 快照复制 | 1.4 / 1.9 | — |
| IndexedDB 提交 | 5.2 / 8.4 | — |

两组各收到并结算 600 条命令，采样积压最多 1 帧，两组均到达逻辑帧 24082。开启保存的确认 P95 增量为 0.0 毫秒，符合计划阈值。固定帧轨迹另外比较了 1×、4×、暂停、改速、分块补算和存档恢复后的完整对局状态。

用 Chrome 生命周期控制冻结另一活页面 300 秒，挂起前为 4×。恢复调用至失败状态可读取约 16.5 毫秒。测试对局从第 21 帧补算到第 211 帧，首批入场后容怪点达到 29，立即判负，剩余待处理帧清零。

生产构建的主 JavaScript 约 511 KB，gzip 后约 132 KB。Vite 给出单块体积提示。

生产构建另从新局用正常界面在 4× 下完成五类经济操作，合成并装备聚光环后剩余 2 金币。主线第 6057 帧清场，对局用时 605.7 秒。胜利后刷新，进入无尽并在第 6707 帧暂停，刷新恢复同一对局、同一帧和暂停状态。继续到无尽第 14 波判负，连续完成 12 波，未来出怪事件清空。重开后为新对局 ID，初始金币为 100。浏览器对局实际用时约 305 秒，未捕获页面脚本异常。

### V1 保存开关同帧对照

在 Intel Core i5-1038NG7、16 GB MacBook Pro 的无头 Chrome 158.0.8127.88 运行[固定轨迹验证页](../checks/m1-performance.html)，持续 600.037 秒现实时间。种子 1337，23 个在场容怪点，四座满级塔均装备聚光环。两组都按固定 4× 逻辑时间输入并结算 600 条命令，每十条比较完整玩法状态，结束于第 24001 帧。全程无命令遗漏，采样待算最多 1 帧。结束快照为 39,739 字节，保存组成功提交 282 次。

| 单逻辑帧处理 | 0.1 / 0.1 | 0.1 / 0.1 |
| 捕获快照并交给保存队列 | — | 0.7 / 1.0 |
