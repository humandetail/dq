## 4. 跨标签写入与存档

采用独立 M2 IndexedDB 数据库 `td3-m2`，默认档案 `default`、当前局槽 `current`。档案与对局同一事务保存；每次事务包含 `revision`、`activeMatchId`、完整档案与当前局。`revision` 持续单调递增，重开不归零，局 ID 不复用。每 5 秒现实时间请求自动保存；重要经济动作、领取、任务节点及阶段切换在动作提交后立即请求保存，不等待周期。

使用 Web Locks 独占锁 `td3-m2:profile:default:writer`，持锁标签是唯一运行模拟和写入者。第二标签显示“此对局已在另一个标签页打开”，只读，不启动自己的模拟或交易。持锁页挂起仍持锁，不按心跳超时抢占；关闭／崩溃释放后，新写者先重新读取磁盘最新修订，再恢复。验收浏览器须支持该锁；不支持时提示切换支持的浏览器，不降级为多写者。

**独占锁之外仍执行事务内比较。** 在同一 IndexedDB 读写事务中比较期望 `revision` 与 `activeMatchId`；不同则拒绝整个旧快照，不覆盖、不自动把旧快照改挂到新修订重试。合法重开也是比较旧头后原子写入新局 ID＋新修订。取消尚未开始的旧局保存，已在途事务不能在新局后复活旧局。读取、校验、更新头及档案／对局须在同一事务，不用事务外检查代替。

命令去重令牌、奖励槽、材料消耗、积分和任务节点随同一次修订提交；成功保存提示只在事务完成后更新。失败保留最近成功快照，重试仅针对仍属当前局的合法最新状态。不兼容记录保留，不静默初始化覆盖。关闭期间不推进，活页面挂起补算与系统回收后的读档继续按 B05 区分。

必须覆盖：A 标签领奖／交易／推进任务后，B 的旧自动快照写入被拒；A 已重开后，旧局快照、旧回调与旧交易均不得覆盖；第一标签关闭后第二标签取得锁，必须恢复最新修订。最终余额、已领奖状态和新局 ID 一并断言，不能只检查“没生成第二件奖励”。

每份整局记录绑定验收版本、运行内容版本、配置版本及配置文件 SHA-256、源码修订、构建 SHA-256、候选部署地址、存档格式、种子、输入日志 SHA-256 和初态 SHA-256。源码仍有未提交改动时同时保存完整补丁及其摘要，不能只登记一个不能重建该运行的提交号。配置标签相同但文件内容不同，也不得视为同一证据。正式交付核对实际部署构建摘要；记录中保存实际运行日志及快照，不能只有摘要。

本期缩池使普通 SR 档内单卡概率从 1/47 变为 1/4；因此 A10 通过只证明本次实际运行的内容版本。扩池、改变抽签或权重、奖励／商店可达性、收入／费用、塔与技能／装备效果、资格／成长、敌方强度／波次时点或模拟规则时，必须更新运行内容版本并重跑 A10。沿原预登记种子重新执行并记录全部结果；旧输入不再合法时保留失败记录和新的合法操作日志，仍须至少一局满足无 SSR、提前突破及阵容击杀，不能通过换标签沿用旧通过结果。其他受影响的 A01–A18 用例一并回归。

后续模式扩展仍回归原普通主线 A10；更高难度和新模式按各自规则新增验收，不将“普通主线无 SSR”自动推广为所有难度要求。纯文档更正不改变运行内容版本；纯素材替换须重验视觉和性能，若影响玩法则同时触发 A10。

### 固定峰值场景与提前验证

100 容怪点仅用于 C01 的检查时点，不限制同波继续生成的单位，也不限制不计个人容怪的辅助实体。固定以下三种场景，M2-06 生成并归档实际夹具、输入轨迹与 SHA-256；此处定义的是构造合同，尚无运行快照或通过结果。

| 场景 | 固定构造与记录 | 通过条件及关联验收 |
| --- | --- | --- |
| PF01 同波超限 | 从普通波首批 C01 已通过、个人容怪点恰为 100 的快照开始，保留该波真实后续批次和下一波首批事件；后续刷怪使点数超过 100，固定输入保持到下一次检查。夹具登记所用波次、批次、敌人 ID、点数及事件时刻；不在采样中追加调试刷怪 | 同波不提前判负、不截断刷怪或删除超额对象；下一波首批按当时实际点数判定。超限段仍执行移动、攻击、渲染和保存并达到既定指标。关联 A05/A12/A13 |
| PF02 挑战及召唤峰值 | 在首批检查之后的主线负载上接入已核 m523 挑战出怪，共 12 只、每只 3 点；使用入选 H029 的召唤和 i196／i722 的真实效果形成己方召唤／幻象负载，并保留该场景敌方的真实辅助生成。不得把 36 个挑战点写成 36 只怪，也不得裁掉不计个人点数的实体；固定完整素材、合法施法轨迹及实体峰值 | 全部对象的登记、撤销、技能和特效实际运行；峰值下输入、帧耗时和事件积压达标，开启保存与关闭保存结果一致。关联 A08/A12/A14/A17 |
| PF03 最大保存快照 | 对 PF01/PF02 及 M2-07 至少四个种子的整局轨迹采集快照，从中选序列化字节数最大者；另保留待处理事件数或实体数更高的快照，避免三种峰值不在同刻时漏测。保存持续效果、在途弹道、召唤、商店／奖励、PRNG 和事件队列 | 比较连续运行、存档开／关、写入失败恢复和挂起补算结果；逐项记录复制／序列化／提交耗时及恢复一致性。关联 A12/A13/A16 |

峰值场景从预先固定的同一快照开始各跑 3 次，统计全部有效交互帧；如果自然发生失败或结算，到该终态结束本次样本并重新载入开始下一次，不关闭判负、不停波、不延长召唤寿命来凑 10 分钟。短峰值样本与持续 10 分钟整局样本分开报告，不能混入终态空闲帧稀释峰值。

M2-06 在已建立的候选 HTTPS 上试跑 PF01/PF02 和当时最大的 PF03，记录缺失依赖及失败项；不因完整主线尚未接好而跳过。M2-07 接齐实际时间线后以完整轨迹补充 PF03，并冻结最终夹具。M2-08 接入最终 UI／保存链后检查负载仍有效；M2-09 用交付候选构建运行全部固定场景和持续样本，失败项修复后才能通过。夹具版本或素材／技能负载变化须重新测量，早期试跑不能替代最终成绩。

性能报告除通用版本字段外，还须包含 fixtureId、快照和输入文件摘要、浏览器／硬件环境及上述负载计数；同一比较组的初态、输入、构建、环境一致，只切换保存开关。夹具允许构造高负载初态，但不作为 A10 正常新局战力证据。
