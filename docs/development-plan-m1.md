## 依赖与任务

先确定内容和状态契约，再实现统一逻辑帧；经济与模式可分别推进，随后接入完整保存和桌面交互，最后验收整局。依赖关系如下：

```text
M1-01 → M1-02 → M1-03 ─┐
           ├─→ M1-04 ─┴→ M1-05 ─┐
           └─→ M1-06 ────────────┴→ M1-07 → M1-08
```

依赖以表格为准；M1-06 可与经济／模式实现独立推进，M1-05 依赖状态写入契约，不依赖 3D 资源。

## V1 性能验证的计划通过线

在记录机器、桌面 Chrome 版本、分辨率及配置版本的固定环境中，使用首版可达到的接近容怪上限、最多己方单位／持续效果和最大代表性快照，固定种子与输入轨迹。分别开启／关闭自动存档，4× 下连续操作 10 分钟现实时间；另覆盖活页面冻结 5 分钟后按 4× 补算，并检查中途失败时的停止帧。

计划通过线：输入收到至 UI 确认的 P95 ≤100 ms、P99 ≤200 ms，保存开启相对关闭的 P95 增量 ≤20 ms；无指令丢失，4× 前台待算积压不持续增长，同逻辑时刻玩法状态一致。UI 确认时间与下一逻辑帧生效时间分别测量；报告另列逻辑帧、快照生成／复制／提交耗时和补算总耗时。

若未通过，先依据测量定位复制、排队、渲染或逻辑计算开销，再优化并复测；不以删除无尽、降低承诺倍速或遗漏保存绕过验收。
