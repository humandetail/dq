## 范围与规则继承

1. **内容身份。** 按下表的名称、卡片 ID、塔对象链及资格映射，实现对应属性、完整绑定技能、获取和成长；开局为小小、双头龙、暗影萨满、复仇之魂四选一。模型替换仅调整外观，保持这些内容身份及玩法字段。
2. **规则来源。** 直接消费已提炼的规则规格及用户裁决，包括 Q24 的明确 Web 行为；继续查证时遵循图鉴优先、缺失查地图资料。专项的最终收口及索引优先于其中保留的早期“尚待核查”文字。M2 配置决定本期适配及名单，M1 样例数值和简化机制不作为 M2 的默认值。
3. **主线体量。** 单人、个人模式、普通难度，覆盖 55 波及其敌方能力、波间事件、福利打金、商店开放、透支和最终肉山。普通难度倍率按已核 1.2；主线个人容怪容量按已决 100，失败时点仍按 C01。模型外形不决定移动类型、碰撞、射程或伤害。
4. **阶段结束。** 普通难度按已核难度与模式关系结束于主线结算。结算后可查看结果、重开，刷新后保留结算阶段。已提炼的无尽、深渊、多难度、剩余图鉴内容和手机完整触控按 F1–F3 后续批次交付；M1 的样例无尽不计入这些模式的完成状态。
5. **平衡与取得。** 通过抽卡、资源、布塔、技能、装备和突破共同形成阵容，不指定固定通关阵容。若首批内容不能支撑普通主线，先核对遗漏的规则、收入与依赖，再补必要内容；不通过静默削弱敌人、修改既定概率或删除绑定技能解决。
6. **地形与模型。** 制作新的魔兽式斜俯视 3D 地形场景，交付地表材质、可辨识的道路与建造区、边界及障碍表现，并与实际空间数据对应；布局允许重新设计。参战对象优先使用素材清点中与内容 ID 对应的魔兽模型，缺项可从已有模型库选其他魔兽模型，登记对应关系并验证贴图、所需动画和依赖。几何块、路线线条、Prism／Skimmer 样例仅用于开发调试，不能作为该项交付。镜头默认斜俯视，可切换俯视、左右旋转与拖动调整俯仰，保留平移、缩放和一键复位；外观不改变碰撞与规则。
7. **地图布局与放塔可见性（2026-11-25）。** 按用户提供的[布局参考](evidence/m2-map-3/reference.png)，采用多层回字形道路与环间分岔，按用户明确要求，横向复用纵向中间的设计：四个方向分别连接外圈 → 中圈 → 内圈，在内圈边缘终止，中央区域保持断开及绕行关系，层间留出可建造区域。道路与建造地表明确区分，常驻显示建造区边界及图例；选择塔卡或工人塔后显示网格、完整底座预览和可放／不可放反馈，支持取消与回到全图。放置预检与正式提交使用同一规则，失败保留选择且不消费。布局变更须标记地图版本，旧路线存档保留并提示重开，不能直接套用新路点。

## 核心机制适配

M1 的状态独占、稳定 ID、命令提交和 IndexedDB 保存协调器可继续使用。其 100 毫秒逻辑帧、四个固定阵位、直接扣生命的攻击、单件装备和样例配置均只支撑 M1；M2 须按以下规则实现并逐项验收。

- **时间。** 按 [B05](rules/web-baseline.md#b05同一时刻的计时事件按入队顺序执行)使用整数微秒和到期时间／入队序号排序。可以保留外层批量推进，但内部完整执行各到期事件；零秒回调留在同刻队尾，周期事件从计划时刻递推，不取整到 100 毫秒或渲染帧。
- **移动与空间。** 每 1/32 战斗秒更新，按稳定创建顺序处理；沿[空间规则](rules/pathing-and-placement.md)执行寻路、扫掠、动态占用和入区。分岔按已定候选顺序及随机状态选择，排除来路；卡住不凭空移除、扣容怪或传送。新地形数据和模型缩放不覆盖真实移动类型与攻击目标类型。
- **同刻规则。** 写清玩家命令、移动、波次首批、C01、攻击和伤害事件的交接。C01 的首批加入与检查不可被攻击或快照插入；超限判负先于同刻攻击，等于上限继续，同波后续批次不另触发。补算期间新命令不回填历史事件。
- **战斗与资源。** 接入已核普通攻击、护甲／魔抗、命中、弹道、控制、光环、施法、伤害重入和死亡奖励，再实现各塔与装备的局部效果；贡献移除只撤本来源，不能靠改写最终面板值代替生命周期。
- **状态与保存。** 存档覆盖事件队列及序号、取消状态、路线与随机状态、施工／升级、经验与技能点、资格 ID、装备实例及归属、充能／成长、效果／召唤物、商店／奖励防重和阶段倒计时。恢复不重放建成、抽签、学习或发奖。
- **跨标签写入。** M2 使用独立数据库、Web Locks 单写者及事务内 `revision＋activeMatchId` 比较，档案与对局原子保存；第二标签只读，接管前重读最新修订，不按挂起超时抢锁。旧自动快照、旧局事务和旧回调不得回退余额、领奖状态或新局 ID。完整合同见配置定稿第 4 节，不能直接沿用 M1 的无条件覆盖写入。

现有 335 项塔技能、243 件装备道具等核查成果是规则来源。它们与 M1 自动测试均不能替代 M2 对运行代码的契约和整局验证。

### M2 性能通过线

基线固定为 MacBookPro16,2／四核 2.0 GHz Intel Core i5／16 GB／Intel Iris Plus，Chrome 158.0.8127.88，有窗口硬件加速、1440×900 CSS 视口、DPR 1、60 Hz。100 点仅是 C01 检查阈值，不是对象上限；固定 PF01 同波超限、PF02 挑战与召唤峰值、PF03 最大保存快照，并覆盖人口 90–100 的代表阵容和肉山。分别记录个人容怪点、全部敌我实体／召唤物、弹道／效果、事件数及快照字节。完整构造、版本字段和统计口径见[配置定稿第 5 节](m2-configuration.md#固定峰值场景与提前验证)。

自动存档开／关各测 4× 连续现实 10 分钟，每组至少 3 次全部达标。输入确认 P95≤100 ms、P99≤200 ms，存档导致 P95 增量≤20 ms；中位 FPS≥55，帧间隔 P95≤33.4 ms、P99≤50 ms。冻结现实 5 分钟后按 4× 补算，每片计算预算≤8 ms，现实 60 秒内追平或到正确终局。冷启动 20 Mbps／50 ms RTT 下交互可用≤15 秒。命令零丢失、前台积压不持续增长，同战斗时刻状态一致；另报命令实际生效及事件／快照／提交耗时。

性能验收使用候选 HTTPS 的实际路径、技能、素材及保存链；先定位失败项再优化，不通过降低承诺倍速、移除复杂技能或停用自动保存通过测试。以上是已定通过线，尚无 M2 运行成绩，不能用隔离逻辑页的输入耗时代替三维场景流畅度。

M2-06 开始峰值试跑，M2-07 从完整时间线冻结最终快照，M2-09 在交付候选构建全部复测。短峰值场景各跑 3 次，与持续 10 分钟样本分开报告；自然进入终态即结束本次峰值样本，不能停波、禁用判负或混入终态空闲帧来凑时长。每份结果附夹具、输入和构建摘要，负载变化后重测。

## 公开交付清单

- 稳定、无需登录的公开 HTTPS 地址，静态模型／贴图等依赖随生产部署可访问；同址续局不依赖本地文件路径。
- 与线上版本一致的提交／标签、构建产物和内容／存档格式版本，包含安装、启动、检查、玩法和已知限制说明；验收记录附配置与构建摘要、种子、输入及初态文件，线上实际构建须能对应到证据。
- A01–A18 的结果与证据：规则来源、自动检查、正常整局、13 条突破链、截图或必要录屏、性能报告；规则核查、实现完成、运行通过分别记录。
- M2 从新局开始，不迁移 M1 存档；M2 后续更新明确兼容版本，兼容时迁移并验证，不兼容时保留原记录并提示，不能静默覆盖成新局。
- 发布前在候选部署做完整验证，交付时核对公开地址实际版本；保留可重建的前一构建及回退步骤，回退同步检查内容与存档兼容性。
- 结算、失败、重开和线上续局均从正式界面可操作；无尽、深渊、多难度、剩余图鉴内容和手机适配按[后续恢复登记](post-m2-backlog.md)进入 F1/F2/F3，41 个后移图鉴物品及兑换／任务／礼盒均有任务和验收入口，不把它们记作本轮已完成。
