# 以图鉴作为 Web 移植的规则基准

采用用户指定的6.25图鉴为第一依据，从原地图补足缺项。图鉴来自静态核对，部分规则缺失，且可能存在成品与制作书描述不一致的情况；需保留来源证据，不能把地图数据直接视为全部规则的最终答案。

2026-11-23用户补充授权：“后续这种图鉴和脚本数值差异，均以图鉴数值为主，不需要再让我决策”。因此，确认技能/物品身份、等级、单位和触发入口对应后，图鉴与原脚本之间的数值差异自动采用图鉴值，不再逐项询问。保留原值、比较式与证据位置，并记录Web采用值及必要的边界验证；已有单独裁决保持有效。

这项授权不把不同技能或入口的数值误配当成冲突，也不把图鉴缺项解释为零。图鉴内部互相矛盾、存在多种合理解读的机制或新的产品取舍，若无法从既有决定与来源消除，仍按用户要求一次只问一个问题。已查证但无法确证的原生细节继续按Q24建立明确的Web规则；未阅读的脚本继续调查。

[两书补充列全量证据](../rules/workbook-supplementary-columns.json)确认塔技能J4的实际表头为“补充对象字段”。全书249个非空J单元格涉及117个ID，共375段冷却/耗蓝数据，逐段对应原W3A中同ID的acdn/amcs修改，未发现不符；它是原对象字段附录。H/I正文已经明确同等级设计值时，沿既定图鉴设计优先政策采用H/I，J保留为来源证据；正文缺失时才用J补足，再查原图。不把这类正文/原对象附录差异另列用户决策题。例如A194采用正文20/40/60/80/100/120耗蓝，A217采用30/60/90/120/150/180，J中的旧对象值仍不改写。

## Q54：已验证的跨施法计数串扰

用户已确认：图鉴规定单次施法次数或持续时长，且原指令验证共享计数导致新旧施法互相覆盖、提前结束或超额时，Web采用每次施法独立实例，不再逐项确认。各技能实时等级、神杖和选目标规则保持；有意共享层数、资源及光环组不适用。记录最小原重现及Web边界验证，不能仅凭变量共享就改写机制。

## Q61 与 Q64：减少已明确规则的重复裁决

Q61：图鉴未给具体数值时，核实为同一对象、等级和效果后，原地图专属提示优先于执行代码；陈旧通用模板不能覆盖该技能专属提示。保留两套来源和差异，已有明确逐项用户裁决优先。

Q64：图鉴机制明确且内部不矛盾时，脚本的相反或遗漏行为统一按图鉴修正留证，不再逐项询问。图鉴缺漏仍查原图补齐，不能把未写某个细节当成禁止；图鉴内部矛盾或必须新增设计才提问。

## Q71：原地图专属提示的明确机制

图鉴缺失时，经确认相同对象、等级和效果且原地图专属提示明确、内部不矛盾，机制亦优先提示；图鉴及先前明确裁决更高，通用陈旧模板不算，提示歧义另问。保持原值、原执行路径与采用规则的对应证据。例如涤罪之焰每层均包含“当前生命5%＋1000”，不能只给其中一层固定1000；提示仅列出的Boss例外按实际对应身份实施，不将整个模式的普通敌人一并排除。
