# 经验授予、击杀分摊与等级门槛

本页为 `experience-sharing-v1`，只补经验链，不重算或更改 [B02 经验表](web-baseline.md#b02经验表逐项向下取整)。结论分为原图事实、有出处的外部默认数据和 Q24 下的明确 Web 行为。配套 [experience-sharing.json](experience-sharing.json) 保存字段行号、字节码范围、直接奖励表和算例；尚未运行原客户端或 Web 游戏。

## 原图实际控制了什么

|配置|原图值|来源|
|---|---:|---|
|建筑作为击杀者可产生经验 `BuildingKillsGiveExp`|1|[Misc L11](../../reference/map-6.25/war3mapMisc.txt#L11)|
|无附近英雄时的全局经验 `GlobalExperience`|0|[L29](../../reference/map-6.25/war3mapMisc.txt#L29)|
|经验范围 `HeroExpRange`|1600|[L39](../../reference/map-6.25/war3mapMisc.txt#L39)|
|原生英雄最大等级 `MaxHeroLevel`|30|[L44](../../reference/map-6.25/war3mapMisc.txt#L44)|
|`TWN1/TWN2/TWN3.XPFactor`|均为 0|[L67](../../reference/map-6.25/war3mapMisc.txt#L67)、[L71](../../reference/map-6.25/war3mapMisc.txt#L71)、[L75](../../reference/map-6.25/war3mapMisc.txt#L75)|

三组经验表起点和递推系数见 B02。这里的 `BuildingKillsGiveExp` 指**建筑打出最后一击**，不能误写成“所有被杀建筑都给经验”。三个城镇等级的经验加成均被地图明确设为 0，因此不引入标准对战的单英雄高级基地经验加成。

全文扫描 Lua、JASS 和字节码，地图实际调用 `AddHeroXP` 的位置只有下述五个道具函数。`SuspendHeroXP`、`SetPlayerHandicapXP`、`SetHeroLevel` 只找到原生绑定／通用 BJ 封装，没有地图调用；`SetHeroXP` 还出现在通用 `ReplaceUnitBJ` 内复制旧英雄经验，但未找到该封装的地图调用。这是所给源文件中的静态覆盖结论，不代表闭源引擎没有对应行为。不能把 20 级限制实现成原图调用了经验暂停，也不能擅自加一个难度经验倍率。

### 直接奖励：五个脚本入口，三个原生道具对象

`ItemSkillUsed` 按技能 ID 分派五个函数，调用后立即返回：[Lua L96040–96081](../../reference/map-6.25/main.readable.lua#L96040)、[字节码 L143978–144023](../../reference/map-6.25/main.disasm#L143978)。全部向 `GetSpellTargetUnit()` 调 `AddHeroXP(target, amount, true)`；若目标 `GetUnitLevel()==30`，先提示并返回。它们没有再判断附近英雄数量，也不查询目标当前经验。

|物品 / 技能|脚本实际奖励|Lua / 已核字节码|

|经验书 i127 / I167|1400 XP|[L80201–80230](../../reference/map-6.25/main.readable.lua#L80201)；`main/f235/f0` L126472–126520|

|知识之书 Lv1 i312 / I226|2000 XP|[L81649–81678](../../reference/map-6.25/main.readable.lua#L81649)；`main/f250/f0` L128815–128863|
|知识之书 Lv2 i313 / I227|20000 XP|[L81689–81718](../../reference/map-6.25/main.readable.lua#L81689)；`main/f251/f0` L128882–128930|
|知识之书 Max i314 / I228|与 I168 相同 D(L)|[L81728–81781](../../reference/map-6.25/main.readable.lua#L81728)；`main/f252/f0` L128949–129030|

五个能力都是 `AOcl`，目标字段 `invulnerable,hero,friend`、射程 999999；这不表示每次对范围 500 内所有英雄发经验，脚本只用一个 `GetSpellTargetUnit`。完整对象字段和增量检查见机器表。

能量书算法是独立的**脚本实数运算**，不是 B02 表的逐项取整：

```text
s = 0
for j = 1..L:
    if s == 0: s = 20
    else if j == L: s = (s*1.4 + 20*(j+1)) - s
    else: s = s*1.4 + 20*(j+1)
D(L) = floor(s)
```

按原指令顺序以二进制双精度执行，中间不 floor；30 级分支已经先返回。D(1..5)=20/68/115/181/273，D(10)=1691，D(20)=50321，D(29)=1040682。10 级时 B02 相邻门槛差是 1687，不能拿这个数替换脚本的 1691。它仍使未被门槛阻止的 1–29 级英雄恰好提高一级，但可能留有额外经验，且不保证经验条百分比保持不变。逐级验证表列在 JSON。

另有 `texp→AIem.DataA1=150`、`tgxp→AIe2(code=AIem).DataA1=500`、`tkno→AIlm.DataA1=1` 三个原生拾取即用对象。前两项分别与图鉴 `装备与道具!H245/H246` 的 150/500 一致；获取入口仍未确认，不因为存在对象就新增售卖入口。它们不是五个脚本函数的第六次分派，不能再额外叠一次脚本奖励。

### 原生英雄、Boss 谓词与击杀归属

经验表和接收资格使用原生英雄类型 `IsUnitType(u, UNIT_TYPE_HERO)`。自定义 `UnitIsHero(u)` 实际是 `GetUnitAbilityLevel(u,N534)>0 AND IsUnitType(u,UNIT_TYPE_SAPPER)`：[字节码 main/f7/f45 L52444–52480](../../reference/map-6.25/main.disasm#L52444)。它用于若干 Boss／掉落判断，不等于原生英雄。普通死者用其单位等级查 N 表；原生英雄死者用运行时英雄等级查 H 表，不用主线波号，也不用英雄对象的静态 `level` 代替实际英雄等级。

普通主线／无尽造怪函数创建的是 **Player(11)** 单位：[Lua L128509–128518](../../reference/map-6.25/main.readable.lua#L128509)、[字节码 main/f294/f18 L184648–184657](../../reference/map-6.25/main.disasm#L184648)。`PLAYER_NEUTRAL_AGGRESSIVE=12` 在 [Lua L614](../../reference/map-6.25/main.readable.lua#L614)。所以怪物名称、`race=creeps` 或自定义 Boss 标签都不能使 Player(11) 的怪物自动变成中立敌对野怪。机器表列出 55 个主线对象的 `level`，例如 m001 等级 1、m003 等级 2，按 B02 的 N 表分别为 2、6 基础 XP。

`anyUnitDEAT` 开头取 `GetKillingUnit()`；稍后对临时单位、召唤物或幻象把**本地奖励归属变量**改为 `Tower_ALL[GetUnitUserData(killer)]`，用于额外金币、技能和装备成长：[Lua L115968–115995](../../reference/map-6.25/main.readable.lua#L115968)、[字节码 L168707–168744](../../reference/map-6.25/main.disasm#L168707)。这里没有经验分配调用，也没有改写引擎 `GetKillingUnit`。不能拿这个塔索引把原生范围经验全塞给召唤者本人。死亡处理还可能当场复活玩家英雄或清理死者，因而 Web 必须明确经验取快照与死亡回调的先后。

### 20 级门槛是升级事件，不是经验开关

Player(0..3) 注册 `EVENT_PLAYER_HERO_LEVEL`：[Lua L125208–125250](../../reference/map-6.25/main.readable.lua#L125208)、[字节码 main/f291/f38 L179949–180014](../../reference/map-6.25/main.disasm#L179949)。`HeroLevelUpEvent` 已核 [main/f291/f18 L172901–172978](../../reference/map-6.25/main.disasm#L172901)，实际顺序为：

1. 取得升级单位及当前等级；若有 A225，先加再移除 T299。T299 是 `AIml`，不是经验能力 `AIlm`，不要交换两个字母。
2. 若 `Game_Mode != 2 AND level > 20 AND B015<=0`，调用 `UnitStripHeroLevel(unit, level−20)`，本地等级变量改为 20。
3. 调 `WAbility_W019(unit, 最终本地等级)`。该函数只给原生英雄、且所属工人已有 W019 时重算三属性加成 `floor((0.5*天赋等级+0.5)*英雄等级)`；先减去记录中的旧加成再加新值，不是再发经验。[Lua L132345–132448](../../reference/map-6.25/main.readable.lua#L132345)、[字节码 main/f296/f21 L190265–190408](../../reference/map-6.25/main.disasm#L190265)

没有“失去 B015 时立即剥级”的经验监听器：已到 25 级后失去资格，只有再次升级触发此事件才检查；30 级没有后续升级事件，也不能凭本页额外降到 20。资格本身的添加／移除依其规则，本页不重定义。

## 原开发方资料与版本边界

[暴雪 Hero Basics](https://classic.battle.net/war3/basics/heroes.shtml)支持敌对击杀、附近友方英雄均分、普通／英雄奖励区分及野怪奖励按接收英雄等级衰减；其比例奖励示例向下取整。默认全局兜底、默认满级、建筑击杀限制和基地加成均须服从本图覆盖，不能整页照搬。

已固定的 [YDWE 原作者仓库 MiscGame](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Component/share/en-US/mpq/Units/MiscGame.txt#L69) 与 [Custom_V1 数据](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Component/share/en-US/mpq/Custom_V1/Units/MiscGame.txt#L69) 同时给出：`MaxLevelHeroesDrainExp=1`（L69）、`HeroFactorXP=80,70,60,50,0`（L133）、`SummonedKillFactor=0.5`（L134）。这是随该版本工具分发的原始数据证据；本图没有显式覆盖，不声称已识别实际客户端读取的最终默认表。

当前官网的野怪表是 80/70/**62/55**/0，和上述 80/70/**60/50**/0 不同。这是外部版本资料差异，不是图鉴冲突。下文选择固定数据表作为 Web 后备；对 Player(11) 普通波怪，两种野怪表均不应用。第三方引擎的经验实现仅供参考。

## Q24 下的完整 Web 行为

下列选择补足仍无法匹配客户端验证的原生细节；其数值和时序明确可测。B02 保持原版本，不能把这页的直接道具算法统一改成 B02。

**X01：一次死亡只生成一次击杀经验事务。** 在致死提交时记录死者位置、所有者、原生英雄／召唤／幻象标记、死亡等级、实际致死伤害来源及来源所有者。只有有明确来源、且死者对来源玩家敌对时才产生击杀经验；自杀、友军击杀、无来源 `KillUnit`／寿命结束、移除单位和回收不产生。无需另外用击杀者距离判定；真正受 1600 限制的是接收英雄到死者的位置。

采用致死包的实际来源所有者，不追溯最后一次普通攻击，也不使用死亡脚本映射后的 `Tower_ALL` 归属变量。召唤物／临时施法单位杀敌仍按其实际所有者参与范围分配，**召唤击杀者本身不使经验减半**。死亡幻象不给经验；非英雄建筑死者仅在有对象启用的攻击通道时给普通单位基础经验。自定义 `IsTemp/UnitIsHero` 不额外成为经验过滤器。以上未被原脚本明确给出的死亡准入，是本页选择的原生替代边界。

先完成这次经验事务，再执行原死亡脚本，避免它的复活、移除和掉落改写本次死亡快照。事务不改变原死亡脚本内部调用顺序。经验导致的升级回调同步处理；同刻多次死亡仍按现有 B05 顺序，每次死亡各取自己的快照和分母，不能按渲染帧把数次击杀合为一笔。

**X02：死者中心 1600 闭圆，合格英雄均分后各自最后取整。** 从死亡提交当刻取一次接收集合：原生英雄、存活、在场、已完成施工、非幻象、未暂停击杀经验，且属于击杀玩家或其友方玩家、并与死者敌对，二维中心距离平方 `<=1600²`。死亡英雄、施工中英雄、离场英雄不占分母。单位暂停、眩晕或变形本身不自动设置“暂停击杀经验”；只有明确的经验暂停状态才排除。当前已核地图没有设置该状态，初始为 false。单人模式只存在本玩家可参与的友方英雄，不生成额外队友份额。

30 级英雄**仍计入人数 M，但实际收取 0**，采用 `MaxLevelHeroesDrainExp=1`。无 B015 的 20 级英雄仍计入并可得到经验，之后由 X04 处理跨级；野怪比例为 0 的英雄也占分母，不把它们的份额转给别人。M=0 时不发经验，不触发全图兜底。

```text
base = 原生英雄死者 ? B02.H(死者运行时英雄等级) : B02.N(死者单位等级)
summonFactor = 死者具有原生召唤类型 ? 1/2 : 1
creepFactor(h) = 死者所有者为 Player(12)
                 ? [80,70,60,50,0][min(h死亡快照等级,5)] / 100
                 : 1
rawShare(h) = base * summonFactor * creepFactor(h) / M
award(h) = h已满30级 ? 0 : floor(rawShare(h))
```

公式以有理数完成比例和除法，最后各接收者 floor 一次，不先把 `base/M` 取整；丢弃余数，不按创建顺序补发。数据不足以确定死者等级／原生分类时应报告缺项，不能设等级 0 或把任意 Boss 自动套 H。没有额外难度、地图等级或基地经验倍数；当前玩家经验 handicap 明确采用 1。超 30 的普通死者等级沿 B02 递推，不把其等级夹为 30。

集合、接收者用于野怪比例的等级和每人奖励先固定，再按创建序号逐个提交，某英雄升级不重分此次其他人的份额。每笔击杀及其已提交状态随存档保存，读档不能再次发同一份 XP。

**X03：直接经验仅给指定英雄，不经过击杀公式。** 五个脚本函数按原数量和运算顺序执行；不除附近人数，不乘召唤／野怪／基地／handicap 因子，也不受暂停“击杀经验”的状态影响。原生经验道具 150/500 同样直接加给拾取英雄。目标须是有效存活原生英雄，现有能力目标限制保留；达到30级的原脚本分支直接返回，不倒推是否退充能，充能提交顺序不属本页。

原生 `tkno/AIlm` 的 1 级效果缺少本图运行证据，因此选定为加入 `T(L+1)-T(L)` XP，保留已有绝对经验进度，最多到 30 级；不额外调用 I168。它是否可获得仍由对应入口决定。所有直接经验均走 X04 的等级变化和现有门槛，不能把“增加一级”解释为绕过 B015。

**X04：每跨一级同步执行升级事件，剥级明确重置到目标级门槛。** 新英雄经验初始为 0、等级 1；累计经验使用 B02 的 T。一次正奖励先得到 `newXP=min(oldXP+award,T(30))`，按跨越等级从低到高逐级增加等级及其自然成长，执行一次原 `HeroLevelUpEvent`，然后继续处理下一等级。每次事件都读取当前真实 B015 和 Game_Mode，保留 A225/T299 在剥级之前、W019 在剥级之后的顺序。

当原脚本调用 `UnitStripHeroLevel(u,k)` 时，Web 明确减少 k 级并把 XP 置为结果级的 `T(level)`，不额外触发升级事件。通常在刚跨到 21 时降回 20；若原已到 25 后才失去 B015，则下一次升到 26 时会一次剥掉 6 级，不能硬编码每次只减 1。若剥级发生，本次奖励剩余越界进度丢弃、结束本次等级循环，避免同一笔经验反复 `20→21→20`；W019 仍按原回调的本地 20 更新。本页固定 XP、等级和事件边界，既有属性／技能等级如何随原生剥级变化属于英雄生命周期范围，不在此擅自清空装备、永久属性或已学技能。

这个 XP 重置点及多级事件时序是 Q24 选择，不能称为已实测的 `UnitStripHeroLevel` 引擎实现。20 级没有 B015 时，未到 T(21) 的经验仍能暂时积累；越界才触发丢弃。后续取得 B015 不恢复被丢经验。失去 B015 不单独触发本页降级；满 30 级英雄不再积累 XP，不因收到 0 XP 触发升级事件。
