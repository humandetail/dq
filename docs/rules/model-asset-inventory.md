# 原图模型资源清点

按用户要求，Web使用魔兽格式模型，并优先保持原图对应外观；缺项可采用已有模型库中的其他魔兽模型。这里先核实资源是否存在及其依赖，不用“单位表写了模型路径”代替可渲染验证。

对274个图鉴塔对象，已读取单位UI模型字段并检查w3u增量；没有模型字段覆盖。它们共引用157个不同模型路径。只读查询原地图MPQ并解压后，结果为：

| 范围 | 结果 |
|---|---:|
| 模型路径在原图内存在 | 62个，对应65个塔对象 |
| 模型路径不在原图内 | 95个，对应209个塔对象 |
| 已读二进制MDX的块结构、动画及贴图表 | 61个 |
| 已读文本MDL的动画头与贴图声明 | 1个，sf.mdl |
| 存在模型但至少一条命名贴图不在原图内 | 37个 |
| 其命名贴图均能在原图中查到 | 25个；仍需贴图解码和完整渲染验证 |

缺失的95条都是带目录的外部资源路径，未找到根目录自定义模型名缺失。常见例子包括暗夜魔王的 `units\undead\HeroDreadLord\HeroDreadLord`、半人马的原生单位目录。因此这是对基础资源的依赖，不能据此说原地图坏了，也不能假装从地图已经提取到魔兽客户端的全部文件。

已有的62个模型版本字段均为800。`Tichondrius.mdx`有11段动画、命名贴图均在图内；`HongPaoXianZhe.mdx`有8段。影魔 `sf.mdl`实际是文本MDL，不能因没有MDLX头判定损坏；它有11段动画，同时依赖4张图内未找到的基础贴图。已发现的可替换贴图ID为1/2，仍需实现队伍色等对应资源。

原始路径、规范化候选、MPQ块位置/大小、模型SHA256、动画名字/区间及逐条贴图查询保存在[机器清单](model-asset-inventory.json)。`python3 tools/audit-model-assets.py` 可从原地图重新生成；该工具不修改或执行地图，不把资源提取进游戏目录。

二进制结构依据[模型解析器](https://github.com/flowtsohg/mdx-m3-viewer/blob/master/src/parsers/mdlx/model.ts)、[动画记录](https://github.com/flowtsohg/mdx-m3-viewer/blob/master/src/parsers/mdlx/sequence.ts)和[贴图记录](https://github.com/flowtsohg/mdx-m3-viewer/blob/master/src/parsers/mdlx/texture.ts)，档案查询沿用[StormLib散列/解密算法](https://github.com/ladislav-zezula/StormLib/blob/master/src/SBaseCommon.cpp)。这是静态资产核查，尚未用Web渲染器测试。

## 本机模型库复核

已复核 `/Users/laihanbin/Downloads/环界模型库/catalog.json` 的1333条目录记录，对2477个不同资源文件重新核存在性与内容哈希，未发现缺文件或与内容命名不符的文件。重新解析后，716项的模型头和包内命名贴图绑定齐全，613项仍缺命名贴图，4项需另查（包括非魔兽模型格式）。其中266项同时具备几何头、待机/攻击/死亡动画和已解析的命名贴图，可作为已授权替代方案的候选；这不等于266项已经通过实际渲染。

原图本批缺失的70条不同命名贴图路径中，仅8条在库内有完全同路径候选；同一路径有多个不同内容时均保留，不能凭文件名声称是同一素材。模型库有大量候选，也不能据此声称原图的全部基础贴图已补齐。

明细见[本机模型库复核](local-model-library.json)，可用 `python3 tools/audit-local-model-library.py` 重做只读检查。后续按已授权规则记录原模型与替代模型对应，继续核附件/粒子引用、贴图格式、骨骼/材质/动画实际播放及怪物、工人、弹道、特效和界面资源。命名贴图齐全不代表其他依赖齐全。模型尺寸和动画选择只影响呈现，攻击时点、射程和碰撞继续使用已定玩法数据。
