# 村正「居合」与竹光「细雪」

本页补完上一批未展开的 `i132_Skill`、`i132_Get_probability`、`i134_Skill`、`i134_Get_probability` 四个函数，以及直接影响它们的入口条件、回蓝先后、B060修正和特效清理。四个函数共126条指令、8条条件、23处调用、8条return指令；两条概率函数各有一个不可达的编译器末尾return。公式、比较和跳转已对照字节码；不是原客户端实测。

**Q28、Q29已裁决**：Web居合采用20%概率、攻击力×3.6；最大生命15%、460范围等原图补充规则保留。Web细雪采用50%概率、当前魔法×0.67；900范围、原触发过滤和取值时点保留。下文同时保留原脚本，不能以Web裁决改写历史证据。本批没有仍待裁决的公式冲突。

来源为 [main.disasm](../../reference/map-6.25/main.disasm)，[main.readable.lua](../../reference/map-6.25/main.readable.lua)只作定位辅助；[机器索引与局部验证案例](item-muramasa-takemitsu.json)保留条件真假去向、过滤名单、入口与数值例子。此前核完的村正物理×1.25、竹光魔法×1.32复用 [装备伤害效果](item-damage-effects.md)，不重复扩查装备属性、获取、成长和携带限制。

后续 [范围伤害基准 area-damage-v1](native-area-damage.md) 已依 Q24 明确这两项范围包的目标、边缘、魔免和零延迟同步顺序。下文保留原生证据边界，不再将其视作 Web 规则待定；法力时序和相关英雄生命周期仍需各自核查。

## 2. 居合：资格、公式和范围

### 直接资格与随机顺序

`Item_Attack_Special(S,T)` 的第一段（main/f285/f14，L146270–146287）先查 `HasItem(S,i132)!=nil`，有装备才调用 `i132_Get_probability()`，概率返回真才调用 `i132_Skill(S,T)`。没有自己的近战、幻象、英雄、存活、法力或冷却门槛；相应限制要看具体调用入口，不能挪用狂战斧的近战限制。这里没有按物品栏循环，多件同ID不会在本段自动多抽几次。

原概率函数是 main/f238/f2，L126877–126903：先抽 `r=GetRandomInt(0,100)`，返回`r<20`；r=0、19成功，20、100失败。执行技能时才检查计算伤害是否为正，所以即使本次伤害为0，入口仍先消耗这一次概率抽样。Q28只替换成功概率，保留这一执行顺序。

### 技能体

`i132_Skill(S,T)` 为 main/f238/f1，L126768–126875；阅读稿L80381–80451：

```text
maxAttack1 = GetUnitState(S,ConvertUnitState(21))
minAttack1 = GetUnitState(S,ConvertUnitState(20))
maxLife = GetUnitState(S,UNIT_STATE_MAX_LIFE)
P = ((maxAttack1+minAttack1)/2)*3 + 0.15*maxLife   // 原图
P = ((maxAttack1+minAttack1)/2)*3.6 + 0.15*maxLife // Web Q28
if P <= 0: return
point = GetUnitLoc(T)
if GetUnitAbilityLevel(S,B060)>0:
    if Has_A_Item(S)==false:
        P = A163_Debuff_DUr(S,P) // P*0.8
SetPhyDamagePoint(S,0,460,point.x,point.y,P)
if TxShow==true:
    CreateEffAtLoc("Cleave_Cast_Base_Purple.mdx",point,0.5,3.6)
return
```

两条P赋值表示原图与Web两种规格，**不是先后执行两次赋值或制造两份伤害**。取值与计算在L126806–126826；非正数早退L126827–126829；B060及强化资格短路L126834–126851；范围提交L126853–126864；特效L126865–126875。没有取整、最低伤害保底、排除原目标或金币怪×0.2；这些不能从其他装备搬入此函数。它也没有检查T是否nil，必须保持调用者契约或另核native异常边界。

21/20的语义由扩展作者 [YDWE UnitState.cpp固定版本](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Plugin/Warcraft3/yd_jass_api/UnitState.cpp#L22)支持：0x14/0x15分别为第一攻击最小/最大伤害；[L289–294的实现](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Plugin/Warcraft3/yd_jass_api/UnitState.cpp#L289)分别使用`base+bonus+dice`和`base+bonus+dice*side`。因此这里是上下限均值，**不是本次攻击掷出的实际伤害，也不是当前伤害事件值**。该扩展源码提供接口解释，不证明地图实际客户端的所有运行细节。

`A163_Debuff_DUr`（main/f114/f2，L88501–88514）无其他条件，只返回输入P×0.8；不会登记计时器。`Has_A_Item`的两条来源沿用已核规则：单位存在于`A111_113_A`值列表，或持有i310；不能把“没有A杖”简化成物品栏没有i310。B060的授予与到期属英雄技能生命周期，本批只确认读取其当时存在状态。

`SetPhyDamagePoint`（main/f7/f30，L51941–51970）直接调用`UnitDamagePoint`，传`delay=0,radius=460,attack=false,ranged=false,ATTACK_TYPE_HERO,DAMAGE_TYPE_NORMAL,WEAPON_TYPE_WHOKNOWS`。圆心是T位置，伤害来源是S。原生范围命中的目标筛选和边缘判定另见边界；P是传入金额，不是最终扣血。

## 3. 细雪：施法生效后读取当前魔法

### 入口和过滤

1. `main/f291/f35`（L179727–179797）为Player(0、1、2、3、11)登记`EVENT_PLAYER_UNIT_SPELL_EFFECT`并调用`AnySkillStart`。这是**技能生效事件**，不是玩家下达施法命令、SPELL_FINISH或读条开始事件。
2. `AnySkillStart`（main/f291/f14）的局部入口先可能为变身技能执行`Skill_BS_Still`。该前段`Player(11)`判断只控制这项前置处理，**不是把Player(11)统一排除出细雪入口**。随后，施法者满足`IsTemp`，或技能ID为T033/A040/A070/A210，直接return；否则调用`Item_Skill_Action`。L169999–170072，关键过滤L170040–170066。
3. `Item_Skill_Action`（main/f285/f16）重新读取施法者C、技能ID；依次`IsWorker(C)`、`IsBOX(C)`、`IsUseless(abilityId)`，任一真即返回。L146490–146512。这是本体资格，不做临时来源归属映射，不把C替换为Tower_ALL中的塔。
4. 若C有B083至B088任意一个能力，先调用一次`A084_Action(C)`；随后才查i134，再抽细雪概率，成功调用`i134_Skill()`。L146514–146582。之后的其他装备与英雄响应不属于本页；它们不能被提前到细雪取值之前。

`IsWorker/IsBOX/IsTemp`都按**单位类型ID列表**匹配，不按名称或模型判断。列表已从初始化字节码提取到机器表：工人为w001、g002–g018；箱子为w000、g200–g202；临时单位名单57项。`IsUseless`按以下30项**技能ID**排除，不是按技能冷却、耗蓝或主动/被动标签推断：

```text
A000 A075 A083 A164 I001 I002 I167 I168 I204 I205
I206 I207 I210 I211 I219 I220 I233 I243 I245 I248
I266 I267 I274 N000 T329 A226 A227 A228 A229 I270
```

名单字节码初始化L50036–50128；判定main/f7/f16，L51305–51331。工人/箱子初始化L50238–50334，判定main/f7/f49–f50，L52611–52673；临时单位名单初始化L49860–50034、判定main/f7/f15，L51273–51303。名单与四个早退技能的集合不能混为同一层：原图先做AnySkillStart前段，再过滤，随后才进入物品分派。

### 前置回蓝会改变细雪输入

以下保留原调用证据；后续[Q41精气光环](skill-essence-aura-proc.md)已确认Web触发率为准确30%，在同一调用点采用`uniformInteger(1,100)<=30`，回蓝比例与先后顺序不变。

为闭合读取时点，本轮核完`A084_Action`（main/f73/f0，L76378–76516）在此处的直接效果：

- 先抽`GetRandomInt(0,10)`；结果>3立即返回，不回蓝。
- 否则从B088到B083按优先级取第一个存在者，对应最大魔法的30%、25%、20%、15%、10%、5%；没有任何一个时比例0。
- `TxShow==true`时登记1秒回蓝特效，然后调用`SetUnitState(C,MANA,currentMana+maxMana*ratio)`。

外层只在至少有一个对应能力时调用，因此没有这些能力就不消耗这次回蓝随机数。该随机调用在细雪随机调用之前。后续[精气光环效果基准](skill-essence-aura-effect.md)已明确本次回蓝立即裁剪到0至最大魔法；原客户端裁剪仍未实测。**细雪读取的是该写入之后实际可读到的当前魔法**，不能直接用未裁剪的请求值或施法前最大魔法替代。A084另一攻击入口已在上述独立调查中核对，其门槛不能套用本处的前置Buff检查；自动Buff生命周期已在上述效果基准定义，完整幻象复制和换皮资源合成仍另核。

### 概率与技能体

`i134_Get_probability`（main/f240/f2，L127125–127151）原版返回`GetRandomInt(0,100)<50`，r=49成功、50失败。Web Q29改为精确50%，其他过滤与抽样顺序保留。

`i134_Skill`（main/f240/f1，L127051–127123；阅读稿L80551–80593）不接收单位参数，自行取`C=GetTriggerUnit()`：

```text
M = GetUnitState(C,UNIT_STATE_MANA)
P = M/1.5   // 原图
P = M*0.67  // Web Q29；替代上一行，不是再乘一次
if P <= 0: return
UnitDamagePoint(C,0,900,GetUnitX(C),GetUnitY(C),P,
                false,false,NORMAL,MAGIC,WHOKNOWS)
if TxShow==true:
    CreateEffAtLoc("Frost_Nova_1.mdx",GetUnitLoc(C),0.5,2)

```

读魔法和非正早退L127083–127092；范围包L127094–127110；特效L127111–127123。它不消耗这份魔法、不根据施法目标选圆心、不读取最大魔法、不取整，也不创建临时伤害来源。范围以施法者当前位置为圆心，半径900。该函数自己的伤害与特效都在成功抽样后执行；M≤0时本次概率已经抽过，但不会造伤害或特效。

## 4. 后续伤害与必要回调

居合提交HERO/NORMAL类型，细雪提交NORMAL/MAGIC类型；两者`attack=false,ranged=false`。它们进入独立伤害事件，不是直接改写触发攻击或触发技能的伤害；局部公式不能当作最终扣血。若仍满足After装备条件，各自能获得已核的村正×1.25、竹光×1.32，后面还有其他被动、模式和目标修正。普通攻击标记不能因装备文案写了“攻击触发”而被错误设为true。

这两个效果没有自己的持续伤害计时器、内置冷却或叠层状态。0.5秒是特效清理时间，居合特效缩放3.6、细雪缩放2，均由`TxShow==true`控制；关特效不取消伤害。沿用已核的`CreateEffAtLoc`与`Eff_time_end`（main/f7/f25/f26，L51661–51752）：非周期计时器到期后销毁特效和计时器，清除对应数组槽，没有战斗伤害写入。前置A084的1秒特效使用同一个清理回调。Web计时排序沿用B05。

原生范围包没有Lua侧逐单位筛选回调。本页已证明两次`UnitDamagePoint`的全部实参；**尚未证明原生函数针对友军、无敌、飞行、建筑、魔免及碰撞边缘的完整筛选和delay=0提交细节**。图鉴写细雪针对周围敌人；没有native证据前不把未见脚本过滤擅自判为友伤冲突，也不宣称范围技能的全部目标行为已闭合。按Q24处理这项底层缺口时，应单列Web规则并保留来源边界。
