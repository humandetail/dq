## Web 生命周期（Q24）

1. 每个适格原生英雄的实际挂载实例分别登记表中一份固定资源。多个获准共存的实例累加。别名重复已反映在每件数值里，例如一件血精石贡献 1000 固定生命。持有资格、载体和互斥沿用 L01。挂载在 PICKUP 前生效，移出在 DROP 前撤回。换槽及满包交付失败没有贡献变化。嵌套合成按各次实质移出及交付的次序更新，失败时保留已提交事件的结果。读档从恢复的挂载实例重建贡献，资源及偏移直接取存档。[物品生命周期 L01、L07](item-lifecycle.md)
2. 资源上限由基础、三围派生、装备固定、其他有效来源和脚本直接偏移合成，最后取生命下限 1、魔法下限 0。挂载变化按实际最大值增量移动当前值，存活生命裁剪到 `[1,新上限]`，魔法裁剪到 `[0,新上限]`，已死亡生命保持 0。一次挂载事务把静态装备与同批变动的三围派生各加一次，再按该次实际最大值变化调整当前值。回复继续按既有时间边界结算，固定值只改变上限。[英雄属性与资源](hero-attribute-interface.md) · [昼夜与回复](night-state-and-regeneration.md)
3. PICKUP、击杀和 DROP 中的成长充能依原脚本直接写上限，保留当时当前绝对值后裁剪。玲珑心带 5 魔能、+70 智力时，挂载先给最大和当前魔法各加 `550 + 70×12 = 1390`，再由 PICKUP 增加 `5×3 = 15` 最大魔法。移出时先撤销本件静态资源及三围，再用移出时的充能扣直接上限。生命类相同，每点血能按脚本加 4 生命上限。[三围与成长交接](item-attributes.md) · [PICKUP](../../reference/map-6.25/main.disasm#L144824) · [击杀](../../reference/map-6.25/main.disasm#L146114) · [DROP](../../reference/map-6.25/main.disasm#L147316)

三个 Web 资源探针覆盖固定资源与派生及直接写入的先后、单件重复别名和死亡生命、以及低值移除裁剪。匹配版本客户端的挂载／移出当前值调整仍可实测。该批 Web 规则与采用数值已确定。[复查脚本（`--check`）](../../tools/audit-item-resources.py)
