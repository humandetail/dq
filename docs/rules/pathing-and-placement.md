## 统一坐标与静态查询

Web使用源世界坐标，x向东、y向北。路径格32世界单位；范围为`[-6144,6144)²`。先拒绝非有限数或越界坐标，再取：

```text
ix = floor((x + 6144) / 32)
iy = floor((y + 6144) / 32)
fileByteOffset = 16 + iy * 384 + ix
cellCenter = (-6144 + 32*ix + 16, -6144 + 32*iy + 16)
```

不能向零截断负坐标，不能把图像显示时的y翻转用于模拟索引。`(-6144,-6144)`属(0,0)，`(0,0)`属(192,192)，`(6144,0)`越界。格子包含下边界、不包含上边界。

0x02、0x04、0x08分别用于禁止步行、禁止飞行、禁止建造。32单位格与位解释参考[Wurst路径格工具](https://github.com/wurstscript/WurstStdlib2/blob/master/wurst/math/PathingGrid.wurst)和[Warsmash路径数据实现](https://github.com/Retera/WarsmashModEngine/blob/f9e0aeed4be372d6016519d0e97b384aa873f374/core/src/com/etheller/warsmash/viewer5/handlers/w3x/environment/PathingGrid.java#L374)；它们是格式/独立实现依据，不是本图客户端证明。尤其后者对0x40自身标注不确定，本页不将0x40/0x80猜成额外可游泳区域、视野或坡度机制。本次实际地形按WPM的上述三位处理；foot/horse/hover/amph均用步行层，fly用飞行层，没有隐式地形加速/坡度成本。未来若引入本范围没有的纯水上单位，需要独立水域规则。

用于原脚本`IsTerrainPathable(...,BUILDABILITY)`的局部替代：查询点所在格的**WPM与已明确的路径贴图覆盖**是否有0x08，真表示不能建造；越界为真。普通移动单位的圆形碰撞不写进这个“地表点查询”。因此点检查通过不等于完整可放置。

## 碰撞与占地

以下几何形状与生命周期为Q24选择：

1. `collision`按世界单位圆半径使用，保留原值，视觉模型/`modelScale`/选择圈不放大它。动态圆相切允许，距离平方严格小于`(r1+r2)²`才重叠。
2. 完整静态许可检查圆盘与路径格内部有正面积相交的全部格子；所有格子须在界内并没有所需禁止位。不是只测圆心，也不是只测四个角。整个圆盘不能接触地图被排除的最大边界。
3. 地面与飞行是两个动态碰撞层。同层存在、存活、未隐藏且开启碰撞的实体阻挡；不同层不互挡。`Aloc`单位与`SetUnitPathing(false)`实体不提供动态圆阻挡。无敌不等于无碰撞。物品、尸体、纯特效及已核空路径摆件不占这两层。
4. 施工目标从S02提交起就占地；完成不再添加第二份。取消/死亡/删除释放其贡献一次。暂停施工不释放占地。一般塔是地面占位，飞行工人/飞行怪不会因为地面塔圆盘而被挤开，但塔仍须满足建造地表许可。
5. 本批86个缺少`pathTex`的卡片目标，Web明确不加额外贴图占用，圆半径72仍保留。n156的`4x4SimpleSolid.tga`和动态LTlt的`4x4Default.tga`，本页局部选择**4×4全格0x0A**，即阻地面行走/建造、不阻飞行。每像素32，锚定最近32网格顶点，覆盖`ix−2…ix+1,iy−2…iy+1`。这两张对称图样不随视觉缩放或朝向变化，不声称等同未取得的原像素。LTlt删除时释放这16格；完整树技能何时创建/删除仍由其已核脚本提供。
6. 覆盖按“实体、格子、位”的引用计数保留，与不可变WPM按位OR。移除一个覆盖不能清掉另一实体或原地形同一禁止位。实体自身移动/迁移的许可检查排除自己的圆与贴图贡献，仍保留同格其他实体及WPM。动态圆保持精确形状，不粗暴烘焙成一格一个单位。新障碍物若覆盖已有单位，不自动推开或删除单位；其后移动仍需合法扫掠，无路则等待障碍移除。

## 普通移动与阻塞

这是确定性的Web寻路，不照搬另一引擎并称其为原版。普通MOVE从当前位置到原脚本给出的精确目标，不把怪物路线替换成单环：

- 采用32网格的八邻接A*，扩展顺序E/N/W/S/NE/NW/SW/SE；直步成本10、斜步14，启发式`10*max(dx,dy)+4*min(dx,dy)`。队列依次按`f,h,iy*384+ix`升序；只有严格更小g才替换父节点。对角移动要求两侧直邻都可通行，不能穿障碍角。
- 单位仍处于连续世界坐标。精确起点/终点以可碰撞检验通过的线段连接所在格及八邻格的中心；连接成本按世界距离/32×10，等距按行优先索引。虚拟起终点也属于同一次最短路搜索；启发式取各合法终点连接格的octile成本加该格至精确终点成本的最小值。终点无合法连接时命令保留但等待，不能悄悄把“到附近”当到达原路点。实际走线必须通过圆盘扫掠检查；上述图搜索成本仅选路，移动距离仍用真实欧氏长度。
- 动态碰撞也进入当前寻路检查。每个移动tick重新核下一段；受阻就重新寻路，无路则停留并在下一tick重试。不得因卡住自动死亡、移除、扣容怪、传送或选择下一路点。塔放置没有新增“全图路线必须仍连通”的隐藏预检。
- Q24选择每`1/32`战斗秒一个移动tick，同tick单位按稳定创建序号处理。使用当前已解析的移动速度`v`，每tick最多走`v/32`世界单位；暂停/控制导致不能移动时不积攒距离。此接口不额外设置速度上限，也不猜未解析的技能移速。普通转向立即改变行进方向、不额外等待；源`turnRate`保留为证据，未声称已换算其原生时间单位。
- 每条实际线段对禁止地形格、路径贴图矩形与同层动态圆做扫掠，不能因速度大或4倍速穿过去。线段到动态圆心的最近距离若小于两半径之和即阻挡；矩形采用圆盘扫掠等价的线段到矩形最短距离检验。无路时保持旧位置；不取穿透后的终点再修正。
- `EXSetUnitMoveType(1)`在本适配中明确定为普通MOVE不可移动，`2`为地面步行；这与本图完成/深渊切换调用意图一致，但数字枚举未由匹配客户端证明。[YDWE实现](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Plugin/Warcraft3/yd_jass_api/UnitState.cpp)只是写底层字段，不足以证明全部枚举。显式位置迁移仍可移动不可普通行走的塔；其他数字不能猜。`SetUnitPathing(false)`保留世界边界但绕过地形及动态碰撞，不能据此绕过卡片放置检查。

路径/障碍改变不调用路线随机数。移动tick是B05普通周期事件，每轮重入队；不会压过同刻先入队的施工、取消或状态事件。已排队事件之间的动作仍遵守既定顺序。

## 卡片放置与失败事务

卡片预览锚点取最近32世界单位网格顶点，恰好一半时向坐标增大方向取整：`-6144+32*floor((coordinate+6144)/32+0.5)`。仅卡片预览/放置这样吸附，普通移动与原脚本坐标不一起吸附。

保留[OrderBuildEvent，main/f291/f19，B172980–173117](../../reference/map-6.25/main.disasm#L172980)的原顺序：施令者为工人/能量圈、852008…852013对应槽0…5，先查**原始点命令坐标**，再用卡片当前HP做人口预检。原失败的`stop→move(当前坐标)`及提示仍执行；其未检查原生命令返回值不等于原生已经保证不耗卡。

Web后续准入采用以下原子过程：

1. 使用能力显式范围100，按施令者中心到吸附锚点的距离判断。可移动施令者先接近至≤100；距离外的不可移动能量圈拒绝。接近过程不扣卡、不留人口、不占地。接近位置候选为合法可达格中心中距离锚点≤100者，选实际A*总代价最小者，并按行优先索引破同值；已经在范围内则不用先走到某格中心。
2. 到提交点重新检查同一卡片实例/槽归属和充能、原购买/使用前置、原地表及当前HP人口预检、目标fused人口检查、范围，以及吸附后整个圆盘/贴图的地表与动态地面占用。不存在“预览绿色就无需再核”。不将缺失价格或未知许可字段当0/通过。
3. 只有全部通过，才按S02一次提交一只施工实例、占地、人口和一次充能扣减；1秒后完成、资格抽样与S04返卡保持原规格。任何提交前失败/命令取消/卡片移走，都不部分创建、不扣充能、不留幽灵占位、不消费完成资格随机数，也不退之前已经付过的购卡费用。
4. 同刻两个命令读最新状态：先提交者占同一地点，后者失败保卡。施工失败后释放占用与人口仅一次；读档恢复实例和事件身份，不能重新扣费或添加第二份覆盖。

完成、类型与所有者变更提交后，通知[资格生命周期](qualification-lifecycle.md)立即重算；施工对象不提前作为Max资格源。升级中若仍保留原类型，原类型资格保持到转换实际提交。本页不另外改升级价格或技能效果。

## W018移塔与核心刷怪创建

完整W018 [main/f296/f19，B190092–190222](../../reference/map-6.25/main.disasm#L190092)先要求技能ID、同所有者、目标不是能量圈，再取工人位置。该点地表不可建造时才调用`GetTempUnitLoc(point,250)`；再次不可建造则返回并安排原0.1秒冷却清零。该helper [main/f7/f18，B51369–51424](../../reference/map-6.25/main.disasm#L51369)固定按0°、30°…360°尝试圆周，首个地表合格点返回；深渊第一次尝试即退出；全部失败返回360°点。它不检查动态圆，不搜索圆内，也不按距离排序。

到`SetUnitPositionLoc`后的未知原生挤位，局部Q24选择为：先尝试脚本请求的精确坐标；若完整占用许可失败，再按距该请求点平方距离、行优先格索引的顺序试**250范围内的格中心**，忽略被移动塔自身旧占用。成功时旧占用释放与新占用安装原子完成；全失败留在旧位置。这里第二层250搜索是Web选择，不是原helper。原函数随后仍播放CharmTarget特效，没有因为原生挤位失败而写过新的冷却清零分支，不能擅自补此分支。

核心波次原`CreateUnitAtLoc`仍先尝试原出怪坐标；静态非法时选择全图合法格中心中距离平方最小者，行优先破同值。**核心波次创建不因同层移动单位暂时拥挤而少刷怪**，允许出生时临时重叠、不重新抽怪或消费选路RNG。重叠单位移动时可离开初始重叠：对每个初始重叠实体，该步距离必须单调不减且终点严格增大（以其他单位本次已提交位置计算，`dot(start−other,delta)≥0`且终点距离更大）；完全分离后删除该特例，恢复普通碰撞。没有静态合法位置属于内容错误，不能默默删掉该批次。这个特例不适用玩家卡片，不给所有原生召唤技能统一放宽失败规则。

## 入区边界与路线事件

[Get_region_by_rect，B197281–197302](../../reference/map-6.25/main.disasm#L197281)只做CreateRegion/RegionAddRect；[登记main/f306/f34，B200495–200554](../../reference/map-6.25/main.disasm#L200495)依路点0→23登记ENTER，没有exit路线动作。[条件及路线函数B200253–200493](../../reference/map-6.25/main.disasm#L200253)仍只接受owner11，排除临时单位/mb01，活动怪转交专属入口；**未额外检查进入区域是否等于user data中的当前目标**，不能新增该门槛。

Q24选择路点矩形为**闭矩形**，只看单位中心，不加碰撞半径；与网格的半开边界分别定义。每单位保存每区域inside状态：outside→inside发一次，停在里面不重复，离开后才可再次进入。

普通移动对整条实际线段做slab相交，不只测终点。处理最早入区交点；相同交点按原登记0→23顺序。提交交点位置后，在本次移动操作内同步压入`enteringUnit/triggeringRegion`上下文并调用原过滤/路由，再恢复外层上下文；新move命令替换旧目标，剩余本tick距离按新目标重规划。不可先走完整条旧线再补过期入区。闭边界擦角也算一次进入；离开立即更新membership，不在边线上反复触发。

瞬间迁移只比较旧/新坐标membership，不触发中间经过的矩形。核心刷怪创建则在原创建调用方完成user data、move和登记初始化后，将首次入区通知放到同刻队尾，避免尚未初始化便解析路线数据。删除清membership，不伪造enter；存档恢复membership，不重放已执行入区。以上是本空间接口的Q24事件约定，沿用B05队列和嵌套上下文原则，不将普通移动回调伪称零秒timer。

源路由进入节点后仍排除上一节点，保留邻接原顺序；个人模式多候选才调用原`GetRandomInt(1,n)`，唯一候选不抽。原move命令返回值被丢弃，user data/`mon_next_pos_index`仍更新，所以原生命令拒绝不能被改写为自动回滚路线。路径阻塞不会自行制造下一次enter。

## 验证与边界

机器表包含所有87卡片目标与92个相关移动对象的来源行、关键字节码、额外MPQ证据和几何/事务验收向量。已逐值逐行复核2009个选定对象字段、9个完整函数与4段有界切片共517条指令，以及16个本地链接；原37个快照文件哈希及新增6个证据文件哈希均一致。用真实WPM检查52条有向邻接及四个出怪点至首路点，共56条路径均可达；这是半径1飞行层的静态网格可达性检查，没有运行完整虚拟起终点/动态A*，不能据此称所有动态拥堵组合无死锁。
