# 武器伤害字段与共享攻击接口

本页保留完整来源调查，并按 Q24 采纳共享基准 **`weapon-attribute-interface-v1`**（W01–W03）。Q46 已确认：仅 A069 长大每次学习的 +90 作为可被百分比攻击光环放大的专用贡献。原生字段事实、未证明的引擎重算和选定 Web 规则分别列出；不是原 Warcraft 客户端实测。

[固定版本YDWE扩展实现](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Plugin/Warcraft3/yd_jass_api/UnitState.cpp)明确给出第一武器状态编号：16骰子数量、17面数、18基础攻击、19附加攻击、20最小攻击、21最大攻击。对应基础/附加内存字段为int32；getter对20计算 `base+bonus+dice`，对21计算 `base+bonus+dice*sides`。18/19的setter将传入real转为整数后直接写字段，不在这个扩展函数里解释各技能贡献。

该源码支持字段编号与局部运算，不证明本图加载的扩展二进制完全相同，也没有展示魔兽引擎何时将主属性、科技、物品和百分比光环写回这些字段。尤其不能仅凭“bonus”英文名，就宣称任何写S19的能力永远不受其他加成影响。

当前关联规则：

- [属性接口](hero-attribute-interface.md)规定主属性每点1.4攻击贡献；[光环](hero-aura-family.md)规定百分比基数含主属性与本次骰子，排除固定绿字，N016保持同一口径。
- [潮汐使者](skill-jingu-and-tidebringer.md)在自己的原位置读取S18+S19，学习/攻击/回充直接改S19。不能把它改成每次攻击的骰子结果或最终伤害。
- 原 A069 学习直接 S19+=90，A235 按捕获值增加/定时减少 S19。Q46 仅替换 A069 的这一写法为专用可放大贡献 G；A235 按本页通用 J19 固定通道，保留逐次 getter/setter 和原捕获量扣回。
- [原生暴击](native-critical-family.md)中的普通武器原始包R只生成一次；本页给出 R 的贡献接合及独立 API 整数视图；暴击/伤害链仍按既有次序处理 R。

## 一手资料能证明到哪一层

已重新下载固定提交的 UnitState.cpp，SHA256 为 `cce69daa88a376177c31dacf52901e30f9bb37fd28cfb3abfbabe112a3d139a8`，与此前攻速调查一致。以下为**原文件物理行号**，不使用浏览器抽取后压缩的行号：

| 证据 | 物理行 | 可得结论 |
|---|---|---|
| 枚举与成员 | 18–23、75–85 | S16–19分别对应两个骰子参数、base、bonus；成员int32 |
| getter | 258–269、289–294 | 直接读S16–19；S20/21按上述代数和返回，没有在这里掷骰或重算光环 |
| setter | 501–512 | 对S16–19执行 `(uint32_t)jass::from_real(*value_ptr)` 后赋给相应int32成员；没有恢复模板或保存某个技能的来源标签 |
| getter最终返回 | 361 | `jass::to_real((float)retval)`，内部整数先转float，再跨JASS返回；大整数并非原值返回 |
| 无效句柄/属性指针 | 200–204、242–245 | getter返回0；setter相应分支返回，不写其他单位 |

正的可表示实数转整数会截断小数。**负数/溢出不能仅凭这句 C++ 强转宣称原版一定环绕**：输入先经过JASS real桥接，源码又先转uint32再写int32；缺匹配二进制和编译行为证明。地图确有可能减出负数的原逻辑，例如A235复用槽扣回，不能用“不会出现”规避定义。

固定提交 [jass.h L64–65](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Core/ydwar3/warcraft3/jass.h#L64)声明实数转接为float；[jassbind.cpp L78–86](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Plugin/Warcraft3/yd_lua_engine/lua_engine/jassbind.cpp#L78)也先read<float>入参、将from_real结果推回Lua。因而**内部int32与Lua看到的数必须分开**。按选定 binary32 最近偶数舍入，内部16777217返回16777216，16777219返回16777220；2147483647返回2147483648，但再将该返回值写回应被下述有符号域检查拒绝，不凭空认为每个合法内部整数都可经real精确往返。该舍入模式为明确Web选择，未证明本图线程FPU状态。

[暴雪 Hero Basics](https://classic.battle.net/war3/basics/heroes.shtml)证明主属性提供攻击，但没有给出S18/S19分配或绿色数值重算函数；地图将系数改为1.4。[官方光环/物品说明](https://classic.battle.net/war3/basics/heroitemspermanent.shtml)支持固定攻击、百分比光环是不同来源，也没有公开它们的内存映射。故“bonus”这个英文名本身不是“S19所有内容永远不能参与百分比”的证据。

另查了[独立引擎作者的 CUnitAttack](https://github.com/Retera/WarsmashModEngine/blob/f9e0aeed4be372d6016519d0e97b384aa873f374/core/src/com/etheller/warsmash/viewer5/handlers/w3x/simulation/combat/attacks/CUnitAttack.java#L127)。它区分永久/临时主属性，百分比用骰子均值并作整数转换；`roll`才逐骰取数。**这是该引擎的实现，不是原Warcraft实测**。它与已选“本次武器骰子参与百分比”的Web口径有差别，不能直接导入；它只说明“base/bonus两个名称”不足以推导唯一公式。没有找到匹配本图运行版本、能证明整套重算的公开一手实现。

## 已选 Web 接合：weapon-attribute-interface-v1

W01–W03 均按 Q24 采纳。它们补齐未能匹配原客户端的分量与转换细节，沿用主属性每点1.4、实际骰子参与百分比、不同光环组相加等既有选择；并不将独立引擎的公式冒充本图事实。

**W01：getter 与普通武器原始包分离。** 维护模板/科技基础 B、主属性 H=有效主属性×1.4、有效固定攻击 F、同 Buff 合并后的百分比 P、脚本偏移 J18/J19，以及 Q46 专用的 A069 累积贡献 G。令 **`X=B+H+J18+G`**，`μ=n*(s+1)/2`，n/s 为当前武器骰子数/面数。

- 内部视图：`I18=checked_int32(trunc(X))`，`I19=checked_int32(trunc(F+P*(X+μ)+J19))`。
- 公开读取：`Get18=f32(I18)`，`Get19=f32(I19)`；`Get20=f32(checked_int32(I18+I19+n))`，`Get21=f32(checked_int32(I18+I19+n*s))`。S16/17 返回当前合法整数骰子参数的 f32 值；本图没有其脚本写入口。
- S20/21 必须先用内部整数槽求和，不能相加已经舍入的公开 getter。例如 I18=16777217、I19=1、n=0，Get20=16777218；`f32(Get18+Get19)` 错得16777216。所有 getter 均不耗 RNG。
- 普通武器本次骰子和 D 只生成一次，原始金额 **`R=(X+D)*(1+P)+F+J19`**，使用贡献通道而非整数 API 视图。μ 仅用于确定地表示 API 中的百分比贡献，不改变普通攻击使用本次骰子的规则。最终暴击、命中和减免继续交给既有接口。

**W02：显式 setter 保留绝对写入语义。** `T(v)=checked_int32(trunc(f32(v)))`。`Set18(v)` 令 **`J18=T(v)−(B+H+G)`**；`Set19(v)` 令 **`J19=T(v)−[F+P*(X+μ)]`**。逻辑派生值立即更新，当前合法读数等于目标整数再经 f32 返回。之后 B/H/F/P/G 变化保留 J18/J19；例如以后又一次 A069 学习仍 +90，但显式 Set18 本身可以改变当前总基础视图，不会因 G 是永久贡献就忽略覆盖写入。

不能仅给偏移加“目标整数−旧整数 getter”，也不能将减旧/加新合并成净量。原脚本在原位置每次读取/写入，timer 仍减捕获的原数量，不做无损来源回滚。例：字段100，加捕获13.6后得到113，之后减原13.6得到99；A042可能产生小数捕获量。不得擅改为减实际写入的13来恢复100。

本局部接口的贡献求和与 residual 使用精确数值表达，以保证跨零写入的读回不受浮点抵消影响；参考实现把输入数值按其实际值转为有理数。它不会重新舍入进入接口前的 Lua 算术，也不规定后续整条伤害链都使用有理数。R 退出此接口时转为宿主数值，只有上述 native 边界执行 binary32/int32 量化。保存这些通道（或精度等价的表达）和来源状态，读档重建视图，不重放 setter、学习或物品事件；新对象不会自动克隆源通道，实际复制仍由原代码的 getter/setter 发生。

**W03：转换和错误边界。** f32 为 IEEE754 binary32 最近偶数舍入。setter 先 f32、再向0截断、检查有符号 int32 范围，成功才改一个 residual。NaN、无穷或范围外请求抛 `WeaponFieldRangeError`，该写入不改状态；不静默饱和或环绕。无效/已删除句柄优先读0、写无操作；死亡但句柄存在不等于无效。原 SetUnitState 是 void，不额外发明成功布尔返回。

读取中内部视图或 S20/21 整数结果超出 int32，抛同名集成错误，不返回伪造0或环绕值；当前脚本回调停止，先前已发生的真实副作用不回滚。属性/光环变化及普通原始包使用独立贡献通道，API 读数失败不把攻击包改成错误整数。S20/21 setter 不在本图调用范围，不定义反向求解。普通伤害的小数、有效属性×1.4和百分比小数不因 API 视图而被截断。

大整数例：内部16777217返回16777216，16777219返回16777220；合法内部 int32 最大值2147483647返回2147483648，再将此返回值写回会因 int32 越界被拒绝。`X=16777217、P=F=J19=D=0` 时，Get18=16777216，而 R=16777217。两条通道不得混用。
