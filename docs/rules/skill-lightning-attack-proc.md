## 明确概率差异

原函数 `N058_60_Get_probability` 在 [Lua L71765–71775](../../reference/map-6.25/main.readable.lua#L71765)，完整字节码为 **`main/f177/f1` L113437–113464，共 10 条指令**：

```text
roll = GetRandomInt(0, 100)  // 两端均包含，共101个整数
return roll < 20
```

[字节码 L113453–113462](../../reference/map-6.25/main.disasm#L113453) 明确加载 0、100 和阈值 20；`lt 1 r0 k3` 根据结果设置返回布尔值。返回 true 的结果为 **0–19**，false 为 **20–100**。因此原脚本为 **20/101 ≈ 19.801980%**；图鉴和实际 Ubertip 都写 **20%**。

三个形态共用此 helper；它没有技能等级、Game_Mode、幻象、A 杖或其他概率修正分支。**Q37 已选准确20/100**：Web 在原 helper 调用位置抽一次均匀整数1–100，以 `roll<=20` 判定。1–20成功，21–100失败；原 `GetRandomInt(0,100)<20` 仅作为来源对照。

原准入顺序保持：先检查攻击标记，再抽一次，然后查实际伤害源的能力；三个ID都没有时仍按这一位置消费随机数。它与前段雷霆战斧各自抽样，不共享Q36的结果，也不把两次抽样提前合并。

## 实际入口与公共门槛

入口为 `anyUnitDamaged` / `main/f291/f1` 的 **PC1804–1838**，[字节码 L164396–164431](../../reference/map-6.25/main.disasm#L164396)，对应 [Lua L112210–112246](../../reference/map-6.25/main.readable.lua#L112210)：

1. `EXGetEventDamageData(2)!=0` 才继续，即攻击标记的伤害事件；攻击起手本身不是此入口。
2. **先抽一次** `N058_60_Get_probability()`；失败直接跳到 PC1839，不查询能力 ID。
3. 成功后按 N058→N059→N060 检查**实际来源 S（r0）**是否有正等级；任一成立即短路，只调用一次 `N058_60_Action()`。不改用归属塔 O（r2），也不为同时存在多个 ID 增加调用次数。
4. 三个 ID 全无的来源只要到达此处且 attack 非 0，也已经消耗此次随机数。本段排在 N054_57 的 PC1761–1803 之后，是**另一次独立抽样**；不共用 Q36 的结果、不删除前段原有抽样。

本段没有自己的非幻象检查、Game_Mode 限制、敌方所有者检查、耗蓝/冷却检查或修改后的事件伤害正值检查；原生目标/命令最终能否成功是效果层问题，不应反过来改变已核概率入口。

公共门槛沿用 [伤害主流程](damage-pipeline.md)，本批保存相应字节码片段：

| 公共分支 | 字节码位置 | 影响 |

| 实际来源 q039 跳到 PC3964 | PC98–105，[L162598–162605](../../reference/map-6.25/main.disasm#L162598) | 旁路包括本段在内的主体；并非立即 return |

初始 D==0 是一次检查；其他效果随后将 D 写成 0 不会自动增加全局早退。本页保留此前所有已核流程和回调顺序，不替换为“零伤害统一停特效”。
