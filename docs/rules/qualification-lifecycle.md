# 变强资格：前置塔与 B015 生命周期

本页为 `qualification-lifecycle-v1`，补齐 P001–P013 的原生前置条件与资格失效后的 Web 行为。保留图鉴及既有规则：取消地图等级限制，仍要求对应 Max 塔；主线/无尽的升级和拾取事件检查 B015，深渊按原分支豁免。对象与脚本证据见[机器表](qualification-lifecycle.json)，不把下列 Q24 选择标为原客户端实测。

13项实际 profile 的 `Requires` 分别指向这些单位，来源[能力提示 L16069 起](../../reference/map-6.25/units_campaignabilitystrings.txt#L16069)。它们全部为 AOae、一级、checkDep=1、Area=10、BuffID=B015、目标 `self,invulnerable,nonhero,hero`，无对应 w3a 增量。DataA/B没有显式值，不能把学习提示中残留的耐久光环移动/攻速加成当作这项资格的实际数值。`UnitMakeAbilityPermanent` 保留能力本身，不证明其前置永远满足。

完整建成处理 `main/f291/f7`，[L167771–167956](../../reference/map-6.25/main.disasm#L167771)，先登记 Tower_ALL、写 UserData，处理已有 T033/N032、英雄移动类型、stop 和回满魔法，之后才判断原生 HERO 或 n208。仅这些单位均匀抽一次1–13，加对应 P001–P013、设一级并设永久；普通塔不为资格抽样。入口本身没有“已分配则返回”的防重逻辑。正常建成事件与某些显式脚本调用使用同一 handler；保存恢复不得伪造第二次调用，但实际再次调用不能凭空去重。

业务 Lua 对 B015 的字面查询只有两处拾取门槛和一处升级门槛；没有字面上的“前置塔死亡后统一卸装备/降级”函数。这个检索结论不排除其他已核技能的通用 Buff 清除，不能当作所有动态调用不可达的证明。

完整升级处理 `main/f291/f18`，[L172901–172979](../../reference/map-6.25/main.disasm#L172901)，按顺序执行：

1. 若有 A225，先添加再移除 T299。
2. `Game_Mode!=2 && 当前等级>20 && B015<=0` 时，调用 `UnitStripHeroLevel(level-20)`，本地等级改成20。
3. 最后按本地等级调用 W019。资格丢失本身没有合成升级事件。

经验的剥级落点、逐级事件与丢弃本次越界进度继续采用[经验基准 X04](experience-sharing.md)。本页不重选经验表，也不擅自重置已学技能或永久属性。

拾取限定片段为 `main/f285/f10` PC268–422，[L144933–145100](../../reference/map-6.25/main.disasm#L144933)。仅非深渊、非工人/能量圈、物品等级>3且该实例不在 ignore_strong_item 时进入资格检查。熊灵伙伴且拾取物不是 A_ITEM_ID，查询 `Tower_ALL[伙伴.userData]` 的 B015；其他情况查询拾取者自己的 B015。不能把所有召唤物都豁免，也不能把神杖统一算作伙伴依附本体的分支。

不满足资格时执行源代码的提示、特定 i304/i282 字段处理及 `UnitRemoveItemSwapped`，然后返回。该 native 是从该单位移出物品，不等于销毁物品实例；具体物品生命周期仍沿对应交付/拾取规则。已经持有的装备没有因本次资格丢失自动重新触发这段函数。

## Q24 的局部 Web 定义

[暴雪法术说明](https://classic.battle.net/war3/basics/spellbasics.shtml)支持光环自身受益、同类不叠加及隐藏/隐身源不发射，但未证明这张地图的 `Requires` 何时重算、原生残留及永久能力失效顺序。没有匹配客户端，所以本页明确采用如下选择：

- **前置按当前所有物计算。** 对资格持有者所属玩家，至少有一个存在、存活、已完成建造/升级、非幻象、当前类型恰为所需 ID 的单位。卡片、尸体、施工中的目标塔、其他玩家的同盟塔不满足条件。若多个符合单位，只需任意一个仍在；不会消耗前置塔。单位隐藏不会使它从所有物计数消失。
- **资格是自身能力贡献。** 持有者必须存在、存活、未隐藏，持有启用的正等级 P001–P013，且其对应前置满足；仅给自身 B015。n208 可正常获得，不另加 HERO 限制。无敌/魔免允许；隐身、幻象、妖术和钻地暂停此光环贡献，普通眩晕、沉默、单位暂停不独立关闭被动。这是本资格的局部发射选择。
- **即时重算、零残留。** 相关单位建成、出售、死亡、移除、复活、归属或当前类型变化，以及资格能力/发射状态改变后，在状态提交点重算。无额外 timer 或随机数。升级过程中未改变当前类型时保持原类型计数；正式转换后按新类型计算。
- 多项有效资格只贡献一份 B015，不增加属性。独立脚本显式加入的外部贡献分别记来源，本资格重算不删除外部贡献。缺失 DataA/B在此 Web 适配中不授予额外移动或攻速。
- **失效只移除资格贡献。** 不直接降级、清经验或卸下既有装备；后续真实升级/拾取事件按原流程检查。30级已满级者不会因收到0经验而合成一次升级事件。失去后重新取得资格不恢复已被 X04 丢弃的经验。
- 普通魔法驱散不关闭此通用光环。显式移除 B015 先执行，再按仍有效的来源重算；来源已失效则保持移除。清除其他控制效果不能顺带清除资格。
- 同一逻辑单位死亡复活或换皮保留永久资格 ID，发射资格重新判定，不重新抽签。新建逻辑实体是否继承须由实际转换流程明确，不能由本页隐式复制。存档保存已选 ID、单位状态和事件提交位置，重建衍生 B015 时不重放抽签或升级。

上述变化按 B05 的同刻顺序观察：先出售前置塔再拾取，拾取看到新资格；先拾取成功再出售，原持有物不自动移出。既有深渊门槛豁免保持，不能因 Web 重算资格就把深渊也加上20级限制。

## 验收与范围

| 场景 | Web 结果 |
| --- | --- |
| 已分配 P001，仅持有龙卵卡，或 n189 尚未建成 | 没有本资格的 B015 |
| 一个 n189 建成；之后又建成一个 | 获得一份 B015；不叠加 |
| 两个 n189 出售一个；再出售最后一个 | 前一次保持，后一次立即失去贡献 |
| 前置 n189 变更所有者 | 原玩家重算失效，新玩家有匹配资格者可生效 |
| 25级英雄持高级装备，前置塔出售 | 当下等级/经验/装备保持；之后跨26级时按原升级事件剥至20 |
| 同状态但 Game_Mode=2 | 升级与拾取按原深渊豁免，不由本页增加门槛 |
| 在原资格失效后把装备交出再拾回 | 新拾取重新检查资格，不因曾持有而豁免 |
| 已分配英雄死亡复活 | 保留资格ID，不消费新的1–13随机数；复活后重算 |

`tools/audit-qualification.py` 对334条源指令建立证据；完整建成 handler 的39个分类/随机结果、升级 handler 的60个模式/等级/Buff/A225组合验证通过，13份对象与前置映射一致。字节码探针使用原生替身，验证源分支和调用顺序，不声称运行过客户端。
