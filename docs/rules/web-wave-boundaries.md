# Web 波次末批边界

按已确认的 [web-baseline-v1 / B05](web-baseline.md#b05同一时刻的计时事件按入队顺序执行)，**主线 1–54 波的 40 秒端点不再刷怪；无尽普通波的 14 秒端点也不刷怪，每入口固定 7 只。** 这是“原图登记顺序 + Web 同刻队列规则”的推导，不是原客户端实测结论。[原始波次证据](waves-and-modes.md)和 [waves-data.json](waves-data.json) 的原生上下界保持不变。

本页的“主线 1–54 波”包括每五波的主线 Boss 波，只排除第 55 波肉山。计数按一个在完整刷怪窗口内始终有效的入口计算，只统计波次刷怪器产生的基础怪物，不包括福利怪、技能召唤物、无尽 Boss 或深渊。机器表 [web-wave-boundaries.json](web-wave-boundaries.json) 给出全部 54 波、逐项来源行和无尽普通波。

## B05 如何决定同刻末批

以本波刷怪设置开始为 `t=0`。停止事件 S 在这次调用中先入队，周期事件随后登记，首批直接执行。以后每次周期触发 P 执行后，以新的入队序号登记下一次 P。若某次 P 恰好到期于窗口终点，它的入队一定晚于 S；B05 先执行 S，使尚未执行的 P 失效。停止回调直接调用 `StopMon`，这里没有“先到期、再通过零秒回调延后停止”的中间步骤。

因此有效生成时刻为：

```text
k * interval < window，k 为从 0 开始的整数
每入口批数 = ceil(window / interval)
           = (windowUs + intervalUs - 1) // intervalUs
```

`k=0` 是直接生成的首批。所有时间先按 B05 转为整数微秒；本页使用的间隔均可精确转换，避免累加 0.7、0.8 等二进制浮点数时错判边界。若窗口不能整除间隔，本来就没有端点触发；公式仍包含首批，最后一批严格早于停止。

两个时序例子（省略不影响相对顺序的其他事件；S/P 的序号是局部示意）：

| 相对时间 | 主线第 5 波，间隔 5 秒 |
|---|---|
| 0 | 先登记 S@40，再登记 P1@5，直接生成第 1 只 |
| 5、10、15、20、25、30 | 每次生成一只，并用新序号登记下一次 P |
| 35 | 生成第 8 只，再登记 P8@40；它的序号晚于 S |
| 40 | S 先禁用并销毁触发器；P8 被取消，不生成第 9 只 |

| 相对时间 | 无尽普通波，间隔 2 秒 |
|---|---|
| 0 | 先登记 S@14，再登记 P1@2，直接生成第 1 只 |
| 2、4、6、8、10 | 每次生成一只，并重新登记下次 P |
| 12 | 生成第 7 只，再登记 P7@14 |
| 14 | S 先执行并取消 P7，末批不生成 |

全部窗口为 40 秒。下面按相同间隔合并展示，列出的波号合计恰好 54 个且无重复。每批每入口一只，所以批数等于基础刷怪数量。

其中 13 个主线波的原始范围因同刻排序收敛：5、10、13、22、25、27、30、32、35、37、40、45、50。它们全部得到原始范围的下界，这是登记顺序的计算结果，不是任意取下界。一个入口完整经历 54 波，共生成 **2300 只基础主线怪物**；此合计不含任何额外刷怪来源。

## 无尽普通波确定数量

`Game_Mode==1 AND IsEndLessBos()==false` 时，每个有效入口于 `0、2、4、6、8、10、12` 秒各生成一只，共 **7 只**；14 秒周期末批取消。`mw01`–`mw04` 随机模板不会改变每批一只的数量。

四种模板的 `points` 均为 2，所以本波基础怪物累计新增容怪点为 **14 点/入口**；这是生成量，实际存活容怪点仍随击杀变化。模板依据：[units_unitdata.json](../../reference/map-6.25/units_unitdata.json) 的 `points` 行 17160、17174、17188、17202，模板选择入口见 Lua 128445–128472。

## 计算检查与仍然保留的边界

已独立解释 Lua 中四个数值数组的逐项寄存器赋值和数组写入，将全部 54 波的间隔、窗口及相邻波开始间隔与原始机器表交叉检查；再用整数微秒的优先队列逐次模拟停止、周期重入队和取消，逐项对照上面的整数公式。54 个主线配置及 1 个无尽普通配置全部一致，原始上下界表的 SHA-256 在写入前后相同。机器表保存原文件哈希、13 个端点碰撞波号及两个示例的事件轨迹。这是规则计算检查，尚不是 Web 游戏运行测试或原客户端实测。

在“入口完整有效、该波正常执行完刷怪窗口”的范围内，没有尚未固定的数量变量。若入口被移出相关玩家表、对局提前结束，或该波尚未开始，则实际生成数取决于已发生的批次，不能承诺达到表中完整数量。杀怪速度只改变存量，不把停止后的缺失批次补刷；暂停、倍速及后台补算依 B05 保持同一条战斗时间轴。

原客户端对同刻原生计时器的顺序仍未验证；该事实只影响“原版究竟是范围中的哪一值”，不再妨碍已授权 Web 基准下的确定数量。本页未修改图鉴、原图参数或原始范围，也不裁决其他模式的生成规则。
