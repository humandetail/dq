# 物品取得、使用、移出与嵌套事件

`item-lifecycle-v1` 补齐物品事件的事务接口、末次抽卡充能、合成重入和典当；**不把装备能力挂载等同于全部装备效果已经实现**。图鉴价格／数量优先，既定[资格生命周期](qualification-lifecycle.md)、[召唤与交付](summon-and-delivery.md)的 1 秒施工、返卡与 D01/D02 均保留。机器表见 [item-lifecycle.json](item-lifecycle.json)，可复查工具见 [audit-item-lifecycle.py](../../tools/audit-item-lifecycle.py)。

目前唯一新增的待决机制点是个人神秘商店回调读取全局 `unit`，见末节；本页不以 Q24 擅自修正已读到的脚本。

## 核查范围与事件入口

完整核对 `main/f285` 的 15 个核心函数，共 2,947 条指令：f0 成长充能查询，f5 抽卡输出，f6 `ItemSkillUsed`，f7 槽位查询，f8 `HasItem`，f9 配方匹配，f10 `Item_Get`，f17 `Item_Use`，f18 `Item_Drop`，f19/f20 两个零秒回调，f21/f22 两个调度器，f23 `Item_Auto_Use`，f38 注册。机器表逐个给起止行、PC 范围和测试执行覆盖；另核归属锁、魔焰之心替换及必要直接助手。商店部分只核入口中的删除、输出、扣账和调用次序，平台／挑战内部效果仍归各自模块。

[注册 f38，L152692–152829](../../reference/map-6.25/main.disasm#L152692)对 Player(0..3) 分别安装 `PICKUP_ITEM→Item_Get`、`USE_ITEM→Item_Use`、`DROP_ITEM→Item_Drop`，使用 `TriggerAddCondition(Condition(fn))`。回调中的 `return` 只退出该回调；不能将它理解成原生交易自动回滚。

抽卡入口在另一条链上：`SPELL_EFFECT→AnySkillStart`，未被前面的特定技能分支返回时，尾部依次 `WAbility_W012 → WAbility_W014 → WAbility_W016 → WAbility_W018 → ItemSkillUsed(spellTargetLoc) → Model_Change`。[入口登记 Lua L125044–125089](../../reference/map-6.25/main.readable.lua#L125044)，[尾部字节码 L172149–172172](../../reference/map-6.25/main.disasm#L172149)。普通 `Item_Use` 本身没有常规抽卡代码。这里没有重新核完整 `AnySkillStart` 的所有其他技能。

十种商店注册的是 **`EVENT_UNIT_SELL_ITEM`，即商店卖给买者**，见 [L197833–198161](../../reference/map-6.25/main.disasm#L197833)。完整 Lua／JASS 中没有找到本图业务 `PAWN_ITEM` 处理器；同名常量导出不算处理器。卖回商店的典当不能误调这十个购买回调。

## 拾取处理的原始顺序

以下是 [Item_Get 完整字节码 L144536–145508](../../reference/map-6.25/main.disasm#L144536)；机器表 `orderedHandlers.Item_Get` 给每段精确 PC 和来源。所有拒绝均只执行相应脚本动作，不自动退还已经完成的购买／兑换成本。

| 顺序 | 条件与动作 |
|---|---|
| 1 | 缓存拾取类型和载体。i421 调 `Abyss_gold_bless_use` 后返回；i422 提示并向 Player(0..3) 各加 1 皮肤碎片后返回。两者不继续后面的锁定和合成。 |
| 2 | 非工人且非能量圈拒绝 i256/i329/i278、三把破损妖刀 i131/i133/i262，`UnitRemoveItemSwapped` 后返回。工人或能量圈拾取 i330 则**删旧件、创建 i332、尝试加包，不复制充能，也不返回**；外层缓存的类型仍是 i330。能量圈另拒绝 i256/i278。 |
| 3 | 非工人／圈的七种成长装备，有正充能时先按每点生命 4／魔法 3 加最大资源，并记下充能。这在归属与资格拒绝之前。 |
| 4 | 必要时设物品无敌；调用 `AnyUnitPickUp`，返回 false 就移出并返回。随后非工人／圈拒绝 `GetItemLevel>10`。 |
| 5 | `Game_Mode!=2`、非工人／圈、Level>3 且实例不在 `ignore_strong_item`，检查 B015。熊灵伙伴非神杖物品查关联英雄；其他路径查自身。普通资格失败路径对 i304 先写间隔−0.2，对 i282 先加射程／索敌，然后移出。熊灵的另一路拒绝没有这两项预补偿。 |
| 6 | 尝试配方；完成第一条即消耗、创建、交付成品，播放效果并返回。 |
| 7 | 非工人／圈检查 12 组同类互斥；发现其他成员则移出当前实例并返回。 |
| 8 | 14 项叠充能白名单：把新充能加到第一件旧实例，删除新实例并返回。 |
| 9 | 非工人／圈 i304 间隔−0.2 后返回；i282 增加射程与索敌范围后返回，远程+200／近战+100。 |
| 10 | 非工人／圈 i310 调 `Use_A_Item`，继续；随后按**仍有效的当前物品句柄**分派 i718…i723 的六个奖励动作，结束。 |

资格状态复用已定 B015，不因本页增加每帧自动卸装。原生装备能力的属性贡献与脚本显式的 `SetUnitState` 是两个来源；直接最大资源写入接入[属性接口](hero-attribute-interface.md)，保留当前绝对值再裁剪，不能将一次拒绝笼统实现为恢复所有旧快照。

`HasItem` 在槽 0–5 返回第一个同类型且**不等于当前 `GetManipulatedItem()`** 的实例；不是简单的 `contains(type)`。[f8 L144417–144461](../../reference/map-6.25/main.disasm#L144417)。因此它在拾取、使用、移出和施法效果事件里的结果会受事件上下文影响。

归属锁 [main/f280/f0–f1 L137059–137260](../../reference/map-6.25/main.disasm#L137059)按实例查四张玩家表。未绑定则加入当前玩家表；同表放行；跨玩家且原主工人有 B062 或 B160 则拒绝。否则删原表条目，把实例写到新表的**同一个数字索引**，没有另找空位，可能覆盖新表已有条目。后续丢弃不解除这份锁。单人模式一般不发生跨玩家转移，但不能把这段源事实改写成安全追加。

## 配方、充能与移出

原构造器完整提取 91 条配方，图鉴《合成配方》的 90 条逐项按材料数量核对一致；第 89 条 `y017←y013+y014+y015+y016` 没有图鉴行，作为原图补充保留，不据此宣布其取得途径已经闭合。图鉴把重复材料合并写作“×2/×3”，原脚本的材料次序独立保存；例如圣剑材料为 i305、i140、i143、i140、i143。配方数据 [L141321–142585](../../reference/map-6.25/main.disasm#L141321)。

配方只有在本次缓存的拾取类型出现在该配方**任意位置，包括成品位置**时才尝试。匹配器为每个材料找一个尚未使用的槽，因此两个同名材料需要两个实例；一个槽有两次充能不够。[f9 L144463–144534](../../reference/map-6.25/main.disasm#L144463)。按匹配到的槽逐个重新读取当前实例，消费规则为：

- 七种继承装备 i332/i330/i145/i147/i220/i327/i218，充能>0：记下其充能并删除整件。这里是**覆盖上一次记值**，不是累加；最初记值还可能来自步骤 3 的拾取物品。
- 其他材料或充能不为正的上述材料：充能>1 就减 1，否则删除整件。
- 材料处理完才创建成品；记值>0 且成品也在七项表时给成品该充能，然后 `UnitAddItem`，忽略返回值。不会在失败后复原材料。

原消费与输出次序见 [L145115–145206](../../reference/map-6.25/main.disasm#L145115)。若每件普通材料都有剩余充能，合成后未必腾槽。十四项叠充能为 i127/i128/i001/i002/i003/i005/i235/i258/i259/i260/i329/y006/y008/y010；它在配方之后执行，保留旧实例身份。[表 L142997–143040](../../reference/map-6.25/main.disasm#L142997)，[执行 L145278–145306](../../reference/map-6.25/main.disasm#L145278)。

`Item_Drop` [L147097–147619](../../reference/map-6.25/main.disasm#L147097)先移除 `ignore_strong_item` 当前条目，随后依次：无其他 i304 才回加间隔 0.2 并返回；无其他 i282 才减对应射程／索敌；失去有效神杖才调 `Drop_A_Item`；七种成长物按**移出当时充能**扣最大资源并返回（充能 0 也返回）。之后才可能处理 A125 英雄的熊灵攻速：三组 i243/249/250、i245/251/252、i247/253/254 失去最后一件各减 state81 的 0.4 并返回，再查单独 i247 减0.3、单独 i242 减0.2。前面的返回决定哪些后续分支可达；丢 i247 而仍持 i253 时，才可能走后面的−0.3。

源的非对称例为载体失去资格前已持一件 i304。再拾第二件时，拒绝前先−0.2，移出因旧件仍在而不回加。图鉴明确圣力为唯一被动，Web 按 Q64 只给实际成功保留的有效圣剑一份−0.2，拒绝的新件不产生此贡献，只撤销实际已给出的值。L01 事件次序、其他 state37 写入与拒绝物品已经获得的无敌标记继续生效。 [圣力专项](item-final-batch-01.md#圣剑-i304-与神杖-i310)

## 原生证据与本页采用的 Web 接口

[暴雪一般物品说明](https://classic.battle.net/war3/basics/heroitems.shtml)支持六槽、使用消耗充能、永久物品移出后失去相应效果、典当为基价的一半；它没有给出本图客户端的拾取／移出／施法先后、最后一充能何时腾槽、充能叠包折价或移除时的回调。`GetManipulatedItem` 的[原生接口文档](https://lep.duckdns.org/jassbot/doc/GetManipulatedItem)列出其拾取／使用／移出事件上下文，也没有事件嵌套保证。**以下 L01–L09 是 Q24 已授权的 Web 选择，不是原版实测。**

另有[作者在1.27+YDWE的复现报告](https://www.hiveworkshop.com/threads/undroppable-items-trigger.346238/)（ies，2022-11-29）：DROP回调内RemoveItem再加回引起重复触发；同帖还观察到典当和转交会产生DROP。这支持移除／移出可以重入的研究边界，不证明本图客户端的完整顺序。L09的同实例removing幂等保护仍是明确的Web选择，不冒充原版自带防护。

**L01 事件与挂载。** 成功入槽先登记该实例实际 `abilList` 的能力贡献，再同步执行 PICKUP。移出先清槽、撤销该实例的原生能力贡献，再同步执行 DROP；回调期间类型／充能仍可读。显式 RemoveItem 对已在包内的件执行这条移出链，返回后销毁句柄；地上件直接销毁，不虚构载体 DROP。移出由脚本拒绝触发也一样。各能力的属性计算、同名叠加、熊灵／幻象继承由相应效果模块决定，不能把原始列表简单累加成全部数值；例如 i123 的列表有重复 I134，机器表保留原文本，不静默去重。三围贡献变化接入属性接口，脚本额外写入按真实顺序保留，不整体回滚。

每个 PICKUP/USE/DROP/SPELL/SELL 建独立事件帧；getter只读当前帧定义的字段，SPELL和SELL的 `GetManipulatedItem()` 为 nil。嵌套返回后恢复外层帧及其原句柄，而不是把新成品误当原拾取件。

**L02 入槽与重入。** 保留 D01/D02 的最小空槽、满包拒绝／脚本奖励留地、原创建坐标。成功 add 同步完整执行 Item_Get；其内部 create/add 可继续嵌套，内层结束才返回外层。整数键 `pairs` 明确按递增索引，因此配方、材料、互斥组和稀疏表查找可复现；不改变源数组排列。只移动或交换包内槽位不发 PICKUP/DROP。显式 `powerup=1` 沿用 D02 无槽豁免，给它一个不占槽的拾取事件上下文；执行已解析的拾取效果，之后销毁仍存在的即时物品，不另发普通背包 DROP。其具体技能效果仍需对应模块。

**L03 使用提交。** 命令先复核有效载体、物品仍由它持有、可用标记、充能门槛，以及该能力已定义的目标／范围／蓝量／冷却。未准入无扣减／事件；施法行进与前摇由对应能力接口负责，不能把所有物品统一变成瞬发。到成功提交点，快照能力、施法者与目标，正充能先扣1，提交已定义的费用／冷却，依次执行 USE 和该次已提交施法的 SPELL_EFFECT 链；即使 USE 中显式删除物品，也不丢弃已经提交的能力上下文。**易消耗物品末次充能的自动删除延迟到这两条同步链全部结束**：只检查原实例仍存在且仍为0才删。中途显式 RemoveItem 立即照 L01 执行，不延后或复活；没有统一“效果无效返充能”。AIbl 卡片继续独立走 S02 的创建／人口／一次充能提交，不再经过本条重复扣费。

因此六槽满、i001剩1次时：先变0但仍占槽；抽出的卡按D01落在原创建处；外层结束后原i001才移除，最终五槽占用。幸运机会成功时额外卡先落地，常规卡随后落地。I259错误物品目标的SPELL帧能通过HasItem找到仍在槽内的0充能原件并+1，结尾就保留；nil目标没有退款。I211则保留源代码“删第一件i207并新建”，不转成恢复旧充能。钥匙显式先删除自身和宝箱，奖励是在两槽释放后才交付，不能套用抽卡的槽占用结果。

**L04 字段缺省不冒充事实。** 机器表保存425个 i/c/x/y 自定义物品的原字段和缺项。仅 `usable=1` 可主动使用；显式 `uses>0` 的有限使用物品必须有至少1次。未列uses的字段仍存null，Web另明确将其初始**实例计数器**设0、对显式usable=1采用无限基础使用模式；之后脚本若给出正计数仍按L03扣1，这保留i330/i332源码的条件+1。原生缺省并未被证明为0。只有显式perishable=1才在成功使用后的耗尽清理中删除；单独SetItemCharges只改实例计数，不发PICKUP/DROP、不重放成长属性加减，设为0也不自动删除。三把破损妖刀虽显式perishable=1却没有usable/uses，本规则不会让它们以0计数自动消失。425行仅i718…i723缺Level，且均明确powerup=1；w3t没有补写。对这六项局部选择GetItemLevel=0，使原拾取门槛继续到其明确奖励分派，不把它推广成所有未知物品等级默认0。缺abilList仍存null，本Web不从未知模板补能力，只挂载显式列表并执行显式脚本。

UI丢弃／转交需显式或运行期已设droppable=true；未知字段不开放该UI动作，脚本移除不受此限。仅换槽不受droppable限制。拾取／丢弃／转交按Misc的400/1000/1000范围和既定空间接口，在实际提交时重查；收件人满包时转交提交失败，原物仍在原包，不产生一半转交。成功移出后收件人的拾取脚本若拒绝，则留收件人位置，不倒放已发生的DROP/PICKUP。

**L05 典当。** 需有效载体、仍持有该实例、可交互商店和显式／运行期pawnable=true。价格先用图鉴明确金币值，其次已解析的对象金币值；两者均缺失就不提供报价，不能当免费或0元回收。Web返金为 `floor(基价×数量系数/2)`：显式初始uses>0的物品，系数为当前charges/初始uses；其他物品为1，成长计数不加价。这个充能比例与向下取整是Q24选择；不是暴雪页面给出的精确公式。**本接口只返金币，不返木材／平台积分**，是明确的局部Web交易种类，不将缺失木材价解释为原生0。整件出售，提交时按当刻报价一次入账、移出／DROP／销毁一次；不调用商店SELL_ITEM回调，不增加商店库存。显示报价不锁定旧充能；同刻再次出售因实例已移出而拒绝，不再加钱。

**L06 自动使用的延迟。** 零秒回调按B05排队尾，不在调度函数内立即执行。保存的是实例／目标句柄和地点快照；执行时重新检查是否还持有有效物品及正常命令准入。失败不耗充能／蓝／冷却、不发使用事件；原回调仍销毁timer和清记录，不重试。不能因第一项发令成功就取消后面独立分支。

**L07 存档。** 只能在当前同步事务栈和末次充能清理完成后落快照；中途的保存请求排队等本事务结束。零秒timer属于另一B05事件，未执行前可以保存。持久化实例ID、类型、充能、生命／位置／槽位、能力贡献来源、实例标记、已结算资源、随机状态、稀疏锁表／忽略资格表、兑换计数、待执行timer及入队次序和保存的句柄／点。加载直接恢复这些状态，不重放拾取、使用、售出或DROP，不再跑成长属性加法；不得把读档的能力贡献恢复误算成新装备获得。这里没有要求实现或序列化Lua调用栈。

**L08 实体购买与销售事件。** D02通过后提交费用／库存、入槽并同步PICKUP，再调用SELL_ITEM，携带原交易的商品句柄。若PICKUP已合成／删除该实例，SELL仍保留原句柄，按L09读取；不复活原件、不把句柄换成成品、也不凭删除倒退交易。该先后是原生未知的明确选择。已定义的虚拟兑换／翻页菜单直接运行其脚本事务，不凭物品对象价额外收费、不增加一个虚构实体空槽门槛。i546的`HasItem`结果不由本条修正；个人Fshop表选择由独立用户裁决Q44修正。

**L09 本接口无效句柄。** 已删除／nil物品的类型、充能等数值getter返回0，句柄getter返回nil，setter／移除无效果。DROP期间处于`removing`的实例仍可读，但对同实例再次RemoveItem立即无效果，避免递归移出；回调完成后才标`deleted`。这是本页局部适配，不宣称所有native句柄都有此语义。
