# 灰烬兜帽：灰烬印记与焚焰

灰烬兜帽 Lv1、Lv2、Max 对应 i318、i319、i320。两本图鉴的 `装备与道具!H211:H213` 逐格一致，三档均挂一级 I158（AIab.DataB=150），随有效物品实例应用 +150 智力。当前最高有效档决定每次焚焰；同一塔只有一份灰烬印记，普通拾取遵循三档互斥组，脚本或异常状态下同时持有多档也只接受一次入账。静态属性、合成、持有和移出沿既有装备接口。 [装备属性](item-attributes.md) · [物品生命周期](item-lifecycle.md) · [合成表](../../reference/map-6.25/main.disasm#L141535) · [三档互斥](../../reference/map-6.25/main.disasm#L142623)

## 标记的资格、归属和次序

普通分派先经过 `AnySkillStart` 的临时单位和技能过滤，再由 `Item_Skill_Action` 排工人、背包、IsUseless 能力；在原有前置技能和装备之后，读当时的原生 HERO 标志，按 i318 → i319 → i320 依次查任意有效件。A075 在该入口跳过，实际 SPELL_FINISH 分支完成原冷却处理后补一次同样的兜帽接口。拾取、学习、普通攻击和取消的前摇没有这一入账；合格物品主动技能仍沿实际 SPELL_EFFECT。装备检查保留原 HasItem 跳过当前操作物品的规则。 [普通分派](../../reference/map-6.25/main.disasm#L146653) · [再装填完成](../../reference/map-6.25/main.disasm#L172372) · [入场过滤](item-muramasa-takemitsu.md)

在基础检查点读取含加成的 INT、AGI、STR。INT ≥ AGI 且 INT ≥ STR 才加1并检查阈值，平手有效，未达到时保留旧层。随后若 A060 走多重分支，按其已定接口再一次性加本次预定额外次数，无额外智力门槛，不马上检查阈值。额外攻击/Buff 的实际成功次数、马甲、迟到回调和普通装备取放也不再产生这份入账。两步顺序保留：先基础检查，后添加多重计划次数。全新的槽从0开始。 [基础属性条件和计数](../../reference/map-6.25/main.disasm#L153349) · [多重写入](../../reference/map-6.25/main.disasm#L69567) · [多重接口](ogre-multicast.md#灰烬兜帽交接)

印记原键为 `IsInTable(caster,Tower_ALL)`，三档共用 `i318_Sign`，原槽键兼容 `−1`。两处模块初始化写同名表，完整函数指令一致。除初始化、基础处理和多重加层之外，源无该表清除；掉地、出售、销毁物品、替换成更高档时均不清计数，槽内移动也不改计数。不持有效兜帽时无法新入账或兑现，重新持有任意档可以继续。装备转手只移动物品，接受方仍使用自己的登记塔槽和旧计数，印记不跟随物品。死亡不清表；同一登记槽换皮、复活或脚本换单位时，用该槽现有计数。失去登记槽也不主动删原表项，若后来明确复用编号则读原槽值。存档保留计数与塔槽，恢复不重放任何取得或施法事件。 [印记表](../../reference/map-6.25/main.disasm#L153128) · [槽查找和写入](../../reference/map-6.25/main.disasm#L153420) · [物品移出](../../reference/map-6.25/main.disasm#L147097)

## Q53 消费和无目标

一次合格基础检查先固定加1，即使已有5层以上或身边没有目标。然后在计数≥5且仍具有效装备与基础资格时，按 [B04](web-baseline.md) 从当前塔坐标750闭圆取 `hasMon` 的首名存活 Player(11) 单位，固定其当前二维坐标为本轮焚焰中心。中心选择符合原 hasMon，魔免、无敌、Aloc 与视野由不同伤害入口各自处理。没有中心时保留全部层数，等待后续合格施法。找到中心就先扣5、完整提交一轮焚焰，返回后以当前装备、范围和存活状态重查，再决定是否继续。中心只定本轮范围，能重复选仍合格的同一单位。扣层后即使输出被免疫或没有有效受击者也不回退。多轮是同一施法事件中的连续同步效果，不注册额外 SPELL_EFFECT、不另扣费用、不创立计时器。

| 初始层数和条件 | 此次基础检查后的结果 |
| --- | --- |
| 4，无目标 | 5，零次；下一次发现中心时先到6，扣5发一次后余1 |
| 9，无目标 | 10，零次；既有层数和当次新增的1层都保留 |
| 12，可持续找到中心 | 先到13，连续两轮，各扣5，余3 |
| 12，首轮杀死最后合格中心 | 只发一轮，余8 |
| 3，普通检查加1，多重计划额外3次 | 检查点先到4还不发，随后多重加到7；下次合格基础检查才继续 |

原源码在旧值≥4时只尝试一次，发现目标便整槽清0，无目标就保留旧值且不加入本次1。Q53 以用户确认规则替代该部分，保留门槛、不同入账路径和目标筛选。 [原阈值 PC37–84](../../reference/map-6.25/main.disasm#L153437) · [hasMon](autocast.md#3-目标选择约定)

## 一轮焚焰的两段伤害

每轮重读最高有效兜帽、有效智力 I 和此刻当前魔法 M；魔法值已反映当次主动能力按共享提交接口扣除的费用以及先行装备回蓝。M 只读，焚焰不另扣。三档独立按图鉴取金额，法术包的后续修正走统一伤害事件。

| 装备 | 中心半径 | 法术输入 | 神圣比例（普通／Boss） | 源脚本法术；源普通／Boss |
| --- | ---: | --- | --- | --- |
| i318 | 400 | (4000+5I+0.20M) | 3%／1% | (3000+4I+0.15M)；2%／1% |
| i319 | 500 | (8000+6I+0.25M) | 6%／2% | (5000+5I+0.20M)；4%／2% |
| i320 | 600 | (12000+7I+0.30M) | 9%／3% | (7000+6I+0.25M)；6%／3% |

1. 以实际塔为源、中心和所选半径提交零延迟 `SetMagicDamagePoint`（`false,false,NORMAL/MAGIC/WHOKNOWS`），走 [area-damage-v1](native-area-damage.md) 及 B03。普通敌方地空、建筑可以受伤，范围快照对免疫和存在情况按共享规则处理。只完成一轮法术快照后才开始下段。
2. 保留 TxShow 的 `AZ_LordGarithosPF_W1.mdx` 表现，时长0.5秒、三档显示比例1/1.15/1.30，表现不产生等待或追加波。
3. 重新以同一中心、半径形成候选组，B04 遍历时复核 Player(11)、存在、存活。读取轮到该单位时的当前生命和 `UnitIsHero(target)`（N534>0 且原生 SAPPER），发一笔该生命乘对应比例的 `SetRealDamage`（`false,false,CHAOS/DIVINE/WHOKNOWS`）。已经被首段杀死的不发；首段同步回调中新创建、移入并落在第二次新快照的单位可以只收神圣包。神圣可作用魔免，仍走既定无敌、Aloc、生命和管线规则。图鉴 Boss 用该地图谓词实现；普通原生 HERO 不会自动落到 Boss 档。N535 对这两个伤害入口均无作用。

两段实际来源都为施法塔，范围、直接伤害和全部嵌套事件按各既定接口依次处理。首段按敌对关系，第二段按原脚本的 Player(11) 筛选；条件不合并。 [两段字节码](../../reference/map-6.25/main.disasm#L153143) · [直接神圣入口](../../reference/map-6.25/main.disasm#L52093) · [Boss 谓词](../../reference/map-6.25/main.disasm#L52444) · [同类直接伤害边界](zeus-skills.md#3-a105-静电场)
