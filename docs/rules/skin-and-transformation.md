# 换皮、技能变体与同实体交接

基准 **`skin-and-transformation-v1`** 闭合完整Model_Change、直接查表／解锁辅助、111个选择入口及Skill_BS_Still的两类回调。机表保留111条映射、10个ANeg辅助的14组替换、306个相关能力记录、110个单位的模板证据、17个源函数；完整狼人、炼金、德鲁伊、龙骑等主动变身仍由对应技能模块负责。[机器表](skin-and-transformation.json)

本页沿用Q18–Q21的永久内容开放、[物品事件](item-lifecycle.md)、[英雄成长](hero-progression.md)、[属性接口](hero-attribute-interface.md)、[神杖生命周期](scepter-lifecycle.md)、[资格](qualification-lifecycle.md)、[攻击时序](attack-timing.md)与[移动接口](pathing-and-placement.md)。Q24部分是明确Web选择，不声称已经运行匹配原图的Warcraft客户端；没有删掉源码中看似用于绕过原生问题的操作。

相关分派顺序：[f291/f14 L169578–172172](../../reference/map-6.25/main.disasm#L169578)先执行一般变身技能的移动定时器检查；其`skill_bs_id`只有A010/A110/A127/A169/A239，**没有S选择技能**。随后IsTemp或特定排除技能直接返回；皮肤普通路径先`Item_Skill_Action(target)`、`WAbility_initAbility()`。唯一S专用前置是 **S292且A084>0，直接把最大魔法减250×当时技能级**，[L170075–170103](../../reference/map-6.25/main.disasm#L170075)。在其后统一尾部依次运行W012、W014、W016、W018、ItemSkillUsed，然后Model_Change。这些公共物品／神器助手仍按其已核模块执行，本页没有把它们统统替换成无效果。

S292扣上限接既定直接MAX_MANA接口：当前魔法保留绝对值再裁剪；不是扣当前魔法、不是把精气光环重新学习一次，也没有回补分支。即使本Web的Acha不复制原生绿字，也仍保留这条**明确的脚本写入**。例如最大／当前4000、A084六级，前置后均2500，再发生本次+10／+30智力和换皮自然分量的变化。

[Model_Check/Model_Upgrade_Check/Model_Check_type f289/f4–f6 L156422–156528](../../reference/map-6.25/main.disasm#L156422)按目录顺序查S，未命中返回空串。另有48条永久保存目录；Get_Model_Upgrade按保存名称返回S，Get_Model_Index_By_Upgrade按S返回目录索引，未命中nil。[f289/f1–f2 L155369–155429](../../reference/map-6.25/main.disasm#L155369)

[Model_Check_Enable f289/f3 L155431–156420](../../reference/map-6.25/main.disasm#L155431)处理四个玩家：须USER且PLAYING，逐个读取对应ScoreSkin_Player_N的0起字符串片段，nil／空串终止；提取各数字，命中48项保存目录再反查科技并+1。随后处理显式商城／活动权益科技；最后对Player_Build_Unit中非nil单位加S001/S531/S601/S701及源代码列出的永久标记。完整科技对照复用[平台规则](platform-and-access.md)，Q18–Q21已开放的权益不再要求远端账号购买，任务条件照既定决策保留。

**Q24这111项选择的原生准入：**当前实际技能／技能书拥有该选择、科技已解锁、存活且可操控、能力启用、1秒冷却就绪才接受。选择是无目标提交；未写DataB按本局部无目标、未写Cost/Cast/Duration按本局部0费用／0前摇／无持续引导，不把字段缺项改写成原图显式0。提交先登记1秒冷却，再同步进入上述SPELL_EFFECT；不发一次虚构学习事件。界面按真实菜单提供选择，直接脚本调用Model_Change则照源执行，不添加源中没有的“只准一次”保护。

## Model_Change完整事务

[完整函数 f289/f7 L156530–157078](../../reference/map-6.25/main.disasm#L156530)的436条指令全分支已覆盖。

1. 查S对应R；空串立即返回，尚未掉物品或加属性。
2. **此时是原生HERO**才进入英雄段。按槽0→5逐个读取当前物品，保留i310神杖及i304，其余`UnitRemoveItemFromSlot`，包括对空槽的无效果尝试。每次移出同步执行真实DROP；后续槽读取能看到前一回调的修改。不可先快照六件再统一掉落，也不重加回原包。[L156625–156657](../../reference/map-6.25/main.disasm#L156625)
3. 移出全部完成后，依次读取无附加STR/AGI/INT三个基础值。默认各+10，仅`SHOPITEM08 && SHOPITEM01`同时为true才各+30；分别SetHeroStr、SetHeroAgi、SetHeroInt且第三参true。Q18下正常Web玩家具备这两项，故通常+30；原+10分支仍保留作来源与测试。[L156658–156707](../../reference/map-6.25/main.disasm#L156658)
4. 单位不在J003_Hero才调用Skill_BS_Still，然后处理下面十项专用ANeg加删；S042/S043分支没有额外技能操作。J003只跳过这条timer，不跳过掉物品、加三围或ANeg。
5. 英雄段结束后，若R705且当前玩家名字精确为`zado1991`，改为R714；其他情况保持目录R。随后对原单位`UnitAddAbility(R)`。
6. 再读当前IsWorker／IsBOX；两者都false就结束。否则对于类别2/3/4/5，先把R永久化，再读该类别的**每玩家**旧R记录。同R立即返回；旧R非空则从**本次施法单位**移旧R，最后保存新R。四种类别独立，类别1没有这段旧效果移除。

英雄+10/+30发生在Acha之前，和当前R是否已经存在无关。原函数没有检查同一皮肤已选择、没有返还物品、没有属性回滚。强制再调用相同S仍会再加三围和新建timer，不能以Q24擅自修成Lua幂等。

装饰的记录是每玩家、移除操作却只针对当前施法单位；同主工人先戴R532，再让能量圈戴R533，会从圈上尝试移R532，工人原R532仍可能保留。不能将它改成自动找到旧承载者卸除。R705→R714的名字分支原样可观察；不替用户冒用该名字，也不改变Q21的解锁政策。

## Acha同实体提交：Q24明确选择

70项R均为Acha且有明确UnitID1。所有50个英雄目标模板均没有原基础英雄的皮肤技能书。原脚本没有CreateUnit／ReplaceUnit调用，但这不单独证明原生如何保留属性、技能与Buff。

[作者Chaos实验](https://www.hiveworkshop.com/threads/chaos-morph-applying-it-to-a-system.279277/)（Zwiebelchen，2016-05-17）展示无目标Chaos可重复折入属性与奖励；它研究的是空替换目标，不能当作本图有UnitID1时的定量结果。[ANeg作者说明](https://www.hiveworkshop.com/threads/are-alternate-ultimates-possible-in-wc3.258060/)也提示已学技能替换有原生字段混用。没有匹配客户端证据，故本页采用下列**可测试Web规则**，不复现未经证明的奖励翻倍。

- 首次成功添加该Acha，在该native操作内把**同一个稳定实体**的当前类型提交为UnitID1，模型／名字／模板分类／碰撞／武器与移动模板引用改为目标。保留所有者、坐标、朝向、生命状态、经验／等级／技能点、付费历史、现存物品实例和源脚本表引用。不发创建／建成／死亡／升级／学习事件。已经有同一Acha时普通add无效果；其外层脚本仍已执行。
- **区分模板与运行状态。** 目标`abilList`替换旧的模板挂载；真实学习槽及ANeg后的映射、脚本已授予的T002/T008/I269/A106/A154/P***等独立能力保持。新模板不会自动把可学列表学成一级，不会反复加学习属性。已标永久的菜单／装饰保留其脚本来源。50个英雄目标失去原模板皮肤书，所以正常UI选择后不再提供旧书中的第二次换皮；不另造一套永久次数锁。
- 自然成长重基准：`natural(target,L)-natural(old,L)`在当前等级一次提交；保留已形成的脚本基础修改、装备／技能贡献、直接最大资源差额。未来升级使用目标成长。50组中仅S352的H058→G075有三围／成长差异：力量13→15，每级5→6；因此L级再加`L+1`力量，独立于刚执行的+10/+30。L10普通分支原力量100→先110→再121；享权益则先130→141。不是覆盖为新模板初始15。
- 自然属性差接既定属性／最大资源接口；原显式三个setter先后仍可观察。模板HP／基础魔法等重基准保留当前资源绝对值再裁剪，不额外填满；所有保留的直接MAX_*差额仍在，包括S292前置扣上限。尸体不会因换模板被复活。
- 模板武器／原生分类立即更新；已经形成的脚本属性、攻击字段修改与状态81的J分别保留，不把物品／Buff绿字折入第二份永久值。state37现值保留到下述**原3秒回调**显式覆盖，不能在换型时提前执行其重置。其他武器分量的精确字段口径继续由共享武器接口负责，不能借换皮页改S18/S19定义。
- 已开始攻击的当前前／后摇保留本次P/B快照；K、C变化继续沿attack-timing-v1的进度接口，下一次新攻击取新模板P/B及武器。已提交攻击／独立投射物不回放。其他已核timer保留原实体句柄、捕获的数值与截止时间；回调若动态读类型则会读新类型。持续效果不会因“换皮”一词统一取消。
- 类型提交点重算资格派生B015、光环、物品贡献与当前空间碰撞，保留同实体的永久资格ID；不伪造拾取或升级来触发降级／卸装。改变碰撞后当前位置不自行寻路或传送，只影响后续移动／放置查询。模型渲染成功与否不回滚已提交游戏规则。

以上不替代主动变身技能自己的开始／结束逻辑；也不新增“正在变身就不能选择皮肤”的限制。是否可下发仍由当前实际技能书、技能启停和准入决定。真正删除旧单位再新建的路径不能直接复用此同实体接口。

## Skill_BS_Still：0.04秒锁定与3秒显式覆盖

[创建 f291/f13 L169531–169576](../../reference/map-6.25/main.disasm#L169531)每次建立一组独立记录：新0.04秒周期timer，用AddArrAny取首个空索引保存unit；再建3秒一次timer，放到同索引。没有检查同单位已有timer，没有刷新旧timer或合并锁。

[周期 f291/f11 L169294–169324](../../reference/map-6.25/main.disasm#L169294)用到期timer反查该组，读取原实体，再`EXSetUnitMoveType(unit,1)`，没有生命检查、没有stop、没有坐标回写。类型1沿已有空间规则是不准普通MOVE；不是PauseUnit，不暂停攻击和timer。第一次在+0.04秒，不在创建函数内立即执行；结束也没有把移动类型恢复为2。

[结束 f291/f12 L169326–169529](../../reference/map-6.25/main.disasm#L169326)严格依序：

1. 用结束timer反查索引，取原unit；销毁这组周期与结束timer。
2. 读取单位**此刻GetUnitTypeId**，用Get_UnitData_By_ID的jass.slk.unit查询cool1，再`tonumber`，**覆盖state37**为该值。[查询助手 f7/f41 L52312](../../reference/map-6.25/main.disasm#L52312)。有效英雄目标均有明确cool1；未提供数值不是可自动当0的模板。
3. 当时非工人、非BOX且HasItem(i304)命中，再从当前state37减0.2。
4. 当时单位在A111_113_tar值集合中，再减0.1；此项不附加上一步的工人／BOX门槛。
5. 当时非工人、非BOX，持i282，且IsSkill_Bs=true才恢复范围。IsSkill_Bs只检实际A010/A110/A127/A169/A239任一>0，[f7/f17 L51333](../../reference/map-6.25/main.disasm#L51333)。非近战：state22与当前acquire各+200；近战各+100。两项各自先读再加，没有保存原值，也没有“已经加过”标记。
6. 清这组三表索引。没有扫描或清其他组，没有统一重算全部临时减间隔来源。

例如集中火力仍有自己的+0.2结束回调，换皮3秒却可先覆盖C，之后集中火力照旧加0.2；不能为了“还原一致”把两个函数合成一个理想增益账本。原i282已被英雄换皮掉出，正常3秒时通常没有该项；若这三秒内重新拾到，回调按当前持有判断就会加范围。重复建立两组，满足门槛时两组都加，不能幂等化。

**B05可执行时序：**登记时已把3秒结束项入队；周期每轮重新入队。因此+3秒相遇时，结束项早于由2.96秒重新登记的周期项，销毁后不再执行第75次。正常完整存活的一组有74次moveType=1写入。暂停／4×／后台补算只改变战斗时间推进。重叠调用各有自己的74次和结束操作，不是共用一个3秒窗口。

本页局部无效句柄选择：已删除实体native读0／句柄读nil、写无效果；普通尸体仍有效并按源回调执行。对无效类型的SLK桥接可返回nil，不把有效但缺cool1的内容默默补0；有效单位遇未解析cool1应暴露数据错误。不能把已删除句柄改指新塔，也不擅自把所有仍存表引用清掉。

## 保存与验收

保存必须在当前SPELL_EFFECT及嵌套DROP／属性／类型提交全部完成后。记录实际物品实例与地上坐标、当前类型／模板和模型引用、逻辑技能映射与冷却／付费历史／永久来源、三围自然分量和脚本差额、直接MAX与state37/81、资格／Buff、所有既有技能timer、四张每玩家装饰记录，以及每一组Skill_BS_Still的原实体／两timer／剩余时间和B05序号。载入不回放换皮、Use_A_Item、学习、掉落或+30。已掉地物品不会自动回包。

[复现工具](../../tools/audit-skin-and-transformation.py)在明确Web native桩下直接运行源字节码，**801断言通过**；Model_Change **436/436**、周期回调**12/12**、结束回调**153/153**、创建函数**24/24**指令均执行。含目录／入口／构造器共4713条不同指令；AnySkillStart只覆盖与皮肤相关的1015/1984条，不能声称全主动技能分派已完成。目录初始化与未命中分支的覆盖分母均在JSON。
