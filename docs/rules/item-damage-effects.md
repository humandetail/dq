# 装备伤害效果：狂战斧、遗物之刃与妖刀

本轮核完 `i115_Action`、`i132_Action`、`i134_Action`、`i184_Action`、`i263_Action1/2`、`i322_Action/Damage` **8 个函数体的全部条件、公式、顺序和返回**，以及它们直接使用的特效清理回调。它们合计 380 条字节码指令、25 条条件、82 处调用、13 条 return 指令；其中直接改写当前伤害 5 处、调用 `SetRealDamage` 3 处。统计只计这 8 个函数，不计辅助函数。

这不是这些装备所有能力都已还原：村正“居合”、竹光“细雪”、遗物之刃“克敌机先”和大狂战斧光环不属于这 8 个函数；T077 的原生飞行和命中实现也未由 Lua 字节码证明。[机器证据与验证案例](item-damage-effects.json) 保留函数、条件真假去向、返回位置及局部期望值，不复制整份反汇编。

后续已补 [居合与细雪](item-muramasa-takemitsu.md) 和 [遗物之刃命中](item-relic-hit.md)。本页仍只声明下列 8 个函数的原始核查范围；T077 已补部分字段意义，但完整波形几何仍未闭合。

## 1. 狂战斧 / 大狂战斧：i115_Action

图鉴 `装备与道具!H25/H119` 给出普通斧 45%、380 范围，大斧 90%、520 范围，与此函数相符。

1. 自行读取 S、T，以 **T 当前坐标为圆心**，创建枚举组。默认比例 0.45、半径 380；S 持有 i209 时替换成 0.9、520，不再叠加普通斧档。L126245–126275；i209 判断 L126265。
2. `GroupEnumUnitsInRange` 后循环取 `FirstOfGroup`，为 nil 才结束；每个取出的 U 先从组移除，再依次筛选：U 属于 `Player(11)`、U≠T、U 当前生命>0。并不是笼统的“所有敌对单位”。L126278–126307。
3. 对每个通过筛选的 U，若其类型为 m999 或 m998，系数 g=0.2，否则 g=1。此判定针对**被溅射者 U**，不是原目标 T。L126312–126330。
4. 每轮重新读当前事件伤害，调用 `SetRealDamage(S,U,D*比例*g)`。L126332–126340。未在循环前缓存 D；Web B03 保证正常子事件返回后仍处于父事件。不能把溅射改成普通物理伤害。
5. 随后仅在 `TxShow==true` 时，在 U 的位置创建 `CleaveDamageTarget.mdl`，0.5 秒后清理；每轮移除该位置句柄，结束时清空并销毁组。L126341–126363。特效开关不控制伤害。

此函数不改写原目标事件伤害，不对原目标重复溅射。它内部没有独立的 S/T 非 nil、伤害正数或近战检查，调用资格来自 Before。B04 决定 Web 的组内枚举顺序；源脚本没有指定最近或最低生命优先。

## 3. 鬼切：追加伤害与神圣暴击分开处理

图鉴 `装备与道具!H173`：全伤害+18%；“燕返”对非神圣伤害追加15%神圣伤害；“月影”神圣伤害20%概率造成240%伤害。After 先写 `D*1.18`，再按类型二选一调用下列函数，见 L145965–145995。

### i263_Action1(O,T)：燕返

T 为 nil 时立即返回（L132271–132273）；否则读取当前 D，调用 `SetRealDamage(O,T,D*0.15)`，随后返回（L132275–132283）。内部不检查 O，也不改写原事件。注意追加包的实际来源是参数 O，而不是原事件的实际来源 S。

例如仅观察此段，After 第10段入口 D=1000，先变为1180，再提交一个原始金额177的神圣子伤害包。原事件保留1180继续后续流程；子包还要独立经过伤害主流程。若子事件仍满足鬼切装备门槛，会先经过它自己的×1.18，再走神圣分支；不会再次调用燕返。因此不能把“追加15%”直接合并成原事件×1.15，也不能在鬼切自身这两个分支中制造无限递归。这里的递归结论以子包 `DIVINE` 类型保持及既定分派条件为依据，其他被动制造的新事件仍按其自身规则处理。

### i263_Action2(T)：月影

原脚本顺序已核实：

```text
if T == nil: return
r = GetRandomInt(0,100)
if r > 20: return
D = GetEventDamage(0)
EXSetEventDamage(D*2.2)
CreateEffByUnit("AZ_JianCi.mdx", T, "origin", 1, 1)
return
```

nil 早退 L132310–132312；随机与比较 L132314–132320；×2.2 写入 L132322–132327；1 秒特效 L132328–132334。比较是 `20<r` 才早退，因此 r=0 和 r=20 都成功，r=21 失败。若原生整数随机均匀包含两端，成功率为21/101；原始区间和比较符是直接证据，21/101依赖该随机接口约定。特效没有本函数内的 TxShow 门槛。

**Q25 已裁决：Web 月影采用图鉴的 20% 概率、2.4 倍倍率。** 这是已确认的差异，不再等待裁决；不将原脚本2.2改写成原图事实，也不自动改变其他未核装备的概率比较。本函数 T 为 nil 不消耗随机数的顺序保留。Web 同一段神圣入口1000，先×1.18再成功月影，局部结果为2832；原脚本相同成功路径为2596。两者都不是包含全部主分派修正的最终伤害承诺。

## 4. 遗物之刃：十次计数与波命中分离

图鉴 `装备与道具!H215` 写“奇锋：每攻击10次，会对前方一条直线造成神圣伤害（攻速越高伤害越高），近战且敏捷为三围最高属性生效”。下述脚本补足计数和公式；“克敌机先：70%不会落空”不由这两个函数实现。

### i322_Action：计数在符合条件的伤害事件上增加

模块 `main/f267` 在 L133187–133197 创建两张持久局部表：单位表和同索引计数表。它们由实际来源 S 查找，与装备实例、原目标 T 无关。

1. 读取 S；S 为 nil，或 `AGI(S,true)<INT(S,true)`，或 `AGI(S,true)<STR(S,true)`，立即返回（L133236–133261）。**敏捷并列最高也通过**；没有额外的原生 HERO 类型判断。外层近战、非幻象、装备和攻击标记条件仍须满足。
2. 读取 T，以 `IsInTable(S,单位表)` 查索引；返回-1则用 `AddArrAny` 加入并置计数0。随后计数+1。L133263–133281。
3. 计数≥10才触发，先置0，再创建 q018 并发出命令；计数<10正常结束。L133282–133313。资格不满足会在计数前返回，**不会把已积累计数归零**。此模块没有丢弃装备、属性变化或按时间清空计数的分支，不能自行增加该行为；跨变身/单位替换的表迁移应另查对应生命周期。
4. 创建 q018：所属玩家为 S 的玩家，出生于 S 当前坐标，朝向0，加入 T077、设技能等级1，施加 BHwe 原生计时生命2秒。L133285–133297。辅助函数完整顺序见下一节。
5. q018 的 `UserData` 写入 `IsInTable(S,Tower_ALL)` 的索引，再向 **第十次事件目标 T 的当前位置**下发 `carrionswarm` 点命令。L133298–133311。不是追踪绑定 T，也未检查命令返回成功；即使下令失败，计数仍已清零。

原脚本计的是 Before 调用的合格**攻击伤害事件**，并非攻击前摇开始次数；没有按“同一次攻击编号”去重。主分派器入口会排除初始伤害恰为0的事件；这里没有伤害>0门槛，也没有在 Before 前面的其他效果之后再次统一检查伤害是否为0。

### i322_Damage(q018,T)：每次命中重新取归属塔状态

Before 识别实际来源类型为 q018 后调用本函数，不要求 q018 自己持有遗物之刃、不要求攻击标记。函数先 `EXSetEventDamage(0)`，再读取 `O=Tower_ALL[GetUnitUserData(q018)]`。O 为 nil 或生命≤0则返回，**本函数返回时该事件保持0**。L133356–133373；调用者随后仍可继续，不能把这个 return 解释成主分派器终止。

O 有效时按原顺序读当前状态并计算：

```text
C = GetUnitState(O, ConvertUnitState(37))
V = GetUnitState(O, ConvertUnitState(81))
A = GetHeroAgi(O,true)
P = floor((7/C)*900 + V*1000) + A*2.5
if P < 1000: P = 1000
```

状态读取 L133375–133390，运算 L133391–133403。37/81 的“攻击间隔/攻速系数”名称解释沿用 [已有接口证据](combat-and-skills.md)，公式仍保留原编号。**floor 只包住前面的和，敏捷×2.5在 floor 外**；结果可有0.5。源码没有 C=0 防护，不在此凭空补零值规则，也不能以面板攻击力替代这条公式。

随后在 O 的**当前**位置、O 所属玩家下创建 q019，朝向0，BHwe计时生命1秒，UserData存入当时 `IsInTable(O,Tower_ALL)`；最后 `SetRealDamage(q019,T,P)`。L133405–133435。额外包实际来源是 q019，不是 O 或 q018，归属索引仍要保留。它没有再次检查 O 是否继续持有装备、是否近战或是否敏捷最高；这些是生成 q018 时的门槛，不能补成命中时门槛。

P 在**每次 q018 命中时**计算，不在第十次攻击生成波时快照。若塔在飞行中改变攻速/敏捷，会影响随后命中的公式；若塔已死亡，后续命中走归零返回。q018 保存的是 Tower_ALL 索引，命中时重新查槽，不能把它擅自改写成永远指向旧单位的引用。该表在其他生命周期中的删除/复用不属于本函数的保证。

主分派器对 q019 有 `floor(D*1.3)` 漂字（[伤害主流程](damage-pipeline.md)，PC2296）；那一处没有改写 D，不能因此再给本公式追加一个伤害×1.3。
