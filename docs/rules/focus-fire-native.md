## 2. F01：A163准入、前摇和提交

**Web选择，限定这两种塔及沿用同模板的实例：** A163为无目标、自身施法的`evileye`，施法前摇0.3战斗秒，提交后有0.51秒可中断施法后摇。两者不随攻击系数K缩放。缺省Follow Through选0；不因缺省DataE让技能生效后持续锁住其他能力。DataD=1仅控制原有施法特效显示，不阻止移动、攻击或其他施法。

1. **发令准入：** 单位存在且存活，A163已启用且等级1–6，没有暂停、眩晕、沉默或已生效的施法禁用，剩余冷却为0，当前魔法不少于该等级耗蓝。允许自身无敌；自身魔免不单独阻止A163这个准备技能，后续T171是否接受另判。它没有额外敌人/范围要求。
2. 不满足时返回失败，不登记前摇，不扣资源，也不取消已有动作。满足时接受命令，创建唯一的待提交代号，按B05排`当前时刻+0.3`。此时不扣蓝、不启动12秒冷却、不减C、不创建dummy。
3. 接受施法会中断尚未提交的普通攻击前摇；该次攻击开始事件不会回滚。已提交攻击及独立弹道保留；已有攻击冷却继续按共享攻击计时推进。施法过程中不自动再开一次普通攻击。
4. 前摇期间，**后续成功接受的替代命令**（包括停止、移动、攻击或另一施法）使本次待提交代号失效；被拒绝的命令不取消它。普通攻击自动续发不能自行抢占正在前摇的A163。死亡、移除、能力被移除/禁用、暂停/眩晕/沉默也取消未提交施法。
5. 到期条目执行时核代号并重新检查第1步的条件。此时若升级或资源变化，使用**提交时当前合法等级**的耗蓝；条件失败直接结束，不扣蓝、不开冷却。前摇时长仍是先前排定的0.3，不因升级另起一轮。
6. 成功则先将该待提交条目标记已提交，扣一次该等级耗蓝，并把冷却截止设为`提交时刻+12秒`；再同步发出一次原施法生效事件，执行原 `AnySkillStart`。保留其A163前后的装备与技能分派顺序，不能用直接调用A163_Action替代整个入口。事件中后续失败/早退不回滚已经提交的资源。

因此，`Skill_Auto` 的A163即时发令不等于立即成功。它仍继续扫描；若同一调用栈后面有另一条被接受的命令，A163可以在0.3秒提交前被替换。这是明确的Web准入选择，不修改原自动扫描的继续行为，也不替它新增命令队列保护。

提交后0.51秒是可中断恢复：没有新命令时，自动攻击等到后摇结束再恢复；接受新命令可立即截断它，不撤销已经生效的技能、不退蓝或冷却。实际攻击还须满足原攻击冷却等门槛。技能造成的C/R变化本身不额外制造攻击。外部明确的冷却重置仍可按其规则改变A163冷却；本页不新增“Buff期间禁止再施放”的门槛。

## 3. F02：T171同步尝试，B060单独生效

进入 `A163_Action` 后仍严格执行原顺序（main/f114/f1 L88449–88499）：先创建恢复timer、保存索引、`C-=0.2`，再创建q001/T171、设置UserData、发`bloodlust`。**没有bloodlustoff，也不补发这条命令。** q001生命0.5秒，T171初始自动施法关闭；本适配不产生原脚本没有下达的额外自动嗜血。

**Web选择：** 参照已定的临时嗜血适配，q001本次T171的前摇/后摇和耗蓝均取0，同步处理这次目标命令；成功后该dummy的T171冷却1秒。它必须存在、存活、能施法、持有合法1–6级T171且当前冷却为0。目标须存在、存活、友好，中心距离`<=600`，允许无敌，拒绝魔免。不从普通模板另加organic-only条件。命令失败返回false，不删除既存B060，也不撤销A163的耗蓝、冷却、C减少或timer。

成功时先安装/刷新B060，再同步触发一次临时单位的施法生效事件；原 `IsTemp` 分支早退，不触发装备施法连锁。嵌套事件用独立的施法上下文栈保存并恢复触发单位、能力ID、目标与地点；不能让q001覆盖外层A163的事件身份。普通脚本全局变量仍不自动回滚。伤害若嵌套发生，继续使用B03各自的伤害上下文。

**B060的Web生命周期：**

- 每目标同一Buff ID只有一份实例，贡献`+5`到原始攻速R；共享K仍为`clamp(R,0.2,5)`。本页两名英雄及相同原生英雄模板实例按成功时T171等级快照取3/3.5/4/4.5/5/6秒。若直接使用这个T171适配给非原生英雄，普通持续按显式Dur1=60及既有末项续用规则取60秒；不以地图自定义Boss谓词分类。
- 再次成功施加，替换为本次等级/来源/代号，到期设为`现在+本次时长`；不取最大、不叠第二份+5。旧到期条目按代号失效。失败的再次施加不改变原Buff。不同ID的B003和B060保留各自一份贡献，可并存；这是Q24选择，不宣称普通Ablo所有派生在原引擎都如此叠加。
- B060作为可驱散的正面魔法状态，到期、相应驱散、目标死亡/移除时仅删除该实例及其+5；不移除B003或其他贡献，不执行C恢复，不返魔法、不改A163冷却。单独取得魔免、沉默或移除A163技能不主动清除已存在B060；别的技能若有明确清Buff步骤，照该步骤执行。
- dummy在0.5秒死亡/被移除不缩短目标Buff；B060结束也不提前销毁dummy。持续时间与攻击次数无关。单位级暂停不暂停已经登记的Buff/timer战斗时钟；全局暂停则统一停战斗时间。

`Has_A_Item`继续在每次主攻击伤害或居合的既有调用处读取。B060仍在且无强化才调用0.8helper；中途获得强化马上影响后续伤害，失去强化后也立即按后续调用重新判断。它不改变B060的+5、到期或C timer；没有新增对所有法术的统一80%倍率。

## 4. F03：C恢复timer保持原表语义，强制重入不修成刷新

三个状态必须分开保存：原始C、原脚本 `timers[index]/A163_unit[index]`，以及B060实例。单次正常施法的C timer先于B060到期条目入队；两者同一到期时刻时仍各自按B05执行。提前驱散、死亡或T171失败都不取消这个脚本timer。

到期回调按原 main/f114/f0 L88331–88360执行：

```text
i = IsInTable(expiredTimer, timers)
S = A163_unit[i]
DestroyTimer(expiredTimer)
Set37(S, Get37(S)+0.2)
timers[i] = nil
A163_unit[i] = nil
```

`IsInTable`的找不到返回-1由 [main/f7/f7 L50776–50810](../../reference/map-6.25/main.disasm#L50776)确认。**Web选择采用原扩展作者的无效句柄约定：** 无效/已移除句柄的Get37返回数值0，Set37不执行；这不是给缺失配置补0。死亡但尚存在的单位仍有属性，回调照常给它C加0.2；若同句柄复活则沿用已恢复的属性。移除后新建的塔是另一句柄，不能被旧timer自动找来补偿。

当同一合法索引在前次结束前强制再次生效时，源码再次减0.2、覆盖该索引的timer和单位，但旧timer仍在队列。旧timer到期通常查不到自己，取得-1；若 `A163_unit[-1]`不存在，按上述兼容规则读0/写无效，随后清的是-1键，不是该塔真实索引。**不从timer另外保存施法者来兜底，不取消旧timer，不补一遍+0.2，不改成独立效果叠层。** 新timer到期只加回一次，因此一次重叠可能永久留下额外-0.2，直到其他原脚本确实重设C；不能悄悄修复这一来源行为。

- 不把`i==-1`新增为无条件return：原脚本允许-1作为表键。若非Tower_ALL单位的直接调用确实把另一单位写在 `A163_unit[-1]`，仍按实际表项执行；旧timer可能给该表项指向的单位加0.2并清-1键。此类调用不是普通两塔施法，但兼容规则必须可解释，不能一面保留表一面隐藏哨兵碰撞。
- 单位移除只使句柄失效，不提前删除这些脚本表项或销毁timer；到期仍执行清理。重新使用一个Tower_ALL索引也不等于复用原句柄，按表当时的实际覆盖关系处理。
- 每个timer到期回调只执行一次。存档恢复保留未到期的旧timer，即使它已不在`timers`表的值中；不能只序列化当前映射而丢掉旧回调。已销毁timer的重复投递按队列/代号规则失效，不再加0.2。

正常施放不会因为B060已经存在而被本页拒绝：只要原有冷却、魔法和施法状态允许，就能再次走上述流程。强制直接调用生效函数的测试不再扣一次施法资源；经F01成功提交的施法才走那次扣蓝/开冷却，不能把两种入口算成两次扣费。

## 5. 验收时间线

以下C初始1.2，其他原始攻速为1，单位未持强化；所有时刻是战斗秒。普通命令在0秒发出时，提交在0.3秒；“强制生效”例直接以函数执行时刻为0，不包含前摇。

| 场景 | 确定的Web结果 |
| --- | --- |
| 一级，魔法100，正常命令 | 0.3秒扣40，冷却到12.3，C=1.0，B060使R=6/K=5；dummy到0.8；无新命令的施法后摇到0.81；3.3秒C恢复1.2、Buff移除 |
| 发令时魔法39 | 准入失败；不排施法、不改变已有动作或资源 |
| 魔法40时准入，0.1秒被扣1魔法 | 0.3秒提交复查失败；不扣额外魔法、不开始冷却、不改C |
| 0.2秒接受另一命令 | 原A163未提交，取消；原0.3秒条目失效 |
| 0.2秒另一命令被拒绝 | 原A163仍在0.3秒提交 |
| 自身魔免，一级A163正常提交 | 已扣40/开12秒冷却并减C；T171失败，R仍1，无新B060；C仍在3.3秒恢复 |
| 1秒驱散B060 | R立即回1，0.8惩罚停止；C继续1.0直到3.3秒 |
| 1秒死亡但保留单位句柄 | B060立即移除；C timer仍在3.3秒给死单位加0.2，不自动复活它 |
| 1秒移除并创建同索引新塔 | 原timer不补偿新句柄；到期仍清原映射，原失效句柄属性写入无效 |
| 强制一级生效在0和1秒 | C先1.0再0.8，B060仅一份、刷新到4秒；3秒旧timer读-1/无对象而无效；4秒新timer仅恢复到1.0，Buff结束 |
| 强制六级在0秒、一级在1秒 | B060新到期4秒；新C timer在4秒恢复到1.0；旧6秒timer之后查不到自己，无再次恢复 |
| 3秒旧timer先执行，再强制一级生效 | 先恢复1.2再减到1.0；新timer在6秒恢复1.2 |
| 3秒强制生效事件先于旧timer执行 | 先叠减到0.8并覆盖索引，旧timer失配；6秒只恢复1.0 |
| 已有B003+5，再成功B060+5 | R=11/K=5；仅驱散B060后R=6/K=5，B003不变 |

同刻伤害按B05执行顺序看到当时的B060状态，强化资格也当场读取；不能因为两个到期数字相同，就把所有同刻事件统一视为“Buff已结束”。施法前摇取消、Buff到期和timer恢复各有独立代号，保证读档后不重复提交/扣蓝/加C。

保存内容至少包括规则版本、资源与冷却截止、待提交施法及前后摇阶段、原生单位句柄是否仍有效、全部timer实例与队列序号、两张脚本映射（包括可能的-1键）、B060代号/等级/来源/到期/贡献、dummy身份及剩余计时生命。恢复不重新施放，也不按当前技能等级重建原定持续。

## 6. 完成边界

本批已把三项原生缺口写成确定Web行为并用时间线验证；原客户端准入/命令抢占、Ablo同Buff/跨Buff叠加、死亡与失效句柄细节仍没有匹配版本实测，这一事实保留。验证是规格模型计算和来源核对，不是运行魔兽或游戏客户端。没有改写原A163模块或已有索引，没有扩展A180、其他技能的命令规则、驱散能力本身或完整控制系统。
