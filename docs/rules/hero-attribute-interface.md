# 英雄属性接口、属性成长与潜能爆发

基准 `hero-attribute-interface-v1` 明确原生英雄的三围读写、由三围改变的资源、T000/T101及W019。它接续[自然成长](hero-progression.md)，不将44处属性写入所属技能都算作已核完整。机器来源、完整W019字节码及边界探针见 [hero-attribute-interface.json](hero-attribute-interface.json)。

## 已查事实与来源限制

[地图覆盖常量](../../reference/map-6.25/war3mapMisc.txt#L7)明确敏捷攻速系数0.002、敏捷护甲系数/基础均0；智力每点魔法12、每秒回复0.03；主属性攻击系数1.4；力量每点生命15、每秒回复0.1。原模板的[暴雪属性说明](https://classic.battle.net/war3/basics/heroes.shtml)支持主属性影响攻击、力量影响生命、智力影响魔法及属性分量参与回复，但其普通游戏数值不覆盖地图参数。

完整字节码有47处字面`SetHeroStr/Agi/Int`调用，3处为标准包装器、44处为业务调用。每处调用前最后一条指令均把第三参数写成`true`；不是靠反编译变量名猜测。所有调用位置保留在机器表，外围技能条件仍分别核查。

[原生声明及注释](https://github.com/lep/jassdoc/blob/509c14dd0f23e6847516b8a813478974268e9f44/common.j#L17471)表明读写使用整数，getter有`includeBonuses`；其维护者说明降力量可能扣当前生命且不低于1，先减后加因而可能回血。这不能证明本图版本的完整接口。[隐藏新接口的作者示例](https://github.com/Tomotz/wc3-lua-natives/blob/master/jassdocs/extra-jass/reforged-hidden.j)区分按绝对增量与按比例调整资源，但属于较新接口且示例含笔误，不作为旧客户端数值证据。以下明确采用Q24规则，不把`permanent=false`擅解成临时属性来源。

[YDWE原作者的最大资源setter](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Plugin/Warcraft3/yd_jass_api/UnitState.cpp)只直接写最大生命/魔法字段，没有在该函数内写当前值。立即裁剪、后续属性重算保留差额仍是Web定义；与已定[A084资源写入](skill-essence-aura-effect.md)保持一致。

## 属性与资源的Web接口（Q24）

| 操作 | 定义 |
| --- | --- |
| `GetHero*(u,false)` | 当前整数基础属性，即自然成长分量加已实际发生的基础属性修改 |
| `GetHero*(u,true)` | 基础属性加已经生效的装备/技能属性贡献；只读一次有效贡献，不按所有持有图标盲加 |
| `SetHero*(u,n,true)` | 将基础属性设为`max(0,trunc(n))`，保留已有加成；用基础修改差额记录，不重置自然成长表 |
| 无效/已删除/非原生英雄 | 属性getter返回0，setter不做事；自定义`UnitIsHero`不能替代native HERO |
| 原生英雄有效力量变化ΔS | 最大生命变化15×ΔS；对应主属性攻击与生命回复输入同步更新 |
| 原生英雄有效智力变化ΔI | 最大魔法变化12×ΔI；对应主属性攻击与魔法回复输入同步更新 |
| 原生英雄有效敏捷变化ΔA | 攻速贡献变化0.002×ΔA，接入attack-timing-v1；不增加敏捷护甲 |

基础最大生命取模板HP，另加力量贡献及已经解析的独立来源；这136个模板均未写`manaN`，Web明确选择基础最大魔法0，再加智力与其他来源。`mana0`仍是独立初始当前值，不误作上限。最大生命下限1，最大魔法下限0；四个空白敏捷字段依自然成长基准选0。模板Primary仅按大小写归一为STR/AGI/INT；主属性×1.4只进入原生武器基础金额一次，不直接乘所有法术。其他伤害统计/属性额外增伤仍由原脚本独立执行。

本接口的`SetHero*(true)`、自然升级/剥级、T000等级变化，按**实际最大资源变化量**调整对应当前值：`current += newMax-oldMax`。存活单位生命裁剪到`[1,newMaxLife]`，死亡单位仍为0；魔法裁剪到`[0,newMaxMana]`。不因单纯属性改变触发伤害、死亡或复活。各次setter即时可见，不能把先减后加合成一次净变化。

直接`SetUnitState(MAX_LIFE/MAX_MANA,v)`采用另一条已定接口：更新独立直接修改差额，使当前最大值等于合法的请求值，当前资源保持绝对值并立即裁剪；之后属性变化继续保留此差额。它不重复应用上面的“当前值加最大值差”。例如最大魔法1000、当前900，直接设最大1500后仍900；再显式当前+500才得到1400。单纯智力+10则最大和当前分别增加120。

生命/魔法保留小数。普通当前资源写入的死亡/复活事件顺序属于另一生命周期接口；本页不以属性规则绕过它。回复先按旧率结算到事件时间，再处理属性变化；力量/智力回复贡献加入对应输入通道，模板`regenType`（always/night/blight）已由[昼夜与基础回复](night-state-and-regeneration.md)明确分量门槛，其余乘数另核。不能据每点回复系数就声称所有塔全天候恢复。

`permanent=false`没有出现在47处字面调用中，本页不虚构其临时状态撤销规则；若后续发现动态调用再依据真实用途补充。

## T000 属性成长

两本图鉴均有129行，G列均6，H列均“每次学习增加10点全属性”，I列均10/20/30/40/50/60。实际说明相同。原Aamk的DataA/B/C分别对应敏捷/智力/力量，前四级10–40，w3a的Iagi/Iint/Istr补齐五六级50/60；完整合并在机器表。

Q24选择：当前已学且启用的T000等级L提供三项各`10×L`的**加成通道**贡献。六级是各60，不是10+20+…+60。只放在可学列表中不会提供贡献；学习门槛/点数沿用自然成长规格。移除、禁用、降级按实际当前等级重算一次；无额外暴击、随机或施法效果。原学习分派没有T000专用副作用分支。

此贡献对原生英雄生效。幻象是否拥有它由相应创建策略明确，不将本页扩为复制全部装备/技能。保存实际等级与贡献来源，恢复不再加一次60。通用属性接口参与最大资源变化，不能只改面板数字。

## T101 属性成长变体

T101是同名但独立的学习ID，覆盖两书各第8/28/63/68/223/228/248行：众神之王、宙斯、末日使者、末日机甲、变体漩涡、变体精灵和复仇之魂。其[原能力](../../reference/map-6.25/units_abilitydata.json#L34478)与[五六级增量](../../reference/map-6.25/war3map.w3a.json#L7388)的三围表和T000逐字段一致，图鉴全部A–J列140格已双书对照，J均空；也没有T101字面脚本回调。T101采用同一加成/资源/撤销接口，保存自己的等级与付费学习记录，不额外授予T000、不重复写自然成长。

唯一原字段差别是T101的DataD1–4=1，T000没有写；[Ihid元数据](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Component/share/en-US/mpq/Units/AbilityMetaData.slk#L8808)与[编辑器标签](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Component/share/en-US/mpq/UI/WorldEditStrings.txt#L6187)说明它是隐藏按钮。Q24在T101全部六级隐藏已学技能的命令栏图标，仍保留学习/升级入口与属性贡献查看；五六级隐藏值是明确延续选择，原缺失值不改写。隐藏不是禁用属性或不可学习，也不凭这一差异把两技能数值当作两份加成。

## W019 潜能爆发：完整函数

[main/f296/f21](../../reference/map-6.25/main.disasm#L190265)完整102条指令：参数英雄为nil、传入等级为0或不是native HERO则返回；查所有者工人的W019等级，≤0返回。查Tower_ALL槽位及已记旧值，算`floor((0.5×天赋等级+0.5)×传入英雄等级)`；新旧相等立即返回。

旧值非nil且非0时，依次对基础力量、敏捷、智力各减旧值，三个setter均true；再依次加新值，最后保存新值。getter均false，不会把装备绿字写进基础。无旧值时只有后三次写入；天赋消失/传入0会早退，没有主动扣旧值，不能额外添加源码不存在的撤销逻辑。传入等级使用原调用参数，不擅自再读一次英雄等级。

低血例子解释顺序为何有用：假设旧最大1000、当前50，先减10力量后最大850，当前裁剪为1；再加12力量后最大1030、当前181。不能合并成净+2力量后当前80。这个结果是已选Q24属性接口与原六次写入顺序的组合，非原客户端实测。三围之外的技能回调不会因为写入而被自动学习或重新施法。

## 验证与剩余

[审计工具](../../tools/audit-hero-attributes.py)逐处验证47个setter参数；对W019的nil/非英雄/英雄、0/1/20/21/30级、0/1/5级天赋及nil/0/旧值/相等值执行180个原生桩字节码案例，核对早退、写入次数/顺序、最终基础属性和保存值。T000六级三围18个数据点与增量合并一致。没有运行游戏引擎，也不把规格算式当原生测试。

继续核的依赖为：其余技能/装备的实际取得和撤销条件、完整换皮与幻象状态转移、昼夜/荒芜地表与回复乘数，以及通用死亡/复活事件。此处没有把44处写入的外围技能批量升级为完成。
