## 已确认的差异

[N054_57_Get_probability，Lua L71678–71688](../../reference/map-6.25/main.readable.lua#L71678) 对应完整字节码 **`main/f176/f1` L113292–113319，10 条指令**：

```text
roll = GetRandomInt(0, 100)  // 包含两端，共101个整数
return roll < 15
```

字节码 [L113308–113317](../../reference/map-6.25/main.disasm#L113308) 明确加载 0、100，并以 `lt 1 r0 k3`（k3=15）构造返回布尔值。返回 true 的结果为 0–14，false 为 15–100。因此四种形态的原概率均为 **15/101 ≈ 14.851485%**，而图鉴和实际说明均为 **15%**。没有按形态、模式或技能等级切换阈值的分支。

**Q36 已选准确 15/100**：Web 在原 helper 调用位置抽一次均匀整数1–100，以 `roll<=15` 判定。1–15成功，16–100失败；四个 ID 共用这一规则，不分别抽样。原 `GetRandomInt(0,100)<15` 仅作为来源对照，不再作为 Web 执行概率。

准入条件和先抽样后查技能的顺序保持。到达该段且攻击标记非0，即使四个技能都没有，也仍抽一次；公共流程已早退或攻击标记为0时不抽此项。成功后仍只调用一次原效果，不因多持技能多抽。

## 实际入口、公共早退与抽样时点

入口为 `anyUnitDamaged` / `main/f291/f1` 的 **PC1761–1803**，[字节码 L164351–164394](../../reference/map-6.25/main.disasm#L164351)，对应 [Lua L112164–112208](../../reference/map-6.25/main.readable.lua#L112164)：

1. 查询 `EXGetEventDamageData(2)`，必须非 0，即攻击标记的伤害事件；并非只发出攻击动作就抽样。
2. **先调用一次概率 helper**。返回 false 立即跳到下一技能段，不读四个 ID。
3. 返回 true 后，依 N054→N055→N056→N057 的顺序检查**实际伤害源 S（r0）**的能力等级是否大于 0；任意一项满足即短路，调用一次 `N054_57_Action()`。
4. S 与归属塔 O（r2）是不同概念，不能擅自改用 O 查技能。即便四技能全无，只要到达本段且 attack 非 0，仍已经消费了这次随机数。多持一个 ID 也不会多抽或多调用一次。

此分支没有自己的非幻象检查、Game_Mode 分支、额外敌对玩家检查、耗蓝/冷却检查，也没有“此时事件伤害必须仍大于 0”的二次检查；这些不能因为提示写“攻击敌人”便自行加进概率入口。范围效果如何选取敌人属于效果函数的后续核查。

在到达此段之前，保留 [伤害主流程](damage-pipeline.md) 的公共条件：

| 公共条件 | 字节码位置 | 对此概率入口的影响 |
|---|---|---|
| q004/q005 来源先写事件伤害为 0；随后初始 D==0 返回 | PC1–27；[L162494–162522](../../reference/map-6.25/main.disasm#L162494) | 不进入本段、不抽这次随机数 |
| 实际来源 q039 旁路至 PC3964 | PC98–105；[L162598–162605](../../reference/map-6.25/main.disasm#L162598) | 跳过包括此段在内的主体；不是函数立即返回 |
| attack 非 0 且实际来源带 B177 | PC198–214；[L162702–162718](../../reference/map-6.25/main.disasm#L162702) | 先执行 A164_T322_Action，随后返回，不抽此段随机数 |

初始零伤害判断只有这一处。若后续已核流程把 D 改成 0，不能在 Web 新增一个“任何时候伤害归零就提前返回”的全局规则。此处保留公共流程及现有调用顺序，不重做其余技能内部效果。
