# 虚空 A192

基准 `void-effect-v1`。完整核心为 [main/f137/f0，195条指令](../../reference/map-6.25/main.disasm#L100382)，机器表见[skill-void.json](skill-void.json)，两书原值见[night-workbook-check.json](night-workbook-check.json)。本页与[暗夜猎影](night-state-and-regeneration.md)合起来覆盖暗夜魔王三项技能的指定模块；通用换皮、幻象和全部伤害子模块仍单列。

## 金额与入口

两图鉴 `塔技能!F310:I310`、`F340:I340` 一致：六级基础伤害 **1000/1800/2600/3400/4200/5000**，均加**施法者最大生命×13%**；耗蓝 **20/35/50/65/80/100**，冷却8秒，降低移速50%、持续3秒，夜间变范围伤害。原核心、实际提示和显式对象数值与此相符。

核心按能力等级6→2分别取对应基础值，其余值默认1000，包括直接调用时等级0。随后读取一次施法者最大生命并算金额、获取一次目标地点，最后才调用 IsYeMoNightBuff 选择白天或夜晚分支。不因夜晚自动把基础伤害翻倍；夜晚的×1.8/×2.5是伤害主流程中的另一环节，继续在其原位置执行。

[施法入口 main/f291/f14 PC1207–1217](../../reference/map-6.25/main.disasm#L171322)传入施法者与实际单位目标。[自动施法优先级97](../../reference/map-6.25/main.disasm#L177266)先检查A192就绪，在1000范围优先 hasHero，未找到才重新枚举并找 hasMon，取B04首个符合者；发零秒目标 `thunderbolt` 后结束技能扫描。hasHero是地图既有特殊目标谓词，不能改为任意原生HERO。

Q24正常施法准入为存在、存活、技能启用且等级1–6、无施法锁、足够魔法、冷却结束；目标为存在存活且可见的敌方单位，排除Aloc与无敌，允许地面、空中、建筑和魔免承受物理核心。射程1000，实际英雄0.3秒前摇，提交时重检、扣蓝并起8秒冷却，再一次派发原技能事件。前摇取消无消费；提交后子效果失败不退款。ANcl外壳不再制造第二笔法术伤害。

## 白天与夜晚的实际顺序

白天调用 SetPhyDamage，发单个 `attack=false,ranged=false,HERO/NORMAL` 物理包。同步伤害返回后播放视觉，再于**先前保存的目标地点**生成q001，挂一级T213，生命期1秒，先复制施法者塔槽到userdata，再向原目标发 `slow`。即使前面的伤害已杀死目标，源代码仍尝试创建和发令；原生准入可以拒绝，不能提前删掉脚本调用。

夜晚取当时目标x/y，以该点为中心、半径350调用 SetPhyDamagePoint，类型与白天相同。该包采用[范围伤害基准](native-area-damage.md)的敌对目标集合，而后面的减速枚举另外只查 **Player(11)且生命>0**。两者不是同一个过滤器，也不共享同一份目标快照。

这里源函数传给范围助手的延迟来自全局 `delaytime`。全文只找到此处读取，没有静态赋值；原生绑定遇nil怎样转换未证。**Q24仅在该调用边界将缺失real延迟规范为0**，不是伪称源脚本写了0或修出一个隐藏变量；若未来调用环境提供有限非负值，照值传入。零延迟范围同步完成全部伤害，才继续视觉和减速枚举；正延迟则伤害按B05延后，当前减速枚举照原代码立即继续。

夜晚减速枚举在伤害调用返回后进行，B04稳定顺序，中心350闭圆，逐个检查Player11及当时生命。每个通过者生成一只q001，位置仍是最初目标地点，挂一级T213、生命期2秒、先写塔槽再发slow。没有额外魔免/建筑预过滤；这些目标也会收到一次发令尝试，再由子技能决定是否接受。前一个命中引起的新状态会影响后续检查。

G071仅更换两分支的特效资源与缩放；不更换伤害、半径或控制值。day的 `orign` 附着点拼写按原记录保留为美术输入，不用它推导战斗差异。原核心未释放取得的地点；Web将地点保存为值，不引入魔兽句柄泄漏。

## T213减速的局部接口

实际对象为Aslo、B168、耗蓝10、射程500、普通/英雄持续均3秒、DataA移动减速0.5；无DataB攻击减速和物编覆盖。模板Ubertip仍写25%攻速、60%移速、60秒，显然与本技能图鉴和对象不符，不能据此额外给25%攻速下降。

按Q24，T213只减移动速度50%，不另减攻速。q001初始魔法1000，成功提交扣10；采用零前摇，但仍排B05命令提交，保证原脚本先创建、写userdata、发令的顺序。无弹道，射程500；选可见敌方地面/空中非建筑，排除Aloc、隐藏、无敌及魔免。对源代码直接发出的非法目标只拒绝子技能，不倒退已经完成的物理伤害。

沿用同一个N535法术屏障状态；若生效时屏障可用，则阻断本次减速，费用/冷却已消耗。它不拦截已经由原塔发出的物理包。成功时单份B168取最新到期时间，不叠加多份50%；普通负面驱散、显式移除、死亡/删除、获得魔免或到期清除。控制单位的暂停不冻结Buff时间。其他技能若也产生B168，需按自己的已核规格接入，不能据本页消掉其效果。

## 验证与保存

`python3 tools/audit-void.py` 用原字节码运行114条接口桩案例，涵盖等级0–6、昼夜、两种皮肤、子命令成功/失败、伤害先杀目标、边缘/圈外/友军/已死/魔免目标，以及原全局延迟透传。检查夜晚先完成范围请求才枚举、白天致死仍尝试slow、userdata一定先于发令。它不模拟完整游戏或证明原生绑定行为。

存档在同步事务结束后保存；未提交前摇、排队的零秒子技能、临时单位生命期、B168到期和正延迟范围包均接入B05。读取恢复不重复施法、扣蓝或创建q001。金额是核心调用时快照，夜晚状态也只在核心对应位置读取一次；不能用恢复时的最新属性重新计算历史包。
