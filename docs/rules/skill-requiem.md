# A001 魂之挽歌：二十道波、逐次灵魂读取与原生边界

本批完整核查 A001 的两个函数及其必要的 A002 灵魂计数写入、临时单位创建、单体魔法伤害、自定义 Boss 判定和死亡列表清理；另核实际施法入口、自动施法分支、q014 伤害桥接、击杀归属片段。**未发现本批范围内需要新裁决的图鉴冲突。** 原生波形和施法时序按 Q24 单独定义 `requiem-native-v1`，不冒充原客户端实测。[机器表及验证案例](skill-requiem.json) 将来源事实与 Web 选择分开。

下文 `B` 指 [main.disasm](../../reference/map-6.25/main.disasm) 的文件行号；`PC` 是相应函数内指令序号。阅读稿只作定位，条件与分支以字节码为准。

## 施法入口与固定二十次同步发令

主分派注册 Player(0/1/2/3/11) 的 `EVENT_PLAYER_UNIT_SPELL_EFFECT`（main/f291/f35，B179727–179797）。`AnySkillStart` 的公共前段先处理可能的形态停留逻辑；临时单位或 T033/A040/A070/A210 在装备施法分派前早退。A001 正常通过后，先执行 `Item_Skill_Action(GetSpellTargetUnit())` 和 `WAbility_initAbility()`，再按能力 ID 调用 `A001_Action()` 并 return。证据 main/f291/f14：B170000–170074、B170172–170179，PC162–169。不能跳过装备回蓝、施法触发等既有顺序；本页不递归全部装备或全局技能前置效果。

`A001_Action`（main/f15/f0，B60484–60587）只有两个条件：

1. `i=IsInTable(C,Tower_ALL)`；若 i=-1，令 i=`#Tower_ALL+1` 并存入 C。**此处没有同步写 C 的 userData**。
2. 读取当前 C 类型，G053 使用 T135，其余使用 T001。皮肤选择只发生一次，不根据之后的类型变化重新选择已创建波。

之后用数值 for 循环 j=1…20，步长 1，**在同一个 Lua 调用中同步执行**：

- 每次重新取得 C 的当前位置；创建同拥有者的 q014，朝向为绝对世界角度 `18*j`，即 18°、36°……360°，不是加在施法者朝向上。
- 给 q014 添加 T001 或 T135，技能等级固定 1；设置 BHwe 限时生命 3 秒。
- 设置 q014.userData=i；取得 **q014 自身位置**，发出 `carrionswarm` 地点命令，目标点也是它自身位置。
- 删除临时 location。命令返回值丢弃，无发令失败补发。

循环为 PC26–65，B60545–60586；每次创建/发令为 PC30–64，B60550–60584。创建辅助函数是 main/f7/f20，B51457–51509，顺序为创建单位、添加能力、设置等级、设置限时生命；显式传 q014，未传才默认 q001。

A001 没有随机抽取、灵魂门槛、施法者存活复查、周期计时器、返回波、蓄力变量或取消回调；也没有 TxShow 门槛。20 次同步发令不证明原生弹体全部在同一个引擎时刻命中。所谓“一轮”在此只指一次 SPELL_EFFECT 的这 20 道波，不能实现为每 0.6 秒再打一轮。

## 实际自动施法条件

沿用 [完整自动施法规则](autocast.md)，A001 是扫描第 23 块：非幻象攻击 Player(11) 的单位时，攻击者需要 B012 自动施法 Buff。扫描走到本块且 `ready(A001)` 为真，再在攻击事件入口采样的攻击者位置周围 700 枚举；找到首个 owner=Player(11)、生命>0 的单位，就直接发无目标命令 `evileye`。选中的单位只证明附近有怪，**不作为 A001 目标传入**。

`ready` 要求 A001 等级>0、剩余冷却严格等于0、当前魔法≥当前技能耗蓝。不检查灵魂数、原生施法接受状态或命令是否成功。发令后结束技能扫描，仍执行公共道具尾部；失败不改试下一技能。证据 main/f291/f27：B174093–174118、B174757–174786；main/f7/f39：B52213–52272；`hasMon` main/f291/f28：B179252–179311。主线、无尽、深渊在本块没有局部倍率；深渊移除 T033 的既有模式流程仍适用，不能据此保证该模式始终自动施法。

## 每次命中：先载体事件清零，再产生源塔魔法子事件

T001/T135 原生打中单位时，实际来源 S 为 q014。主伤害函数先执行原有初始零伤害早退、归属解析、前置装备和前序技能分派；q014 是临时单位，归属 O 读取 **此时的** `Tower_ALL[S.userData]`。到 main/f291/f1 PC334–347（B162844–162857），仅当 O 非 nil 且 S 类型为 q014，调用 `A001_Damage(O,T)`。没有额外 A001 等级、普通攻击标记或 Boss 类型条件。初始载体事件已经为0时，会在 PC27 早退，根本不到此处。

`A001_Damage`（main/f15/f1，B60589–60632）的全部行为：

```text
当前载体事件伤害 = 0
i = IsInTable(O, Tower_ALL)
n = A002_table[i]
若 n 为 nil 或 0：只从本函数返回
否则：SetMagicDamage(O, T, n*20)
```

`SetMagicDamage`（main/f7/f34，B52062–52088）直接调用 `UnitDamageTarget`，参数为 `attack=false,ranged=false,ATTACK_TYPE_NORMAL,DAMAGE_TYPE_MAGIC,WEAPON_TYPE_WHOKNOWS`。子包实际来源是 O，原始金额为 **该次命中时** 的 n×20，重新经过自身的减免和完整伤害分派。遵循 [B03](web-baseline.md)：子事件同步完成后恢复父事件上下文；父事件继续从 A001 调用之后运行，不能新增“清零后全局早退”。后续地图逻辑仍可能再次改写父事件，不能保证整个载体事件的最终值永远为0。

因此不能把两层事件压成一个直接扣血值。外层原生10点不是额外固定附加伤害，内层20×灵魂数也不是最终生命损失。O 为 nil 时该桥接完全跳过，**连这里的清零都不执行**；不能用本技能说明擅自替整个伤害流水线补清零。

若同一目标实际产生 k 次通过桥接的命中，原始魔法子包之和为 `Σ(20*n_hit)`。n 在期间恒为100、实际命中3道波时为6000；n 依次为10、11、21时为200+220+420=840。不是固定 `20×20×施法时灵魂数`。每个命中的装备/模式修正、目标死亡及其他效果还会改变最终结果，见 [主伤害流水线](damage-pipeline.md)。

## 灵魂计数的必要依赖：A002

A002 模块初始化 `A002_table={}`。全主程序中对这个命名全局的显式引用只出现在 A001 读取与 A002 初始化/写入；本批未发现施放 A001 消耗或清空灵魂。A002 的原图实际 Ubertip 明写神杖将上限翻倍，不能只看未写这句的学习提示：[campaignabilitystrings L31–42](../../reference/map-6.25/units_campaignabilitystrings.txt#L31)。

死亡分派用 `GetKillingUnit()` 取实际杀手 K；若 K 是临时单位、原生召唤物或幻象，C=`Tower_ALL[K.userData]`，否则 C=K。执行前序死亡效果后，C 的 A002 等级>0 才调用 `A002_Action(C,dead)`。这处调用外没有包裹“只限某模式/只限 Player(11) 死者”的条件，不能把前面的掉落分支条件套在收魂上。证据 main/f291/f9：PC290–314，B168708–168733；PC389–400，B168814–168825。前序 `DeadToRemoveUnitAndTrig`（main/f7/f3，B50494–50586）清掉怪物数组及伤害触发器；名字含 Remove，但函数没有 `RemoveUnit`，不应据名把 corpse 句柄先销毁。

`A002_Action`（main/f16/f0，B60658–60834）完整规则为：

- 取得 **A002 自身等级**；自定义 `UnitIsHero(dead)` 为真则本次增加10魂，否则1魂。这里的 Boss 判据是 N534等级>0 **且** `UNIT_TYPE_SAPPER`，不是原生 HERO 标签，也不是名字含 Boss（main/f7/f45，B52444–52480）。
- 以 `IsInTable(C,Tower_ALL)` 作索引。原值 nil 时直接存入完整的1或10，**跳过等级上限和神杖检查**；原值0不是 nil，会进入上限分支。
- 已有值时，A002 1–6级上限分别为200/250/300/350/400/500；其他等级的局部上限保持0。`Has_A_Item(C)` 为真将上限×2。该判据是 C 在 A111_113_A 值列表中，或持有 i310，不能简化为只查物品。
- 已有魂数≥当前上限则直接 return，不将旧魂数截断。否则本次增加量裁剪到 `cap-old`，累加魂数。
- 对实际增加的魂数 d，将 `ConvertUnitState(19)` 改为原值+3d。19 对应第一攻击的附加伤害字段，不是本次随机普通攻击伤害，字段证据见下文。
- 仅 C 类型为 G053 且通过上述计数/增加路径时，在死者位置创建默认 q001，添加 T136一级、限时生命1秒，向 C 当时位置发 `clusterrockets`。已经封顶早退时不发此命令；没有 TxShow 开关或第二次魂数变更。

例如1级198魂击杀自定义 Boss，实际只增加2魂和6附加攻击；带神杖6级900魂移除强化后，下一次击杀因900≥500直接返回，已有900魂仍可给 A001 提供每次18000的原始魔法子包。这是脚本补充，不是将神杖伤害改成直接×2。

没有 A001/A002 内部的模式倍率或额外皮肤伤害分支；G053 的两种差异分别是发波改 T135、收魂附带 T136。索引仍是动态表查找，**本页不擅加换皮时转移/清零灵魂规则**；全局 Tower_ALL 替换生命周期需由相应变身调查负责。

## Q24：requiem-native-v1 的明确 Web 定义

以下均是**查证后未能还原的底层细节的 Web 选择**；没有替换 A001/A002 已核脚本条件和伤害时点。沿用 B03 事件栈、B04 稳定单位顺序、B05 战斗微秒时间与同刻队列。

**施法。** A001 为无目标技能。命令被接受时要求施法者存在、存活、当前可以施法、技能1–6级、冷却0、魔法足够。采用两种英雄共同的0.67秒施法点；到提交时重查这些条件，以提交时等级读取耗蓝/冷却，扣费并启动冷却一次，再派发 SPELL_EFFECT。之前取消/失效不扣费、不冷却、不生成波。之后的0.6秒跟随时间允许停止、移动/攻击命令或施法中断结束；不能退费或召回已生成波。5–6级未显式提供的 Channel 字段在本范围沿用0.6、evileye、无目标；不推广为其他技能的继承规则。castbsw=0.4仅保留作动画字段，不在此额外叠加一段伤害延迟。当前 canCast 状态由已核控制/技能适配器提供，未查完的控制来源不在本页臆造。

**发波与几何。** 每个自身位置 carrionswarm 命令被本适配器接受为一道波，q014 的魔法费用和施法点均选0；通过 B05 零秒事件按 j 顺序入队，在当前脚本调用栈返回后发射。起点为发令时 q014 的位置，方向取其脚本朝向，即使目标点与起点重合也不重新求角度。波前运动1秒，速度800；与原3秒 q014限时生命分开保存。

本范围选择线性扩张的横向波前。以起点为原点、波方向为局部x轴，经过 t 秒时：

```text
0 <= t <= 1
s = 800*t
波前 = {(x,y): x=s 且 |y| <= 20 + 0.35*s}
```

只计算单位二维中心点，边缘包含等号，不加模型或碰撞半径；终点为 x=800、半宽300，不额外向前延伸。每个单位与同一道波最多命中一次，不同波可各命中一次。动态单位按运行时分段连续直线轨迹求首次有效接触，不能把一帧前后都没落在线上的单位漏掉；瞬移是离散位置改变，不沿瞬移路径扫过碰撞。接触后不留下后方持续伤害区，不能因单位后来进入已扫过范围而补打一击。

接触时间按 B05 换成整数微秒排队；同一时刻的波按创建序号、同一道波的目标按单位创建序号处理。发射与初始接触均在本次 SPELL_EFFECT 调用栈返回后处理，不在创建20个载体的循环中插入伤害回调。

**目标与载体。** 接触时及提交前要求单位仍存在、存活、是载体当前拥有者的敌方、生物且为地面或空中单位；排除守卫、Aloc、无敌、魔免。不追加视野、隐形、高差、路径阻挡或“Boss免疫”条件。原生10点载体包明确采用 `false,false,NORMAL,MAGIC,WHOKNOWS`，先经过适用减免，再执行既有完整伤害事件；若初始已为0，保留原主流程早退。通过 q014 桥接后另发20×灵魂数的源塔包，仍不能合并。

每道波的原始载体伤害预算为9999999。对一次合格接触先取 `d=min(10,remaining)`、扣除 d，再提交载体事件；事件后被清零不返还预算。最后可能只剩9点载体包，但只要到达桥接，其魔法子包仍为完整20×魂数，不按9/10缩放。已提交载体包就记录这道波已命中该单位；不合格的接触不消费预算或命中记录。已发波不因源塔后来停止/死亡自动召回，归属仍按 q014.userData 动态读取；源塔表槽缺失时保留原桥接跳过行为，不凭空补成保证0伤害。
