# 装备静态力量、敏捷与智力

`item-attributes-v1` 核定图鉴装备页中 **86 件物品**的 AIab 静态三围。84 件直接挂载，魔焰之心的两种形态通过同一法术书能力间接挂载。39 个 AIab 别名有 180 次出现（直接 178 次、间接 2 次），29 件物品在自身列表中有重复别名。46 本制作书写有成品三围，持有制作书不获得这些属性。[逐项数据与验收](item-attributes.json)

## 对象和图鉴来源

## Web 挂载和属性接口（Q24）

1. 由生命周期确认实际挂载的适格原生英雄，每个物品实例只登记该物品的最终三围向量一次。两个获准持有的实例各提供一份。源列表中重复出现的同名别名保持顺序，计算采用逐物品核定好的向量。原归属、资格、同类互斥仍按原回调。入槽先完成三围与派生重算再进 PICKUP。移出先撤销该实例再进 DROP，脚本可读当前操作实例的物品类型和充能。换槽和满包失败不改变贡献。消耗所有材料会依次触发真实移出，成功交付的成品在自身 PICKUP 前入账。读档直接从恢复的挂载实例重建属性向量，使用已保存的资源状态和脚本偏移，跳过事件及加成变化的当前资源搬移。[物品生命周期 L01、L02、L07](item-lifecycle.md)
2. 装备三围进入英雄属性的加成通道。原生 `GetHero*(false)` 读取基础，`GetHero*(true)` 加有效装备和技能。每次 `SetHero*(...,true)` 只改基础偏移，原基础值的读法和写入时机照脚本。例：古尔丹之颅 I246 的智力分支先读无加成智力，再把随机增量写入基础。移除后只失去固定 40 智力。斩敌巨斧的脚本同时使用有效力量和基础敏捷，这两次读取保留各自的参数。[属性接口](hero-attribute-interface.md) · [I246 分派](../../reference/map-6.25/main.disasm#L144324) · [I246 三围分支](../../reference/map-6.25/main.disasm#L129556) · [斩敌巨斧属性读取](../../reference/map-6.25/main.disasm#L133955)
3. 力量每点使生命上限增加 15、生命回复率输入增加 0.1；智力每点使魔法上限增加 12、魔法回复率输入增加 0.03；敏捷每点增加 0.002 攻速贡献，护甲系数为 0。先按原回复率结算到事件时间，再改变回复输入。属性引起的当前值变化等于实际最大值变化，存活生命裁剪到 `[1,新上限]`、魔法到 `[0,新上限]`，死亡生命保持 0。此处沿用属性、昼夜和攻速接口。[属性与资源](hero-attribute-interface.md) · [昼夜与回复](night-state-and-regeneration.md) · [攻击时序](attack-timing.md)
4. 有效主属性每点贡献 1.4 到 W01 的 H，一次进入武器基数 X，并由已生效的百分比 P 放大。普通包使用本次武器骰子，字段视图用各自的取整边界。固定武器攻击 F、A069 的 G 以及写字段形成的 J18/J19 保持原通道。例如 B=100、力量主属性 100、F/J/G=0、P=50%、本次骰子 D=6，普通包初始为 369；装备 +4 力量后为 377.4，增量 8.4 来自 `4×1.4×1.5`。[武器 W01–W03](weapon-field-source-notes.md) · [固定攻击 F](item-flat-attack.md)

## 充能成长的交接

`ItemUnitDeadAction` 按优先级在每个成长类别内选一件。生命类依次 i332、i330、i145、i147，前 3 件每次 +2 血能，i147 每次 +1，随后直接写生命上限，每点血能 +4。魔法类依次 i220、i327、i218，i220 每次 +2 魔能，后 2 件每次 +1，随后直接写魔法上限，每点魔能 +3。原击杀调用的载体选择与前置流程保持。i220/i218 仍走上述成长路径，其背包槽没有本组 AIab 三围。[优先级与写入](../../reference/map-6.25/main.disasm#L146114) · [数据表](../../reference/map-6.25/main.disasm#L142710) · [调用](../../reference/map-6.25/main.disasm#L168947)

在原 PICKUP 内，符合成长分支条件时用现有正充能增加直接资源上限；在 DROP 内用**移出时**的充能扣减。直接上限写入保持当前绝对值后裁剪，后续三围重算保留这笔独立差额。单独修改物品充能只变计数器。合成由原事件传递实际充能，适配层只在实例挂载时接入静态三围。魔焰之心切换保存槽位和充能，照原次序移除旧形态、交付新形态。以掠夺者之斧 7 血能为例，静态 40 力量先使上限和当前生命各加 600；入包脚本再直接增加上限 28。恐鳌之心等物品还有独立的固定生命或魔法能力，分别按其所属效果接入。[拾取增长](../../reference/map-6.25/main.disasm#L144824) · [移出增长](../../reference/map-6.25/main.disasm#L147316) · [合成传递](../../reference/map-6.25/main.disasm#L145115) · [魔焰之心切换](../../reference/map-6.25/main.disasm#L135003)

## 验收与范围

[审计工具](../../tools/audit-item-attributes.py) 用 `--write` 生成机器表，用 `--check` 重新读取两本图鉴和原表并比较结果。20 个探针使用原事件、合成、成长击杀和形态替换字节码，加上 Web 属性及物品接口测试桩。覆盖同类型实例叠加、共享别名差异、主属性百分比联动、脚本改基础智力、满包、资格拒绝、扣材再到成品、增减生命和魔法、读档和低生命裁剪。测试记录的资源值只叠加本组静态属性与相关脚本写入，其他装备能力由各自规则接入。

本组的 Web 选择已有可复查验收。匹配版本的 Warcraft 客户端尚未运行，原生同名叠加、法术书子能力与资源更新时序仍可用相同载体和样例实测。普通载体资格、熊灵与幻象的完整继承、死亡背包处置，以及固定生命／魔法、装备直接攻速、回复倍率、主动与被动业务效果，继续按各自模块处理。
