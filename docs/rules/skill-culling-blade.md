# A057 淘汰之刃：阈值、成功分支与回调

本批核完 A057 主函数和冷却回调的全部条件与跳转，以及必要的有限伤害包、目标发令队列和深渊伤害回调；复用已经核过的主伤害分派与自动施法入口。**范围不包括全部怪物／装备被调函数或原生技能引擎。** 没有发现可另行裁决的数值冲突；福利小鸡免伤属于模式交互补缺。索引、原字段和验证算例见 [skill-culling-blade.json](skill-culling-blade.json)。

本文 `B` 行号指 [main.disasm](../../reference/map-6.25/main.disasm)，PC 指对应函数从 1 开始的指令序号。阅读稿只用于定位；特别是金币目标的失败分支已按字节码纠正，不能照搬反编译的嵌套结构。

范围物理包可复用后续已定的 [area-damage-v1](native-area-damage.md)；下文的 native 筛选边界不撤销该 Web 选择。原图实际技能提示 [L809](../../reference/map-6.25/units_campaignabilitystrings.txt#L809) 也明确写有神杖失败累计，补强图鉴学习说明未收录这项机制的来源；精确累计仍按字节码的 `r×(c+1)`，不将“翻倍（可叠加）”自行推为 `2^c`。

四个英雄的 `heroAbilList` 均含 A055、A056、A057、T000、P000；只有武圣 G067 有成功特效模型分支，数值共用。

## 2. 进入施法与取值时点

`AnySkillStart` 在 `EVENT_PLAYER_UNIT_SPELL_EFFECT` 触发，先经过公共临时单位／技能过滤，再调用装备施法分派和 `WAbility_initAbility`，随后 A057 分支调用 `A057_Action(GetSpellTargetUnit())` 并 return。见 `main/f291/f14` B169999–170076、B170428–170436（PC393–401）。因此目标阈值读取发生在这些先行效果之后。注册玩家与公共过滤复用 [item-hex-proc.md](item-hex-proc.md)；原生命令接受、耗蓝时点和施法前摇不由这一调用独自证明。

自动施法属于 [完整自动施法调度](autocast.md) 的第 27 个顺序分支：有 B012，A057 已学、剩余冷却严格为 0、当前魔法不少于当前级消耗，才枚举施法者采样位置周围 **550**。`hasMon` 取首个 owner=Player(11) 且生命>0的单位；不按最低生命或阈值挑选，也不排除 Boss／金币怪。选中后登记 **0 秒一次定时器**，回调对保存的目标句柄发 `militia`；本轮结束技能扫描，仍会走道具尾部。A055、A056 在 A057 之前，可能先占用本轮技能尝试。

证据：`main/f291/f27` B174881–174911；就绪函数 `main/f7/f39` B52213–52272；`hasMon` 为 `main/f291/f28` B179252–179311；排队及回调 `main/f291/f25` B173683–173719、`f23` B173599–173639。回调不重查目标存活、距离、冷却或魔法，不读取发令结果。它清除来源、目标、timer 槽，保留命令字符串槽。深渊出战会移除 T033，不能由普通战场自动施法入口推定深渊仍开 B012；手动施法进入相同 A057 事件分支。

## 3. 主函数：成功判定与失败累计

`main/f51/f1` B69018–69282，共 **190 指令、14 条条件、29 次调用、1 个 return**。定义 C=GetTriggerUnit()，T=传入目标，i=IsInTable(C,Tower_ALL)，c=A057_Count[i]。

按顺序读取 T 当前生命 H、C 最大生命 M、整数随机 r∈{1,2,3,4,5}、C 当前位置。若 c 非 nil 且 c>0，令 r←r×(c+1)。然后只有以下条件同时满足才进入“成功分支”：

```text
H < M × r
目标类型不是 m999
目标类型不是 m998
```

相等失败；每次实际进入函数只抽一次 1–5；没有单独的固定成功概率、Boss 总排除或深渊总禁用。给定正 M 与计数 c，成功概率等于满足严格不等式的整数个数除以 5。例如 H=2M、c=0 时抽到 3／4／5 成功，概率 60%；H=5M 时为 0%。字节码 PC25／29（B69109／69113）控制计数倍率，PC36／44／52（B69121／69129／69137）任一失败均跳 **PC140**。

失败分支先以 C 对 T 发一次 `M×0.8` 的物理伤害包。若 TxShow=true 才显示 SpiritLink 失败特效。之后若 `Has_A_Item(C)` 为真，把 nil 计数初始化 0 再加 1；否则不改计数。`Has_A_Item` 是单位出现在 `A111_113_A` 值列表中 **或** 持有 i310，不能简写为仅持 A 杖。失败计数没有本模块内上限；**已有正计数参与下次阈值时不再要求当前 Has_A_Item 为真**。

“成功”是这次阈值／ID 分支的名称，**不是伤害后检查目标是否死亡**。失败伤害碰巧杀死目标，仍走失败奖励和累计；成功伤害被别的规则抵消，仍走成功奖励和清零。金币目标即使只有 1 点生命也走失败分支，且符合 Has_A_Item 时同样累计。计数在其他塔索引生命周期中的清理，本批未证实。

## 4. 成功分支的真实执行顺序

1. 快照 T 的坐标、最大生命 Q，将嗜血等级设为 1。
2. 调用 `UnitKillUnit(C,T)`。它在 C 位置创建 owner 相同的 q025，赋 `GetUnitUserData(C)`，生命期 0.5 秒；由 q025 发 **10,000,000 点原始神圣伤害**，不是直接调用 `KillUnit`。证据 `main/f7/f44` B52387–52442、`f35` B52090–52116。
3. 若调整后的 r>1，显示阈值倍率漂字。创建成功特效：默认 Eff_FW_3.MDX，仅 TxShow=true 且 C=G067 时换 Eff_FW_4.MDX。**TxShow=false 并不会取消成功特效创建**，只影响该换模条件；效果生命期 0.8 秒、缩放 1.3。
4. 用 C 发 `UnitDamagePoint`：delay=0、radius=500、中心为步骤 1 的坐标、原始伤害 Q。不是在斩杀后重新读最大生命或位置。它没有事后存活检查，也没有额外把 T 从范围伤害中剔除；native 枚举行为另有边界。
5. 若 i 槽已有冷却返还 timer，先销毁；新建 **0.1 秒一次** timer。随后仅当 c 非 nil 且 c>0 才清成 0。
6. 最后发嗜血请求，详见下一节。

失败与范围物理包均为 `attack=false,ranged=false,ATTACK_TYPE_HERO,DAMAGE_TYPE_NORMAL,WEAPON_TYPE_WHOKNOWS`；q025 包为同样两个 false、`ATTACK_TYPE_CHAOS,DAMAGE_TYPE_DIVINE`。**10,000,000 是入口原始量，不是所有状态下的最终扣血**；三个包继续走 [主伤害分派](damage-pipeline.md)。来源 q025 的归属按用户数据恢复到塔，装备分派仍区分实际来源与归属，不能把整个事件当普通 C 的伤害。

## 5. 冷却、嗜血与反击螺旋加成

冷却回调 `main/f51/f0` B68932–69016 共 **51 指令、1 条条件、13 次调用、1 个 return**：根据过期 timer 在私有表中的槽找到当时 `Tower_ALL[i]`。只有该值非 nil 时，读取 A057 的状态 1，然后写回 **该时刻剩余冷却×0.5**。它不是减去基础冷却的一半，也不是重置为 0；例如回调当时剩 8 秒则写 4 秒。随后由 1 秒生命期 q001 施放 T220 1 级 `innerfire` 给塔。无论塔是否 nil，最后都销毁 timer 并清槽。

再次成功会替换待执行 timer；失败不取消旧 timer。回调没有检查塔是否存活或 A057 句柄是否有效，且保存的是塔槽，不是固定 C 句柄。现有 Web B05 规定确定性定时器队列；不能把这 0.1 秒 callback 提前内联。

两条分支最终均由 0.5 秒生命期 q001 在**进入技能时采样的 C 位置**施放 T410 `bloodlust`，目标为 C。成功用 1 级、失败用 2 级。[units_abilitydata.json](../../reference/map-6.25/units_abilitydata.json) 的 T410（L39327）是 Ablo，BuffID=B220，DataA1/2=.9，HeroDur1=3、HeroDur2=6，与图鉴的 90% 攻速和 3／6 秒相符。另有 Dur1=60；不能把英雄时长无条件推广到非英雄。

T220（L36916）是 Ainf、BuffID=B171，Dur1=HeroDur1=20。A056 在 B171 等级>0时将其原伤害×1.5：`main/f50/f1` B68599–68607（PC57–65）。这与图鉴 `塔技能!I51/I71/I121/I136` 的“淘汰成功后20秒反击螺旋伤害增加50%”一致。本批只追这一 B171 检查，未声称完整核完 A056。T410／T220 实际请求执行、同 Buff 刷新／叠加的 native 细节尚未由脚本调用闭合。

## 6. 深渊与特殊目标的精确边界

q025 在主事件中豁免了 N533 随机闪避分支、T202 减伤、无尽类别／波次倍率、部分反射和 N521 的后备续命分支，**不豁免深渊回调**。主流程 `main/f291/f1` PC3807–3812、B166518–166523 在 Game_Mode=2 时调用 `Abyss_Damage_Event`。不能把无尽 q025 例外扩大为深渊全免减伤。

`Abyss_Damage_Event`（`main/f290/f2` B157615–157796）本批全部核过：source=nil 早退；临时来源恢复归属塔；先把当时 `floor(D)` 加入玩家深渊伤害记账，再执行以下目标修正。

| 目标 | 对本次伤害的操作 |
| --- | --- |
| ma01 金币小鸡 | 抽 `GetRandomInt(1,100)<12` 且 D>50 时产生 i421；无论是否掉落，最后 **D=0**。无 q025 排除 |
| ma99 深渊巨龙且 N565_Temps 非 nil | 系数从 1 开始，每个生命>0的表项减 .01，负数钳至 0，然后 D←D×系数。保留逐次浮点减法顺序 |
| 其他目标或 ma99 表为 nil | 本函数不改伤害 |

**小鸡是可达交互补缺，不另列图鉴冲突。** 图鉴 `无尽与深渊!D16` 指向 ma01；基础 HP=5000，单人入场系数 .4 得 2000。斧王基础 HP=100、力量30，加地图 `StrHitPointBonus=15` 得 550，抽 4／5 即满足 2000<550r；等级／装备再提升不会取消该条件。小鸡类型也不是 m999／m998。它的 q025 斩杀包和随后范围物理包均被此回调归零，所以小鸡存活而技能仍给成功奖励。创建／HP 与伤害注册见 `main/f290/f9` B158130–158252；基础字段见 JSON；力量换生命系数见 [war3mapMisc.txt](../../reference/map-6.25/war3mapMisc.txt) L55。结算保留福利关自身不死规则，不泛化为所有 Boss 免斩杀。

其他边界按已核主分派保留：T 有 N582／N583／N584 且当时 D>life 时，会写 D=0，调用恢复最大生命并移除这些技能的函数，没有 q025 排除（PC3924–3963、B166641–166681；`main/f180/f0` B113859–113968）。**这只证明原始斩杀包可能被拦截，不单独证明目标能活过之后的范围物理包**。N521 对 q025 另有专门处理；完整怪物生命周期没有在此无限展开。没有据此伪造“所有普通 Boss 免疫”或擅改 A027 共用 helper。

## 7. 完成边界与验证

A057 两个核心函数合计 **241 条指令、15 个条件、42 次调用、2 个 return**，条件真假去向全部保存在 JSON。另完整核查的 5 个直接函数共 204 指令、9 个条件、44 次调用、6 个 return 指令；这些是 UnitKillUnit、SetRealDamage、深渊伤害回调和目标发令队列两函数。自动施法、装备入口和整条伤害管线复用既有静态审计，不重复声明全部下游技能完成。

本批验证 23 个边界／算例：严格阈值、1–5 概率、已有累计的门槛放大、两种金币怪、最大／当前生命区分、成功与死亡不同、失败不取消 timer、timer 取当前剩余、nil 塔清理、小鸡免伤、巨龙系数及特效开关。校验 JSON、原函数行号／条件跳转与源 SHA-256；未运行 Warcraft 或 Web 游戏。

尚未闭合的是原生施法与目标合法性、遗漏等级字段的客户端继承、Buff 刷新叠加、范围伤害的 native 筛选／死亡目标处理，以及塔槽替换时本模块之外的累计清理。Web 已决 B03／B04／B05 分别提供事件提交、枚举和计时顺序；本批没有另选 A057 概率或伤害替代公式。

本页历史列出的原生接口缺口已在[旧技能接口收口](legacy-control-and-cast-closure.md)逐项解决；当前实现规则以该补充及本页原脚本事实共同为准，原客户端未实测单独保留。
