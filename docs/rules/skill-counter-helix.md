# A056 反击螺旋：双入口、邻怪概率与神圣伤害

本批完整静态核查 A056 模块的 5 个函数、必要动画定时器与直接伤害 helper，并核对被动伤害事件、施法生效事件、自动发令三个调用片段。**不是全部原生引擎或整条伤害管线下游的完成声明。** [skill-counter-helix.json](skill-counter-helix.json) 保存条件真假去向、源字段、原文与算例。用户 Q31 已确认保留攻击被动及原图主动／自动施放入口；Q32 已确认准确百分比加原图邻怪加成，封顶100%。下文将原图事实与 Web 决定分开。

`B` 是 [main.disasm](../../reference/map-6.25/main.disasm) 行号；PC 为各函数内部指令序号。全模块 `main/f50` B68424–68904，不能只依赖阅读稿重组的 if/else。

## 2. 两种效果入口与自动尝试

### 攻击伤害事件的概率入口

主伤害管线走到 `main/f291/f1` **PC728–747，B163257–163276** 时：实际来源 S 有 A056，且 `EXGetEventDamageData(2) != 0`，才调用一次 `A056_Get_probability()`；为真则 `A056_Action(S)`。

这里使用**实际来源 S**，不是自动替换为归属塔 O。此片段没有单独排除幻象、检查 A056 冷却、扣蓝或设置内置冷却，也没有“一次攻击最多一次”的去重键。管线更早的零伤害退出／旁路仍需遵守，见 [damage-pipeline.md](damage-pipeline.md)；不能因此给完全未到此处的事件补抽概率。

`A056_Action`（`main/f50/f3` B68722–68744）先向 S 发 `stop`，再执行伤害核心；不读取 stop 的返回值。自身发出的神圣伤害包带 attack=false，因而不会通过这条 attack 门槛重新触发自身。

### 施法生效的必发入口

`AnySkillStart` 的 `main/f291/f14` **PC284–292，B170307–170315**：公共过滤、装备施法分派及 `WAbility_initAbility` 之后，A056 的 SPELL_EFFECT 直接调用 `A056_Skill(caster)`。该函数（`main/f50/f2` B68706–68720）只是调用同一伤害核心，**不抽 A056 概率、不发 stop**。这些是事件一旦发生后的确定路径；不等于没有验证 native 发令合法性就声称每次下令一定成功。

普通自动施法第 26 块（`main/f291/f27` **PC715–743，B174850–174879**）先遵守 B012 开关和公共就绪检查，再寻找施法者周围 **650** 内首个活着的 Player(11) 单位，找到则立即发 `robogoblin`，结束本轮技能扫描，仍进入道具尾部。不保存所找单位为技能目标，这是一条无目标命令。A055 在它之前，A057 在它之后。就绪精确条件、枚举和原生命令边界复用 [autocast.md](autocast.md)。

因此原图可能先由自动发令触发一次必发螺旋，后续攻击伤害事件又独立抽被动概率；此模块没有用主动冷却屏蔽被动触发，也没有共享去重锁。不能把这两条入口静默合并成“每 5 秒只转一次”。

## 3. 原概率：只翻倍邻怪贡献

`A056_Get_probability` 为 `main/f50/f4` B68746–68904，99 条指令、11 个条件。先取当前伤害来源的位置，枚举 **700** 范围；逐一 `FirstOfGroup`／移出组，仅 owner=Player(11) 且当前生命>0的单位计入 N。Boss、金币怪、召唤物、幻象没有额外排除；本次攻击目标在范围内且活着时也计入。原生枚举未返回的单位不能凭类型猜测加入。

每个有效单位给局部累计量+2。枚举结束、销毁组后，若 **Game_Mode==1**，只把这一累计量×2；然后读取 A056 等级，加上等级基础档。

| 等级 | 基础档 b | 力量伤害倍数 k |
| --- | ---: | ---: |
| 1 | 10 | 1 |
| 2 | 12 | 1.5 |
| 3 | 14 | 2 |
| 4 | 16 | 2.5 |
| 5 | 18 | 3 |
| 6 | 20 | 5 |

```text
非无尽（含深渊）：t = b + 2N
无尽 Game_Mode==1：t = b + 4N
抽整数 r = GetRandomInt(0,100)
成功 ⇔ r < t
原真实概率 = min(101, max(0,t)) / 101    # t 为整数
```

没有显式概率上限语句；t=100 时仍有 r=100 这一失败结果，t>100 才自然必触发。若等级不在 1–6，阈值保持 0，虽然之前仍做了计数，也会抽一次并返回 false。

关键证据：`PC39/45/47` B68834–68842 为归属／生命检查与+2；`PC57/59` B68854–68856 为无尽仅翻倍累计；PC67–89 B68865–68892 为基础档；PC90–98 B68894–68903 为一次随机及真假返回。比较 PC94 的 true 路径跳 PC97=true，false 路径 PC96=false 并跳过 PC97。

6 级、附近 5 个有效单位时，原普通／深渊为 **30/101≈29.703%**，无尽为 **40/101≈39.604%**；若按原图实际提示的百分比理解，则分别为 30%／40%。图鉴简略说明只写 20%。用户 Q32 已确认 **Web 保留邻怪补充并使用准确百分比**，上述例子 Web 分别为30%／40%；原脚本的 `/101` 仍保留为来源事实。

## 4. 伤害核心、快照和对象筛选

共享核心 `main/f50/f1` B68475–68704，157 条指令、13 个条件。依次读取 A056 等级、`GetHeroStr(U,true)`、扩展 state18 和 state19，计算：

```text
P = state18(U) + state19(U) + GetHeroStr(U,true) × k[level]
若 P == 0：立即 return
若 B171 等级 > 0：P ← P × 1.5
```

扩展状态 18 是攻击 1 的 damage_base，19 是 damage_bonus，**此处没有加攻击骰子，也不是最小／最大攻击的平均值**。接口定义及实现依据 [YDWE 固定版本 UnitState.cpp](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Plugin/Warcraft3/yd_jass_api/UnitState.cpp) L20–21、L264–268。图鉴“攻击力”没有细写取样字段，本批按源补足；不擅自改成其他技能使用的 state20／21。

等级不在 1–6 时 P 保持 0。返回条件是 **等于 0**，不是 ≤0；负值会继续发包，native 如何处理负伤害不是本函数证明的事实。

核心接着开启 spin 动画、登记 0.4 秒去除动画回调；若 U=G067 则显示 T1837.mdx 0.4 秒，不受 TxShow 控制。然后才采样 U 坐标，重新枚举 700 范围。**概率计数的组与伤害组是两次独立枚举**，不能直接复用第一次结果。

伤害循环按组顺序逐一读取单位，nil 结束；只有 owner=Player(11) 且当时生命>0才由 U 发 `SetRealDamage(U,target,P)`。它是逐个单位的 `UnitDamageTarget`，不是 `UnitDamagePoint`；参数 `attack=false,ranged=false,ATTACK_TYPE_CHAOS,DAMAGE_TYPE_DIVINE,WEAPON_TYPE_WHOKNOWS`。P 在本次核心开始时只算一次，即便前一个目标死亡引发了属性变化，后续原始包仍用这个快照；最终伤害各自继续经过主事件修正。若 TxShow=true，给已发伤害的每个有效目标加 0.5 秒血迹特效。

B171 ×1.5 作用于**整个 P**。例如 state18=300、state19=50、力量100、6级时 P=850，有 B171 则为1275。该 Buff 来自 A057 成功分支的 0.1 秒回调施放 T220，持续20秒；参见 [skill-culling-blade.md](skill-culling-blade.md)，本批不更改已核 A057 规则。

## 5. 必要动画回调

`delayTimeRunFunc`（`main/f7/f2` B50459–50492）把函数存到数组第一个 nil 槽，创建 timer，登记 0.4 秒一次回调，并保存 timer 与参数 `{U}`。`AddArrAny`（`main/f7/f22` B51546–51568）只找空槽，**不按回调函数去重**。

通用回调（`main/f7/f1` B50410–50457）找到 timer 槽，先销毁 timer；无参数表时直接调用，有参数表则 `table.unpack` 后调用；最后清函数、timer、参数槽。A056 实际传了 `{U}`，其回调（`main/f50/f0` B68449–68473）仅判断 U 是否 nil；非 nil 就关 spin，不重查存活。

每次核心执行独立登记 timer，不取消已有 timer。例如 t=0 和 t=.2 各转一次，t=.4 和 t=.6 都会发关闭动画请求；第二次没有把第一次的结束时刻顺延。这些回调只改动画，不延迟或重复伤害。效果显示 helper 的销毁逻辑复用已有审计；Web 定时顺序遵守 B05。

## 6. 已决 Web 规则与完成边界

- **入口 Q31 已决**：保留普通攻击概率入口，以及原图实际提示与脚本明确的主动／自动施放入口；主动冷却采用实际提示的 5 秒。
- **概率 Q32 已决**：保留700范围内原计数条件；合法等级1–6的基础 b=10／12／14／16／18／20，普通和深渊 t=b+2N，无尽 t=b+4N，采用准确概率 `p=min(100,t)/100`，封顶100%。保留原攻击事件资格与概率调用时点；主动／自动施法生效仍直接进入伤害核心，不抽此概率。

边界对照：6级在普通／深渊 N=40 或无尽 N=20 时 t=100，原脚本是100/101，**Web 为100%，不存在额外失败结果**；无尽 N=19 时为96%，N=21 时仍封顶100%。该修改不增加冷却或魔法门槛；未到被动分支、未学A056、attack标志为0的事件不补抽概率。主动／自动入口的无概率执行与攻击入口的单次概率判定分别验证。若概率函数被调用时等级不在1–6，仍计数并消耗一次随机抽签，但阈值保持0、恒不触发；不能用“基础缺省0再加邻怪”代替原分支。每次实际概率函数调用都保留一次抽签，包括概率为0或100%的情况。

五个模块函数共 **277 指令、25 个条件、48 次调用、8 个 return 指令**；四个直接 helper 共 **60 指令、2 个条件、10 次调用、5 个 return 指令**。包含隐式不可达 return，所以不是把数量当作业务分支数。模块初始化 9 指令只绑定闭包，另列来源而不混入核心计数。

本批提供 45 个验证向量（原始脚本与已决 Web 结果分列），涵盖各级／三种模式概率、100阈值边界、计数筛选、六级伤害系数、B171、零／负值门槛、双入口、无冷却门槛、重叠动画 timer 和武圣特效。校验原字节码条件／跳转、字段、四组图鉴文本与六条实际提示；未运行 Warcraft 或 Web 游戏。
