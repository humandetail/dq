# 伤害事件主分派流程（6.25 原图）

本轮核查对象是 `anyUnitDamaged` 的**整个分派函数**：原字节码 `main/f291/f1`，位于 [main.disasm](../../reference/map-6.25/main.disasm) L161979–167018；阅读辅助 [main.readable.lua](../../reference/map-6.25/main.readable.lua) 从 L110377 起。已核遍主函数的条件、跳转、调用次序、直接写伤害和返回路径；**没有递归验证全部被调技能内部，也没有完成原生魔兽引擎行为验证**。

[damage-pipeline.json](damage-pipeline.json) 保留全部 437 个条件的真假去向、964 个调用、56 处直接伤害写入及其他跳转。原始 4,278 条指令已在证据快照中，不再复制进索引。可用 `python3 tools/index-damage-pipeline.py` 重建索引；[生成器](../../tools/index-damage-pipeline.py) 只读反汇编，不运行游戏。

原图事实与 Web 决策分开：用户已选 EUL **10% × 1.4**、大法师之戒 **25% × 2**、怒意狂击 **300/450 层**。以下记录原图顺序，不撤销这些裁决，也不重复提问。

## 如何读证据

本文 `PC` 指该函数内部从 1 开始的字节码指令号，原文件标签 `l1234` 就是 PC1234。JSON 每条条件和调用均有原文件 `line`；可由 PC 精确回查，不依赖反编译的 `if/else` 重组。

`S` 为实际伤害来源（r0），`T` 为受伤单位（r1），`O` 为归属塔（r2）；`D` 表示调用当时的 `japi.GetEventDamage(0)`，不是不可变初始伤害。`attack` 是 `EXGetEventDamageData(2)`，`type` 是数据 4；`has(U,id)` 表示技能等级 > 0，`gold(T)` 表示 m999/m998。`ready` 指原图冷却/魔法就绪函数。`in(U,arr)` 指 `IsInTable(U,arr) != -1`。

控制流依据 [Lua 5.3 指令定义](https://www.lua.org/source/5.3/lopcodes.h.html) 与 [执行器](https://www.lua.org/source/5.3/lvm.c.html)：比较指令与紧随的 JMP 必须一起解释；索引已将每个条件规范化为 `normalizedTrueNextPC/normalizedFalseNextPC`。表达式仅展开同一基本块中的来源，跨块寄存器保留 rN；`...RET@pc` 表示该 PC 的多返回值展开。表达式重复出现只是显示其来源，并不表示重执行随机函数或创建对象。

审计计数：4,278 指令、501 常量、437 比较/真假判断、478 JMP、1 个 `forprep/forloop` 对、5 个 return、170 个不同调用目标。所有调用名和所有 B=0 的返回值生产者均可定位。结构图中仅 PC3490 是不可达的多余 JMP；这是字节码事实，不推导为玩法故障。结构可达不等于游戏状态一定能触发。

## 6. 模式、反射与濒死处理

**T202（PC3676–3741 / L166376–166445）**：T 的 T202 等级>0 且 S不是q025。按事件类型选全局 `J100_Damage_Phy/Magic/Other` 写入全局 `damageFlag`，乘 T202 等级得到 x，仅设置上界 `x=min(99,x)`，再用进入该段时保存的 D 写 `D*(100-x)/100`。代码没有下界裁剪；这里的 `damageFlag` 是全局赋值。

**无尽（PC3742–3806 / L166447–166516）**：Game_Mode=1 且 S不是q025，重新保存 D。类型倍率 k 取 `EndLess_Damage_Phy/Magic/Other`。若 T 有 T176 且 `EndLess_Damage_Reduce!=0`，k 再乘 `min(2.5,100/EndLess_Damage_Reduce)`。最后写：

```text
D = 进入无尽段时的D × EndLess_Damage_Reduce/100 × k
```

**Web Q67覆盖：** 上述是原无尽指令证据。实际实现中，T176有效时将无尽减伤率减半：设原剩余承伤比例r=R/100，使用`D×(1−(1−r)/2)×类型倍率`，不再乘旧的`min(2.5,1/r)`；q025旁路保持。详见[末日规则](doom.md)。

**深渊（PC3807–3812 / L166518–166523）**：单独检查 Game_Mode=2，调用 `Abyss_Damage_Event()`；主分派器这里**没有排除 q025**，是否排除须看深渊函数内部。无尽、深渊全局参数的生成见 [waves-and-modes.md](waves-and-modes.md)。该函数内部本轮不再次递归展开。

随后严格按以下顺序：

1. PC3824：T 有 N579则 `N579_Action(T)`。
2. PC3839：O 有 A231则 `A231_damage_Ref(O,D)`，读的是此时事件值。
3. PC3868：S不是q039，T有T188，S不是q025，调用 `A173_Damage(O,T)`。q039 已在入口旁路，该条件是此段保留的重复限制。

## 8. A026 是否已证明与图鉴冲突

后续 Web 决策：Q24 已明确护甲/事件基准，Q26 已选择按图鉴忽略 5%–30% 护甲并保留深渊折半，精确替换公式见 [战斗规则](combat-and-skills.md)。Q27 已选择 i267 忽略 35% 护甲并保留深渊/A026 折半，计算和组合方式见 [装备分派](item-damage-dispatch.md)。下文保留调查阶段对原客户端的证据边界；未实测原客户端不再阻止已授权的 Web 选择。

**结论：精确脚本操作已经证实；目前不足以把“最终伤害与忽略护甲描述不等价”作为已闭合事实再向用户索要裁决。** 不能把描述直接实现成减护甲，也不能宣称原图数学完全等价。

A026 在 PC512 执行，位于前置装备之后、负护甲修正与后置装备之前；本轮全主分派器中只此一处调用。函数 `main/f28/f0` / L63229–63344 精确计算：

```text
p = [0.05,0.10,0.15,0.20,0.25,0.30][技能等级]
a = GetUnitState(T,ConvertUnitState(32))
x = a*p；x==0时直接返回
x = max(0,min(a,x))
若Game_Mode==2：x/=2
D = 当前事件D * (1+0.007*x)
```

该函数没有直接写目标护甲。但“以事件增伤模拟忽略护甲”本身可能是一种实现方式，是否等价必须把原生护甲转换函数、伤害事件处于护甲前还是后、`EXSetEventDamage` 的提交语义一起核实。地图已覆盖 `DefenseArmor=0.018`；这一个系数本身不能证明完整原生函数。

**仅用于检验的条件推导，不能当已证实引擎公式**：若正护甲实际采用 `F(a)=1/(1+0.018a)`，按字面忽略比例p后的事件增幅应为 `F((1-p)a)/F(a)`。例如 a=100、p=0.30，字面倍率约1.23894，而此脚本倍率是1.21（非深渊）。在这个明确假设下两者不恒等；缺失的是该假设在实际客户端与钩子中的证明。

还有一个不能漏掉的联动：`ItemDamageActionAfter` 中，持有 i267 且 attack!=0 时调用 `i267_Action()`（Lua L97633–97647）。其字节码 `main/f261/f0` L132358–132442 已复核：S有T085则return；否则 `x=max(0,min(a,0.35a))`，深渊x/=2，**S有A026时x再/=2**，然后 `D*=1+0.007x`。这在 A026 主分支之后执行，不能把两个提示“忽略比例”简单相加。前置装备、原生能力以及其他被调技能能否改变查询到的护甲还需各自闭合。

A026 物编记录 `code=AHad`，SLK定位 [units_abilitydata.json](../../reference/map-6.25/units_abilitydata.json) L14217；缺字段不能擅自当成零，也不能忽略原生能力默认。**原客户端等价性仍未实测**；Web 的事件内计算则已由 Q26 定案，不能再将 Q26 标为未决。

## 9. 已完成与仍缺事实

已完成的是主分派器的静态骨架与直接操作：全部条件/跳转入口、短路顺序、5条返回、两个装备钩子、56处直接写伤害、模式段与统计时点。JSON覆盖每个判断及调用，文档给出可以据此实现分派器的阶段、业务门槛与顺序。生成器检查标签PC一致、跳转目标存在、开放返回值生产者可追踪、所有调用目标可识别；没有运行原地图。

尚未完成：全部170种调用目标的内部语义；原生命中/护甲/魔抗与事件钩子提交顺序；能力code默认；嵌套伤害对当前事件数据的恢复；全局变量在重入时的保护；原生命令是否接受及何时耗蓝/开始冷却。它们可能改变单个调用产生的真实效果，但不允许重排本页已证实的调用边界。

据此可称“**主伤害分派流程静态核查完成**”，不能称“全部技能行为已还原”或“最终伤害公式已完全验证”。

后续补充：[前后置装备分派](item-damage-dispatch.md) 已核完整条件与调用边界；[原生护甲与经验](native-armor-and-xp.md) 已提供正护甲公式与类别列序的依据。其余装备/技能内部效果、原生提交先后与事件重入仍按各自缺口记录。

最终复核：生成器连续运行结果逐字节一致；437 个条件的真假目标、964 个调用的行号与参数编码、56 个直接写伤害的顺序、5 个返回位置，以及正文 PC/行号对照均与快照一致。复核中修正了三围段起始行与 i267 函数范围的引用；未改变原图规则或已确认的 Web 裁决。
