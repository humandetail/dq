# 超强力量 A022：触发、狂热与原生适配

本页核查利爪熊将 G037、熊战士 H006 的 A022 完整模块、普通/幻象攻击入口及直接使用的 T007/B003；不重做怒意狂击 A023，也不扩其他英雄技能。图鉴为 `塔技能!H190:I190、H451:I451`。**Q34 已选图鉴的准确概率，Q35 已选增加 500% 攻速**；其余原生细节按 Q24 明确为 `overpower-effect-v1`。机器表见 [skill-overpower.json](skill-overpower.json)。

原始证据：[main.disasm](../../reference/map-6.25/main.disasm) 为字节码，[main.readable.lua](../../reference/map-6.25/main.readable.lua) 为阅读辅助。A022 两函数的全部 97 条指令已核，入口另核幻象完整分支及普通入口至 A023 的前缀。没有运行 Warcraft 客户端，不把静态字段直接等同于最终攻击速度。

## 1. 两项差异与一致项

| 项目 | 图鉴/实际说明 | 原执行来源 | 状态 |
| --- | --- | --- | --- |
| 1–6级触发概率 | `I190/I451`：6%、8%、10%、12%、14%、17% | 先取得同数值阈值，再 `GetRandomInt(0,100)<阈值`，均匀含端点时为 N/101 | **Q34 已选准确的 6/8/10/12/14/17%**；原门槛与抽样位置保留 |
| 攻速输入 | `H190/H451` 及 A022 Name/Researchubertip：“提升攻击速度500%” | 实际 T007 `Ablo.DataA1..4=4.0`，字段是攻速增加量，即 +400 个百分点 | **Q35 已选 +500%**，向共享攻速系数增加5；不是最终攻速固定为5倍 |

实际说明在 [units_campaignabilitystrings.txt](../../reference/map-6.25/units_campaignabilitystrings.txt) `[A022]` L271–284。每一级 Ubertip 都包含神杖例外；不能只读 Name 的基础说明后删掉强化效果。技能概率表本身返回的是阈值，不负责掷随机数。

攻速差异只描述**输入量**。若其他加成为0，+4 与 +5 对应的未钳制速率系数是5与6，但不能据此断言游戏中实际始终快20%，更不能直接把攻击间隔设置为原间隔的1/5或1/6。总攻速、上限及现有状态的边界见第5节。

## 2. 入口、概率与消耗顺序

`EVENT_PLAYER_UNIT_ATTACKED` 对 Player(11) 注册并调用 `chooseAttackedAction`，见 main/f291/f31 L179448–179486。这里是目标**受到攻击事件**，不是攻击已命中、已造成伤害或已击杀；脚本没有补一个成功命中条件。取消攻击、闪避等后续结果不会回滚此前已经发生的这一事件处理。

### 普通攻击者

main/f291/f3 的 PC1–109（L167142 起）中：先取得攻击者和目标；非幻象分支先做 T217 相关计数、`Skill_Auto`、符合条件时的 N706/N707/N708 目标响应，然后处理 A022，再处理 T316，随后有 A023 才调用 `A023_Action`。A022 的本地门槛/调用在 L167208–167225：

```text
if level(attacker,A022)>0:
    threshold = A022_Get_probability()
    r = GetRandomInt(0,100)
    if r < threshold: A022_Action()
// 然后继续原T316、A023及后续分派
```

只要持有等级>0的 A022，即使 threshold=0，也仍然消耗这次随机数。没有技能才跳过这一抽样。A022 成功与否不决定后续 A023 是否叠层；A023 保留既有 300/450 层、6秒续期规则，见 [战斗技能](combat-and-skills.md)，本页不重新裁决它。

### 幻象攻击者

主入口发现幻象，进入私有 main/f291/f2（L167020–167082），然后立刻从普通主分支返回。该私有函数仍先检查 A022、读取同一个阈值函数、抽0–100并严格比较，成功仍调用同一 `A022_Action`；之后处理 T316。因此**不能统一排除幻象的超强力量**。这一入口不会继续普通分支的 `Skill_Auto`、A023 和后续装备攻击响应。

是否继承技能等级、Buff 和强化资格，使用该幻象当时的实际状态；本页没有把原塔的神杖资格强行复制到所有幻象。原图 `war3mapMisc.txt:41` 的 `IllusionsGetAttackSpeedBonus=1` 是已存在配置，仍须保留，但不等于创建幻象时必然复制 B003 全部生命周期。

### 阈值函数完整行为

main/f24/f1，L62599–62694，56条指令、8个条件；阅读稿 L38799–38848：

```text
S = GetAttacker()
if level(S,B003)>0:
    if Has_A_Item(S)==false: return 0
L = level(S,A022)
return ({1:6,2:8,3:10,4:12,5:14,6:17})[L] or 0
```

字节码顺序是**先查 B003/强化资格，再读 A022 等级**。`Has_A_Item` 沿用 main/f7/f8 L50812–50855：S 出现在 `A111_113_A` 中，或持 i310；不能缩成“物品栏没有A杖”。B003 检查不区分施加来源，任意有效 B003 都会触发这道门槛。持有强化资格不保证自动刷新，只允许这次攻击按正常阈值再尝试。

原阈值17时，r=0..16成功，17..100失败；阈值0时连r=0也失败。等级不在1–6时返回0。以上是原脚本的严格 `<` 条件，仅保存为来源证据。

**Q34 已裁决 Web 使用准确百分比**：保留上述阈值解析顺序，取得阈值 t 后，以均匀整数 r∈[1,100] 判定 `r<=t`，概率为 t/100。六级准确为17%；阈值0必不触发，但入口已经确认持有技能时仍消耗一次抽样。普通与幻象入口都采用此规则；无技能仍不抽样，原神杖/狂热门槛、A023 调用关系不变。这里改变了抽样区间与比较方式，不把 Web 条件倒写成原脚本事实。

## 3. 成功后创建一次嗜血施法

`A022_Action` 为 main/f24/f0，L62527–62598，41条指令、11处调用；阅读稿 L38753–38797：

1. `S=GetAttacker()`，计算 `index=IsInTable(S,Tower_ALL)`，取得 S 当前位置。
2. 调用 `CreateTempAndSetAbilityLv(owner(S),loc,0,"T007",level(S,A022),0.5)`。第七参数缺省，创建 q001；能力等级与当时 A022 一致；BHwe 计时生命0.5秒。
3. 释放位置句柄，再把 `index` 写入 q001 的 UserData。
4. 对 q001 先下达 `bloodlustoff`，再下达 `bloodlust`，目标是原攻击者 S。两条命令返回值都未检查。

这里的 UserData 是本次 `IsInTable` 的结果，**不是直接复制 S 的 UserData**。若返回-1，源码也直接写-1，没有在此添加回退索引。不能误用共享妖术的复制方式。位置释放发生在设置 UserData 和下达命令之前；逻辑位置已用于创建单位。

q001 与通用包装器的证据已在 [共享妖术效果](item-hex-effect.md) 核实；本次只更换 T007、等级和0.5秒生命。它有 Avul/Aloc、隐藏模型、1000初始魔法；仍是有创建序号的逻辑单位，不把多次成功合并为一名长期施法者。临时单位的技能生效经 `IsTemp` 早退，不触发装备施法连锁。

**本次没有攻击次数计数器，没有“接下来N次攻击”，没有独立A022冷却。** T007 的1秒冷却属于每次新创建的临时单位，不能变成原塔的1秒触发冷却。函数没有直接改攻击伤害、移动速度、攻击间隔或额外调用怒意狂击，只提交这一项原生嗜血能力。

## 4. T007/B003 的数值与缺省分层

[units_abilitydata.json](../../reference/map-6.25/units_abilitydata.json) 的 A022 记录 L14136 是 `code=AHad` 的持有/等级模板；实际施加狂热的是 T007（L32651起），不能把 A022 自身零散的 Dur 字段当狂热时长。本适配将 A022 模板作为被动持有标记，不生成未经图鉴或字段支持的额外光环。

| T007字段 | 已取得的原值 |
| --- | --- |
| code / levels | `Ablo / 6` |
| BuffID1–4 | B003 |
| DataA1–4 | 4.0、4.0、4.0、4.0 |
| HeroDur1–4 | 2、2、3、3秒 |
| w3a增量 `ahdu` 第5/6级 | 各4秒 |
| Cool1 / Rng1 | 1秒 / 600 |
| targs1–4 | `friend,invulnerable` |
| Dur1 | 60秒；普通目标字段，不用于覆盖本页英雄的持续表 |
| DataB / DataC | 本记录未显式列出；不能搬用普通嗜血说明的移速/体型参数 |

B003 在 [units_abilitybuffdata.json](../../reference/map-6.25/units_abilitybuffdata.json) L744；[Buff说明](../../reference/map-6.25/units_commonabilitystrings.txt) L26起写“超强力量／狂热状态”。程序中 B003 的字面读取只在本阈值函数，T007 的字面施加也只在本效果；没有发现另一条专属 Lua 到期、每攻击扣次数或额外攻速回调。

[YDWE 元数据 Blo1](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Component/share/en-US/mpq/Units/AbilityMetaData.slk#L4867)映射 Ablo 的 DataA；[编辑器字段名](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Component/share/en-US/mpq/UI/WorldEditStrings.txt#L6018)明确为攻速增加百分比，DataB是移速增加、DataC是缩放。故 4.0 是加成输入，不是某种攻击次数。

5/6级 DataA、BuffID 等没有独立 SLK 列；[同开发工具的补全代码](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Component/plugin/w3x2lni/script/core/slk/frontend_merge.lua#L18)在超出已有数组长度时沿用末项，再合并显式对象增量。来源解析层将 DataA5/6、BuffID5/6等续用第4级，HeroDur5/6再按明确增量取4秒；随后 Web 裁决层依 Q35 将全部1–6级攻速加成覆盖为5，原值仍保留为证据。**这是有开发工具依据的移植补全，不伪装成地图显式写了 DataA5=4。** 普通 Dur 各级缺省不在此推成“所有目标60秒”；本范围是两名英雄及其实际持有A022的幻象。

T007 `[马甲-超强力量]` 的旧 Ubertip（campaignabilitystrings L19584起）仍写40%攻速、25%移速、60秒，是模板文本；不能覆盖图鉴与修改字段。[暴雪普通 Bloodlust 说明](https://classic.battle.net/war3/orc/units/shaman.shtml)也描述普通40%/25%及魔免目标限制，只用来解释能力类型，不能把普通数值加回这个定制技能。

## 5. 攻速加成不等于最终间隔

原图 `war3mapMisc.txt` 已明示敏捷攻速系数0.002（L7）、冰冻攻速降低0.6（L26）、幻象继承攻速（L41），**未在该覆盖文件找到总攻速上/下限**。这不证明没有原生上限。A022 两个函数没有其他 `SetUnitState`、攻速乘算或限幅；其他英雄、装备和全局状态对总攻速的影响不能被本技能抹掉。

[独立 Warsmash 引擎实现](https://github.com/Retera/WarsmashModEngine/blob/f9e0aeed4be372d6016519d0e97b384aa873f374/core/src/com/etheller/warsmash/viewer5/handlers/w3x/simulation/combat/attacks/CUnitAttack.java#L185)先合计攻速加成，钳制到[-0.9,4]，再加1用于攻击间隔及动画时间。此源码证明该实现确实存在钳制，**不是本图实际客户端上限的证据**。例如若共同上限就是加成4，其他加成0时，输入4与5都得到有效系数5；本项目已在 Q24 授权下明确选择有效系数0.2–5，见[共享攻击计时](attack-timing.md)；该选择独立于此实现的下界，也不表示两输入在所有状态下都相同。

Q35 已确定：B003有效时登记**一个 +5 的攻速贡献**，解除时仅移除这一项；全部1–6级一致。共享系统保留原始系数 R，调度使用 K=clamp(R,0.2,5)，详见[攻击计时](attack-timing.md)。其他贡献合计使原始系数为0.4时，加5得到R=5.4、K=5；状态结束回到R=0.4、K=0.4。不能把最终钳制值存回R，否则撤销时会丢失其他贡献。

Q24 的本地时序选择为：Buff变化不额外发起攻击，也不把当前攻击进度清零；保留尚未完成的标准化攻击阶段工作量，用共享系统提供的新有效速率推进。已经完成的前摇/已发出的独立弹道不回溯改写。例如有效系数由K1变K2时，剩余时间按旧剩余时间×K1/K2换算；这里K来自实际汇总/钳制结果，不能直接用4或5代入。

## 6. Q24：施加、刷新与生命周期

以下是针对 T007/B003 的明确 Web 选择；概率按 Q34，全部等级攻速加成为 Q35 选择的 +5：

- q001 的 T007 专用施法前摇和耗蓝取0；0.5秒计时生命保留。`bloodlustoff` 先关闭自动施法，再同步接受对原攻击者的唯一目标命令。嵌套技能事件结束恢复原攻击事件上下文，不自动回滚脚本全局变量。
- 目标须存在、存活、与临时施法者友好且在600内；明确允许无敌，因为自定义目标字段包含 invulnerable，两名塔的初始能力也含 Avul。魔免目标不接受新的嗜血；不再把普通模板的 organic-only 条件擅加到这个自定义 `friend,invulnerable` 字段上。施加失败仍已消耗概率，临时单位照常到期，主攻击分派继续。
- 本页英雄/幻象配置按成功施加时的 A022 等级快照取2/2/3/3/4/4秒；不是按发生了几次攻击来扣除。临时单位0.5秒死亡不结束目标Buff。
- 同一目标只有一份 B003攻速修正。强化允许的再次成功触发将到期设为`当前时间+本次等级持续`，覆盖旧实例，不累加、不取较大值，也不叠第二份攻速；旧到期回调通过实例代号失效。
- 获得或失去神杖/其他强化资格不会直接刷新或移除已有Buff，只改变下一次攻击读取的阈值。没有强化时，Buff到期前的每次有技能攻击仍抽一次随机数，但阈值为0。
- B003属于可被相应驱散移除的正面魔法状态；死亡移除，不继承至复活。到期、驱散、死亡都只撤掉这一修正，并让旧到期回调失效。单独获得魔免标志不由本效果额外轮询清Buff；具体能力已有清除步骤照常执行。其他攻速、移动或控制状态不随B003一起清空。
- 到期及临时单位生命计时依B05；保存Buff代号/来源/等级/到期、加成参数、临时单位归属与UserData、随机消耗位置、队列序号和最终裁决版本。
