## A111：连接、伤害与共享

完整建立／周期／结束分别为[f89/f2 L80648–80846](../../reference/map-6.25/main.disasm#L80648)、[f89/f1 L80490–80646](../../reference/map-6.25/main.disasm#L80490)、[f89/f0 L80399–80488](../../reference/map-6.25/main.disasm#L80399)。保留神杖模块全部顺序：

1. 不同owner时查目标玩家Help_Arr，值1拒绝；同owner不查。目标已出现在A111_113_tar任一值中也拒绝，包括同一来源重连同一目标；不刷新timer。
2. 来源以`IsInTable(source,Tower_ALL)`找索引，原函数没有额外拒绝−1。该索引已有其他目标，先完整A111_end；建立新的闪电及1秒周期，目标当前state37立即−0.1。按来源**建立时**类型，G057闪电JIEYG、G058为JIEY、其他CLPB；端点z均90。
3. 每秒：目标nil／生命≤0先结束；否则更新闪电坐标；目标没有实体神杖时先处理共享授予／撤销，再调用A112_timer_loop；最后距离严格>1000才结束。距离等于1000仍保持。来源死亡不是这里的显式断链条件。
4. 结束：活目标且无实体杖先Drop_A_Item，然后活目标当前state37+0.1；无论目标生死都A112_end；销毁timer／闪电，清四表。死亡目标跳过Drop及+0.1，不能自动修复尸体遗留。共享不是每帧重建的理想能力集合，详细不对称行为继续按神杖模块。

**伤害源事实：**[f291/f1 PC1192–1233、L163748–163790](../../reference/map-6.25/main.disasm#L163748)用**实际伤害来源S**在A111_113_tar中反查关联小精灵，再动态读其A111等级L。物理原乘`1+0.03L`，其他类型乘`1+0.05L`。没有attack标记、Has_A_Item、生命或再次距离检查；不是把归属塔O旗下全部临时单位也视为被连英雄。该段位于B181/B140倍率之后、q032分派之前，仍服从整个伤害流程的前置早退／q039旁路。

**图鉴优先修正：**仅把这里的物理系数改为0.05，其他门槛／位置不变；所有到达此段的伤害类型均乘`1+0.05L`。当前事件D=100，六级变130；之后其他减免／改写仍继续。小精灵升级即影响下一次伤害；超距但尚未到下一连接tick，倍率仍可生效。没有伤害派生包，也不再额外复制一份30%伤害。

**Q24准入：**A111须存在、存活、可操控、实际技能等级1–6且启用、非暂停／眩晕／沉默／施法禁用、冷却就绪；目标存在存活、友好且为原生HERO，允许无敌，拒绝魔免，中心距离≤800。自连未被源targets排除，允许后仍走真实连接门槛；自定义UnitIsHero不是英雄准入谓词。缺失Cost在本局部选0，缺失FollowThrough选0。不可移动塔范围外直接拒绝，不额外自动瞬移。

A111/A113均采用已定ANcl提交事务：接受命令后0.3秒前摇，到期复查当前条件／当前等级；后续成功替代命令、死亡、移除、能力禁用或相应控制取消未提交动作。提交先扣魔法并开冷却，再同步SPELL_EFFECT；事件内的Help／重复目标／地表拒绝不退款。未提交被取消或复查失败不收费。成功后0.1秒可截断施法后摇，均不随攻击K变化；已提交弹道／独立timer不撤销。原函数的直接强制调用不另收这份资源。

## A112：原完整分段与Q47选定公式

原脚本[f90/f9 L81601–81858](../../reference/map-6.25/main.disasm#L81601)先撤旧贡献，再看目标此刻有效三围选传递类型：力量严格最大选力；力敏并列高于智选敏；任何最高值与智并列选智。取来源相同类型的有效属性S；源原始档为：

```text
rawLevel = floor((0.4 + L/10) * S / (Game_Mode==1 ? 67 : 100))
Level = min(29, rawLevel)
Count = Level + 1
若 frac(S/100) > 0.5 且 Count < 30：Count += 1
源授予量 = 70 * (Count-1)，最高2030
```

补档助手[f90/f8 L81485–81599](../../reference/map-6.25/main.disasm#L81485)看的是`S/100`的小数，**不是**理论传递量小数，也不受67分母替换；恰0.5不补。T121/T122前四级及W3A五至三十级均为每档70；智力分支直接写基础智力，同样70×档数。原T123虽然列在数组里，智力分支没有挂它。

两本图鉴H/I261、372、377没有写70点档宽、无尽+50%或补档算法，只有比例、上限与“分段取整”。A112 及换皮 A142/A143 的实际提示六级均写无尽传递量+50%。图鉴未给这个系数，[Q61](q61-reconciliation.md) 采用确切的3/2。原脚本使用100/67（约1.492537），留作来源证据。70点档宽取自源属性辅助和智力乘数。 [A112](../../reference/map-6.25/units_campaignabilitystrings.txt#L1677) · [A142](../../reference/map-6.25/units_campaignabilitystrings.txt#L2046) · [A143](../../reference/map-6.25/units_campaignabilitystrings.txt#L2066)

**Q47已确认选项1：70点向下取整。** 替换旧分段数学，不沿用旧额外补档；原选择类型、撤旧、加新和周期顺序保持。精确Web公式为：

```text
p = (L+1)/10                       # 合法L1..6即20%..70%
m = (Game_Mode==1 ? 3/2 : 1)     # 有理数，勿先四舍五入
q = max(0, p * S * m)
若 q >= 3000：grade=43，amount=3000
否则：grade=floor(q/70)，amount=70*grade
Count = grade+1                    # 1..43对应0..2940，44是特殊末档3000
```

非正理论贡献取0为本页Q24的输入下界；不能产生负传递。正常等级为1–6；强制状态出现Buff但实际技能等级0时，仍按同一线性表达式p=0.1，不把未定义槽静默当成合法一级。缺失／删除单位getter按本页局部接口读0。

不能保留原30级限制，否则永远到不了3000；Web的T121/T122局部表扩为44档：`0,70,…,2940,3000`。这不是改源SLK或伪称原本就有44级。Count44不能用70×43，否则错误授3010。智力与其他两项均保存**实际授予amount**，撤销时按该记录处理，而非按现等级／现属性重算。T123不因此新增挂载。

|---|---:|
| 一级S=1000，理论200 | 140；另一候选210已否决 |
| 一级S=1049／1050 | 140／210 |
| 一级S=14999／15000／15001 | 2940／3000／3000 |
| 六级S=1000 | 700 |

## A112：刷新、回退和原生开启

[f90/f7 L81256–81483](../../reference/map-6.25/main.disasm#L81256)依来源**当前类型**取Buff／能力／标记：G057用B142/A142/T160，G058用B143/A143/T161，其他用B113/A112/T159。要求对应Buff等级**恰1**、来源仍在Tower_ALL；否则A112_end。不是看任一过载Buff就继续。

通过后，有目标就先加当前皮肤标记。无旧Type立即rate；有旧Type仅用**旧选中类型**对应的来源有效属性和当前等级计算新grade，新grade与已存grade不同才rate。到顶grade43后再增加来源属性仍不刷新；降到上限以下才可刷新。目标最高属性改变、同档内来源属性改变本身都不触发。Q47去掉旧补档后，不能仍拿旧floor(.../100)判断是否刷新。

rate严格顺序为撤旧→重新读目标有效三围选Type→读来源对应属性／等级→算新grade/amount→保存状态→应用新贡献。力量／敏捷移旧T121/T122后加当前辅助、永久化、设新Count；智力先从基础值减已授amount，再把新amount加到基础值，setter第三参true。各步接属性资源接口即时生效，不合并成净delta。Count>24仍调用原活动任务2，参数改为本次真实amount；不悄悄把门槛改成另一奖励规则。

[f90/f6 L81172–81254](../../reference/map-6.25/main.disasm#L81172)仅有旧Type才撤销；按保存amount撤回，随后按来源**结束时当前类型**移T159/T160/T161，再清Type/Level/Count/amount。没有生命检查；换皮后旧标记可能遗留，不自动移三个。目标死亡导致A111_end仍调用此回退，和共享神杖死亡时跳过Drop是两条不同规则。

原生AEim的本图字段：Cost2/3/4明确25，Cost1缺失；DataB1..6是10/20/30/40/50/70；DataA伤害、DataC缓冲魔法均未列；Dur/HeroDur1..4=1。基础AEim对象另有25开启费、10缓冲、原焚烧伤害，**缺项是否继承无法据code证明**。[原开发工具元数据Eim1–3](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Component/share/en-US/mpq/Units/AbilityMetaData.slk#L2274)和[字段标签L5910–5912](https://github.com/actboy168/YDWE/blob/a69c315ebf2886ec54d66200707ab6e38bd3484d/Development/Component/share/en-US/mpq/UI/WorldEditStrings.txt#L5910)分别证实为间隔伤害、每秒耗蓝、缓冲魔法。[暴雪普通焚烧说明](https://classic.battle.net/war3/nightelf/units/demonhunter.shtml)支持持续开启／耗蓝／手动关闭；[官方1.36.1改动](https://news.blizzard.com/en-us/article/23987390/warcraft-iii-reforged-patch-notes-version-1-36-1)又分别修改开启费与缓冲，不能借普通新版数值补此旧地图。

**Q24，限定三种过载实例：**

- 开启是即时无目标toggle，不用ANcl的0.3秒前摇、不打断正在进行的普通攻击。须实际能力启用、合法等级、单位存活可控、非暂停／眩晕／沉默／施法禁用、未开启、5秒冷却已好、魔法足够。魔免／无敌不阻止自身准备技能。开启费用选`[0,25,25,25,25,25]`：二至四级25是明确字段；一级0是缺项的局部选择，五六级25延续最后明确值。额外缓冲魔法选0；不冒称这是原生显式0。
- 成功先扣一次开启费、记冷却截止+5秒、安装对应**一级Buff**并登记独立1秒周期，再同步一次SPELL_EFFECT。无连接仍可开启和耗蓝：A112_Action[f90/f5 L81129](../../reference/map-6.25/main.disasm#L81129)只在来源不在Tower_ALL时提示，没有拒绝开关或检查连接目标。
- 每周期先按已有回复接口结算到该时刻，再按当前实际技能等级扣10/20/30/40/50/70；第一扣在开启后1秒。魔法不足一整次时扣剩余至0并关闭；恰等于一次费用时扣到0并关闭。普通暂停不暂停战斗timer；全局暂停停止时间。缺少DataA在本局部选无焚烧伤害，不凭Area160暗加伤害。Buff作为开启标记持续到关闭，不把Dur1=1当作仅持续1秒。
- 关闭即时、无费用，可在冷却中操作；不重设冷却，不另发一次开启SPELL_EFFECT。死亡、删除、实际能力移除／禁用、相应驱散关闭此native实例；单独沉默不删除已经开启的状态。关闭只移Buff和耗蓝timer，**不直接调用A112_end**；已经授出的属性等下一次原A111周期按Buff条件撤销。source死亡亦不自动断A111连接。
- A112_Study[f90/f4 L81096–81127](../../reference/map-6.25/main.disasm#L81096)看到B113/B142/B143任意>0就依次下`unimmolation→immolation`，不读两次命令返回值。关闭能成功而重新开启因冷却／魔法失败；不能替源码保住开启状态或免费重开。若重开成功，按新等级付开启费并从此刻重新排首扣。学习事件本身不立刻rate。
- 同实体ANeg换槽保留已有native实例／剩余冷却和下次扣蓝时刻，后续扣蓝读该逻辑槽现在的实际等级；已经安装的Buff ID不在换槽时自动替成新皮肤Buff。对应新类型找不到要求的Buff，原A111下次tick就撤过载；真实关闭后再开启才安装当前实际技能的Buff。普通能力移除是关闭，ANeg同槽改ID不是一次虚构移除／重施法。

例如先建立连接、再开启一级且魔法10，无其他回复：同刻+1秒连接tick先授属性，随后耗蓝至0关Buff；+2秒连接tick才撤属性。若开启先登记、连接后登记，同刻耗蓝先关Buff，连接tick不会授属性。两者按B05入队序，不能统一把“1秒时已关闭”提前到当轮所有事件前。

## A113：地表拒绝、延迟与两次独立迁移

ANcl准入沿上文，目标点须有限且在原地图半开边界内，法定魔法足够，范围999999覆盖地图；缺失FollowThrough选0。原地表检查在**已经提交的SPELL_EFFECT内**：[f291/f14 PC765–789](../../reference/map-6.25/main.disasm#L170839)只读请求点的BUILDABILITY；不可建造提示并return，无timer、无退款或冷却清零。这里不提前做整塔动态占用检查。

[A113_Action f91/f0 L81882–81919](../../reference/map-6.25/main.disasm#L81882)动态GetTriggerUnit，以Tower_ALL索引保存新timer和原location句柄，排+0.1秒。已提交后停止／沉默／原施法后摇结束均不取消这条独立timer。Q24将该句柄适配为本次请求坐标的值快照，后续外部位置对象修改不回写；源中没有RemoveLocation，Web不保留原生内存泄漏。

[回调 f91/f1 L81921–82058](../../reference/map-6.25/main.disasm#L81921)用到期timer反查索引，再读**当时**Tower_ALL与A111_113_tar，不捕获最初连接目标：

1. TxShow=true时按当前来源类型选择出发／到达特效；G057为jieyi_tpG/jieyi_tp_doneG，G058为jieyi_tp/jieyi_tp_done，普通仅CharmTarget到达特效。先在来源旧位置播放非空出发特效。
2. 当前连接目标非nil，先`SetUnitPositionLoc(target,requestedPoint)`，再`SetUnitPositionLoc(source,GetTempUnitLoc(requestedPoint,400))`，最后活动任务3+1。圆心是**请求点**，不是目标经过原生挤位后的最终位置。无目标则只把来源移到请求点。
