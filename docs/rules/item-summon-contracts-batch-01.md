## 既有出生、攻击和退包路径

- 普通召唤走实际 SUMMON，取主人的该时点库存，颜色标记每色取最高档。一般本体继承系数使用 0.4；仅 i240 提升时0.5，任一高档颜色时0.6。熊灵用自己的0.7/0.8/0.9动态三围接口，额外专属规则照旧。BIil 幻象和其他提前退出的源分别沿召唤分派，不能仅按模型外观识别。按 Q64 的图鉴明文，当前每件实际装备各贡献一次，含同色不同档及同 ID 多个有效实例。高阶每件 +0.5，i240 每件 +0.3，i242 每件 +0.2。同色档位优先取高与攻速累计分别执行。[标记与赋值 L125445–125916](../../reference/map-6.25/main.disasm#L125445) · [普通召唤](ward-summons.md) · [熊灵](spirit-bear.md)
- 伤害入口需要有效 S/O、S 当前属于 SUMMONED、非临时且非 Aloc、attack 非零。T085/T086/T087 读取实际 S，绿契敏捷读取 O 当前值，蓝契伤害读取 S 当前 S18+S19。红、绿、蓝按源顺序运行；绿/蓝采用 Q55 的远程完整系数，红和绿必中只限近战。已核模式折算保留绿契无尽 ×2，蓝契主线 ×0.5。红契近战将外层普通包写0，沿 Q64 发出300范围 HERO/NORMAL，各子目标实际忽略该目标正护甲30/40/50%。详细基数与减免如下，m998/m999 仍令分裂倍率乘0.2。绿契发 CHAOS/DIVINE；蓝契15%成功后发400范围 NORMAL/MAGIC，两者均保持原实际源、事件顺序及 B03。原红护甲档为20/30/40%，原蓝倍率为6/10/14，图鉴覆盖这些数值。[契约执行 L125917–126170](../../reference/map-6.25/main.disasm#L125917) · [分派门槛 L162636](../../reference/map-6.25/main.disasm#L162636) · [近战与 Q55](spirit-bear.md)
- 原普通召唤没有主人取放之后同步重算攻速的分派。熊灵是 A125+当前熊的特殊路径。每秒既有流程可根据当前库存移除颜色标记，退包源回调按红、绿、蓝、单独项执行 state81 增减与提前返回。Web 修正后段基础增益的物品 ID，从 i247 改为对应的 i240；Q70 仅撤回当前熊对该物品实例已经落实的数值。出生、退包和持有者直接属性各有状态，不能把取放扩展到无对应调用的对象。[退包原门槛 L147380](../../reference/map-6.25/main.disasm#L147380) · [实际熊周期](spirit-bear.md)

## 红契的真正护甲忽略

触发时读取父包当前 D，保存此前所有业务乘数，按该父事件实际已用的护甲因子 F父 还原分裂输入 D/F父。父包没有应用护甲时取 F父=1，只有实际已应用的护甲因子在这一步撤回。随后仍将外层事件置0，发原范围、攻击和伤害类型的子包。以父目标 m998/m999 为判断时仍将原分裂倍率80/100/120%乘0.2。每个子目标独立读取自己的当前护甲 a，若 a>0，使用 F(a×(1−p))，p=30/40/50%；a≤0 继续实际负甲/零甲规则。沿 Q26/Q27 的正甲限定，不写面板护甲。B03 子包自身的类别、资格和后续回调继续执行，先前的其他业务倍率保留。[既有护甲忽略接口](item-damage-dispatch.md#6-已核装备效果的复用与边界) · [护甲层](web-baseline.md)

例如父目标护甲100、原始280、入事件后 D=100。一级红契的子包基数是224。同一波中护甲100和200的两个子目标分别以70和140进入自己的护甲层，结果约99.12及63.64，例中其余倍率取1。原代码用父目标护甲20/30/40%代入一次线性增伤，并以同一个原始金额发所有孩子，一级原 VM 普通目标为96，m998为32，留作来源差异。原 Q55 的红契远程无效和模式倍率保持。

## Q70 熊灵退包

熊出生时按本体实例与所持物品实例记录实际加到 state81 的每笔贡献。A125 当前熊仍有效时，同一物品实例移出只撤自己的已写数额一次。熊出生未携带 i240，R=1，后来拾取再移出，R仍是1；出生时已携带，则 R从1.3回到1。重复的退包通知无需再次扣除，同 ID 另一件物品使用自己的记录。熊死亡或替换时清本实体记录；新熊从它自己的出生库存建账。普通召唤仍保留出生快照，无实时 PICKUP 重算。旧原退包对 i240／i247 的错误及各色末件源分支保留为证据。

运行 python3 tools/audit-item-summon-contracts.py --check 核对两书和四项辅助能力，原字节码执行两条出生、四条移出、两条红契路径，另核 Q64 的同色多件、分裂各目标护甲，以及 Q70 的后拾物、已登记物和重复撤回。11件的对应组件和整件覆盖均完成。
