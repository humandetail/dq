# 自动施法：完整分支与攻击事件入口

本文件只补全原图 `Skill_Auto` 的调度规则，不修改技能伤害或图鉴。**已覆盖全部157个顺序分支、198个就绪检查、167个发令调用点**；对每块直接跟踪 Lua 5.3 字节码的条件与跳转，共532条块内控制路径。覆盖率指静态调度清单完整，不代表已经运行 Warcraft native，也不代表这198个技能的效果均已实现。

## 来源、计数与可复核方式

- `L` 为 [main.readable.lua](../../reference/map-6.25/main.readable.lua) 的行号；`B` 为 [main.disasm](../../reference/map-6.25/main.disasm) 的行号。主函数 `main/f291/f27`：L119802–124699 / B173759–179250。
- [autocast-data.json](autocast-data.json) 给每个分支保留 Lua 行区间、字节码行区间、函数内 PC 区间、全部块内条件路径、发令参数及终点；另存源文件 SHA-256。JSON 条件中的 `nil` 就是 Lua nil。
- 157块覆盖PC27–4831，共4805条指令；首部PC1–26为入口与单轮循环设置，PC4832为单轮循环收尾，PC4833起为道具/组清理尾部。组合技能的短路 OR 仍为一个分支，因此198个检查与157块不矛盾。
- `controlFlowPaths` 从“已经走到此块”起算，不把前156块的失败条件展开成巨大的表达式。块内条件值属于符号化的 native 返回值，不冒充实机测试；共有532条结构路径。

## 1. 触发关系与全局开关

注册的是 **Player(11) 所有单位的 `EVENT_PLAYER_UNIT_ATTACKED`**，随后以 `Condition(chooseAttackedAction)` 执行入口（L124834–124854，`main/f291/f31` B179448–179486）。不是周期轮询，也不是“伤害已经命中”后才触发。

`chooseAttackedAction` 取 `u=GetAttacker()`、`v=GetTriggerUnit()`；如果u是幻象，执行专门的幻象攻击处理后return，不进`Skill_Auto`。非幻象若有T217先执行`A196_add_num(u)`，然后调用`Skill_Auto()`，返回后继续其余攻击事件逻辑。证据L114750–114779；`main/f291/f3`的入口字节码B167140–167169。本文件不向下递归这些被动攻击效果。

`Skill_Auto`重新读取u、v及u的坐标；只有`GetUnitAbilityLevel(u,'B012')>0`才进行技能扫描和道具自动使用，≤0直接return（L119804–119828 / B174093–174118）。B012是“自动施法”buff：`units_commonabilitystrings.txt:95–98`；T033的`BuffID1=B012`，开关命令分别`manashieldon`/`manashieldoff`，见`units_abilitydata.json`的alias T033与`units_campaignabilitystrings.txt:19732–19749`。建造完成处理在拥有T033时发`manashieldon`（L115288–115308）。这不等于任何塔任何阶段都必然开启；深渊出战流程会移除T033（L108875–108880），恢复时再加回（L108045–108064），是否仍有原buff须按对应native状态处理。

## 2. 共用就绪门槛

`ready(u,id) = Unit_Ability_Has_Cool_Down(u,id)` 实际意思是“可尝试施放”，而不是“正在冷却”。精确条件：

1. `GetUnitAbilityLevel(u,id)>0`；
2. `EXGetAbilityState(EXGetUnitAbility(u,id),1)==0`，要求冷却字段严格等于0；
3. `GetUnitState(u,UNIT_STATE_MANA) >= EXGetAbilityDataInteger(ability,currentLevel,104)`。

证据L32006–32048、`main/f7/f39` B52213–52272。该函数不自行检查沉默、眩晕、暂停、正在引导、目标可见性、无敌、目标是否合法或原生命令会不会接受；那些由native及实际技能执行决定。列出多个能力ID的行按列出顺序短路OR检查，只要任一个ready就下发同一个命令；脚本并未传具体能力ID给`Issue*Order`。

## 3. 目标选择约定

下表所有半径围绕**本次入口采样的攻击者坐标**。没有额外范围条件的行写“—”；这表示脚本不做这一检查，不表示技能本身无限施法距离。

|记号|精确定义|
|---|---|
|M|重新`GroupEnumUnitsInRange(group,u.x,u.y,r,null)`后，`hasMon`取组中第一个owner为Player(11)且生命>0的单位|
|H|同样枚举，`hasHero`还要求自定义`UnitIsHero(target)==true`|
|N|同样枚举，`hasNor`还要求`UnitIsHero(target)==false`|
|H→M|先枚举找H；未找到则重新枚举同半径找M，M也可以是Boss|
|记录目标→自身|从指定表读单位；nil或生命≤0则回退u；A202还检查距离>1000|
|当前被攻击单位|本次事件的`GetTriggerUnit()`，不再枚举|

三个选择函数逐次`FirstOfGroup`并`GroupRemoveUnit`，返回首个满足者；没有按距离、血量、路线进度或随机数排序。native枚举顺序仍未证实，因此不得把M写成“最近敌人”。`UnitIsHero(t)`是 **N534等级>0且`UNIT_TYPE_SAPPER`**，不是原生英雄类型；见L32149–32163的字节码修正`main/f7/f45`。选择辅助函数证据L124703–124831 / `main/f291/f28`、`f29`、`f30` B179252–179446。

## 4. 发令方式、延迟与本轮终点

- **即**：直接`IssueImmediateOrder(u,order)`；**ID**：直接`IssueImmediateOrderById(u,852261)`。
- **目标0**：L17_2，即`main/f291/f25`，将u、命令、目标句柄放进数组，登记一次`TimerStart(timer,0,false,callback)`；回调f23执行`IssueTargetOrder`。
- **地点0**：L18_2，即`main/f291/f26`；先`GetUnitLoc(target)`取得当时地点，再登记0秒一次回调；f24执行`IssuePointOrderLoc`。目标之后移动不意味着地点参数跟随。
- 0秒是native定时器延后回调，不是内联调用，也没有证据等于固定一帧。回调不重新找目标、不重检存活、距离、蓝量或冷却；先发命令，再销毁计时器并清相关索引。证据L119710–119798 / B173599–173757。
- 所有`Issue*Order`返回值均被丢弃。“结束扫描”代表发出/排入一次尝试后跳到PC4833，不代表施法成功，也不因native拒绝而改试下一个技能。
- **A163是唯一发令后继续下一块的分支**；**A221在ready为真后，即使600范围内没有M也结束扫描**。其他行在未满足额外条件或未找到所需目标时继续下一块。
- 结束技能扫描仍执行`Item_Auto_Use(group)`，随后清空、销毁组（L124685–124698 / B179236–179250）。因此一次攻击事件可先发A163，再发一个后续技能，再尝试自动道具；目标0/地点0技能也可能尚在等待回调，道具已被调用。不应实现“每次攻击最多一条技能或道具命令”。B012缺失导致的首部return才跳过此尾部。
